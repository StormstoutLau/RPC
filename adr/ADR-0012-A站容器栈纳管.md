## 背景（Context）

1. **A 站有一套未被任何条目覆盖的容器栈（E2，`O-122` 登记）**：`docker.service` / `docker.socket` /
   `containerd.service` 三个 **enabled**（开机自启），`dockerd` 自 2026-09-16 起 active（`Restart=always`）；
   ★ **`Running: 0`（无任何容器）** —— 本体现为**空转**（50.9 M 内存 · 13 天累计 CPU 2 min 42 s）。
   该栈**不属** `cluster.py` / `infer-*` 工具链 ⇒ **不在任何管理面内**。
2. **它的用途已查清 = 「Agent 检索基础设施」的宿主（E2，四条证据链）**：
   ① `~/searxng/docker-compose.yml` 自建 **SearXNG** 元搜索引擎；② 技能
   `~/.hermes/hermes-agent/optional-skills/research/searxng-search/` 读 `SEARXNG_URL`；
   ③ 镜像 **`mcp/paper-search`**；④ `~/.hermes/hermes-agent/docker-compose.yml`（hermes-agent 本体编排）。
   ⇒ 与本仓对得上：`PLUGIN-LEDGER` 把 `web-searxng` 列为「契合度 ⭐⭐⭐ · 无需 key 或自建」的检索层。
3. **★ 本会话新测（E1，2026-09-30）**：
   - `~/searxng/docker-compose.yml`（422 B）原文写死 **`"8080:8080"`** + `SEARXNG_BASE_URL=http://localhost:8080/`；
   - `docker ps -a` ⇒ **只有 1 个 exited 的 `hello-world`**（searxng 容器**不存在**）；
   - `ss -ltn` ⇒ `8080 / 8088 / 8090 / 8091 / 8099 / 8888` **全部无监听**；
   - `docker compose version` = **v5.1.1**；`docker compose config` **可离线解析**（无需 daemon ⇒ 可作校验器）。
4. **一次实际冲突已被裁并已执行（E1，本会话）**：compose 的 `8080` 与 A 站**推理引擎**（unsloth studio，
   本表 `managed/8080`）**双重声明**。**当前无冲突**（8080 空闲、容器已删），但 **`compose up` 即撞**。
   ⇒ 裁「**searxng 让位**」：宿主端口 **8080 → 8888**（选 8888 因它是该 skill 文档**自带示例端口**，
   `SEARXNG_URL=http://localhost:8888`）并同步 `SEARXNG_BASE_URL`；**改动经 `cluster_ssh.ssh_run` 执行**
   （即**已经**走 ADR-0004 的 SSH 层，未新造入口）；证据 = `docker compose config` 实测 `published: "8888"`；
   备份件 `docker-compose.yml.bak_20260930`（改前 sha256 `c8ef140f…` → 改后 `af0f3260…`）。
   ★ 这一改动**恰好暴露**了缺口的实质：**唯一能做这件事的入口是 `ops/cluster.py` 的 SSH 层**，
   而该栈本身**没有**任何子命令/判据/台账 ⇒ 属"管理动作已发生，但管理面里没有它的位置"。
5. **两条仍在的缺口（E2，`O-122` 登记）**：① `dockerd` 连续 13 天而 `containerd` 仅 1 d 19 h
   （2026-09-28 09:45 dockerd 日志报 containerd **连接 EOF**）⇒ **生命周期不同步，根因未查**；
   ② **两套 Docker 并存 + 配置双源** —— `docker-ce`（在跑）与 `docker-desktop` 4.69.0（装了未跑）并存，
   且 **`daemon.json` 有两份**（`/etc/docker/` 与 `~/.docker/`，**registry-mirror 列表不同**）⇒
   属本仓「**同一事实两处表达**」同族，**哪份生效未核**。

## 决策（Decision）

### D1. 该栈**纳入**唯一管理面（`ADR-0004` D1 不变：不新增并列入口）
A 站的容器栈（镜像 / 容器 / `docker compose` 栈 / 其端口）**登记为纳管对象**；
一切**管理动作**（看状态、起停、拉取、清理）**只准**经 `ops/cluster.py（+ cluster_web.py）`
的**同一入口**执行。**禁止**再写一次性 `ssh + docker` 脚本 —— 那正是 `ADR-0004` D2 要拦的形态。

### D2. 第一步**只做只读**：`cluster.py containers status`
- 首期能力 = **只读一屏**：三站 `docker ps -a`（含 exited）+ `docker images` + `docker compose ls` +
  该栈**端口**与 `inventory/ports.yaml` 的**对账**（复用既有 `ports` 断言口径）。
- **写动作**（`compose up/down`、`pull`、`prune`）**不在首期**；日后若要，**必须**仍是同一入口的子命令，
  且**默认 `--plan`、`--go` 才动手**（与 `models` / `flow` 的既有约定一致）。
- **判据**：`containers status` 恒 `exit 0`（只读观测，与 `frames` 同族），
  但**必须显式报**「无容器」而**不是**打印空（本仓头号形态：**空集被读成"没问题"**）。

### D3. 端口真值收敛：**该栈的端口一律进 `inventory/ports.yaml`**
- 已执行：A 站 searxng 宿主端口 **8888** 已登记（`managed`，`scope: [A]`，`mode: on_demand` +
  `status: configured_but_stopped` ⇒ 未监听**不算故障**，豁免本表"声明在用却没监听"的反向对账）。
- **纪律**：凡 compose 里出现的**宿主**端口，**必须**能在 `ports.yaml` 找到（或显式说明为何不登记）。
  这条把「8080 双重声明」那类**latent 撞车**从"下次 `compose up` 才发现"提前到**登记时可见**。

### D4. 两条「同一事实两处表达」的处置 = **先登记，后收敛**（不本轮动手）
- **`daemon.json` 双源**（`/etc/docker/` vs `~/.docker/`，mirror 列表不同）：**先核"哪份生效"**，
  再定"留哪份"。在核清之前**不动**任何一份（改错那份 = 静默改变拉取路径）。
- **`dockerd` ↔ `containerd` 生命周期不同步**：登记为**观察项**（`O-122` 缺口②），
  **不**在本 ADR 里改系统服务（那属宿主 `systemd` 归属，超出容器栈纳管的射程）。
- ⚠ 两条都**不许**用"再抄一份清单"的方式解决（本仓头号失败形态）。

### D5. 与 `ADR-0011` / `O-121` 的边界（**明确不做**）
本 ADR **不**为任何推理栈（vLLM / kyuz0 / ds4）背书：`O-121` 已裁「**当前不引入**」第三方容器，
`ADR-0011` 已裁 A4/vLLM **暂缓**。本 ADR 只管 **A 站**这套**已在跑的检索栈**的**纳管与登记**，
**不**新增任何镜像、**不**改变引擎拓扑。

## 考虑的替代方案（Alternatives Considered）

| # | 方案 | 为何不采纳 |
|---|---|---|
| 甲 | **不纳管**，只在 `O-122` 里登记为「管理面外」已知缺口 | ① 本会话实测已证明**管理动作真的会发生**（端口冲突已需动 compose）⇒ "不纳管"只是把动作推给一次性 ssh；② `ADR-0004` 的失效形态正是"**动作在入口之外发生**"⇒ 不纳管等于**主动**制造该形态 |
| 丙 | **部分纳管**：只把**检索面**（searxng / paper-search）登记进 `PLUGIN-LEDGER`，`dockerd` 本体不入管理面 | ① 该栈的**风险不在检索面**而在**容器生命周期**（daemon/containerd 不同步、镜像/卷占盘、端口撞车）⇒ 只登记检索面**恰好漏掉全部风险面**；② 会出现"**同一栈两处登记**"（PLUGIN-LEDGER + 未来某处）⇒ 第二份真值 |
| 丁 | 纳管但**让 cluster.py 直接调 `docker` 而不复用 SSH 层** | `ADR-0004` 已定**唯一管理面**；另起通道 = 并列入口。本 ADR 明确**复用** `cluster_ssh.ssh_run`（本会话的端口改动即走此路） |

## 后果（Consequences）

**正面**
- 该栈从"**没人看得见**"变成"**有入口、有判据、有台账落点**"；端口 latency 冲突提前可见（D3）。
- 与 `PLUGIN-LEDGER` 的 `web-searxng` 条目**互为佐证**（一个讲"能力可用"，一个讲"载体在管"）。
- 复用 `cluster_ssh` ⇒ **零新入口、零新脚本**（`ADR-0004` D2 的 `scripts` 断言不受影响）。

**代价 / 风险**
- `cluster.py` 增一个子命令 ⇒ 门面符号表（`facade` 断言）与 usage 文本要同步；
  ⚠ `containers` 是**新符号**，须确认它进入 `facade` 的统计口径而**不是**"无消费者引用"一类。
- 「纳管」**不等于**"已安全"：本 ADR **不**审查镜像来源 / 供应链，**不**审计容器内权限。
  ⇒ ★ **别把它读成"容器栈已合规"**。

## 未实测登记（不静默）

1. **`containers status` 子命令未实现** —— 本 ADR 是**立项**，`cluster.py` **未加**任何子命令；
   ⇒ D2 的判据（含"必须显式报无容器"）**尚无对象**。（同 `U1#8` / `D7-CC#3/#8` 的处理：**已裁 + 实现未落地**。）
2. **`daemon.json` 哪份生效未核**（E4 推断为"取决于 daemon 启动时的工作目录 / `--config-file`"）——
   **未做**任何实测；在核清前 D4 明确**不动**两份中的任何一份。
3. **`dockerd` ↔ `containerd` 不同步的根因未查** —— 只有 E2 的一条日志（2026-09-28 09:45 EOF）；
   **未复现**、**未做** `journalctl` 时序对齐。
4. **`O-121` 顺带结清的那条"未验"仍未验** —— 两份 `daemon.json` 都配了国内 registry mirror，
   但 **"配置存在" ≠ "能拉到镜像"**：**未实测**一次 `docker pull`。
5. **未核镜像/容器的实际占盘口径**（E2 报 `/var/lib/containerd` 691 M 而 `/var/lib/docker` 仅 300 K
   —— 因启用 **containerd image store**；★ 此处**极易看错**，本轮**未复测**）。
