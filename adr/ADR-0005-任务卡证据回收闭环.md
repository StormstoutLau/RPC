> **Feature**: 把「任务卡验收结论的原始载体」从"站上野生残留 + 主控 `%TEMP%`"收进 `agent-out/<ts>/`，
> 使 `run.json` 的验收结论从 **wrapper 转述** 变为 **可复核证据**；并顺带消除 `%TEMP%` 临时件泄漏
> 与"collect 失败即无证据"。
> **创建日期**: 2026-09-16
> **状态**: accepted
> **适用**: [agent-cli.ps1](../../ops/station-bin/agent-cli.ps1) 两条执行路径（远端 opencode / 主控 claude）的 collect 段
> **上游调研**: [2026-09-16_任务卡证据流可重放性调研.md](../../docs/research/2026-09-16_任务卡证据流可重放性调研.md)（§2 现状清点 / §7.1 分阶段路径 / §10 缺口表）

---------------------------------------------------------------------

## 背景（Context）

**触发**：用户提出把取证矩阵从"文档审查"扩展到"任务卡验收"（`evidence_manifest` + 异基座 agent 审计编排管线证据流）。调研（见上游文档）的结论是：**该提议的前置条件不是 manifest，而是"证据根本不在手上"** —— 故先做阶段 0。

**问题链（为什么必须先做这一步）**：`run.json` 里的 `status` / `accept.passed` / `accept_golden.passed` 全部由 wrapper 解析远端 `.meta` 后**转述**；而承载这些结论的**原始记录全部不可得**：

| # | 证据件 | 现状落点 | 问题 |
|---|---|---|---|
| 1 | **判据记录** `.meta`（`TASK_ID/QUEUE_S/RUN_S/TASK_RC/ACCEPT_OK/ACCEPT_GOLDEN_OK/REVIEW_NEEDED`） | 远端 → `%TEMP%\agent-cli-meta-<ts>.txt`，解析完**不归档**（[:1126](../../ops/station-bin/agent-cli.ps1#L1126) / [:1139-1146](../../ops/station-bin/agent-cli.ps1#L1139-L1146)） | 验收结论的唯一原始载体丢失 |
| 2 | **节拍 trace** `.progress` 原文 | 远端 → `%TEMP%`，**只取末行**换算 `output_bytes/bps`（[:1130](../../ops/station-bin/agent-cli.ps1#L1130) / [:1160-1165](../../ops/station-bin/agent-cli.ps1#L1160-L1165)） | 原始吞吐曲线不留档，且**最易失**（同 proj 下次 run 即被截断重写 [:1035](../../ops/station-bin/agent-cli.ps1#L1035)） |
| 3 | **prompt 全文** `out/.prompt.txt` | **从不回收**（[:1018](../../ops/station-bin/agent-cli.ps1#L1018) 写） | `prompt_sha256` 永远无法自证 |
| 4 | **accept 命令清单** `out/.accept-cmds.txt` | 从不回收（[:1081](../../ops/station-bin/agent-cli.ps1#L1081) 写） | "实际跑了哪几条命令"事后看不到 |
| 5 | **golden 命令清单** `out/.golden-cmd.txt` | 从不回收（[:964](../../ops/station-bin/agent-cli.ps1#L964) 写） | 同上 |
| 6 | **当次 golden checksum** | 只在主控变量 `$goldenSha`（[:933](../../ops/station-bin/agent-cli.ps1#L933)）→ 远端脚本字面量（[:955](../../ops/station-bin/agent-cli.ps1#L955)），**无任何存档** | "这次跑的是不是我期望的那份 golden"不可回溯 |
| 7 | claude 备路：prompt 全文 / stderr / golden 哈希 | `%TEMP%\agent-cli-claude-<ts>\` 下的本地件（[:1483-1489](../../ops/station-bin/agent-cli.ps1#L1483-L1489)）、`$goldenSha` 变量（[:1528](../../ops/station-bin/agent-cli.ps1#L1528)） | 同类问题；scratch **永不清理** |

**四条已自证的事实**（决定本 ADR 的成本账；均经复核，非推测）：

- **F1**：prompt **不内联附件正文**，只有清单 + 一句尾注（[:888-893](../../ops/station-bin/agent-cli.ps1#L888-L893)）⇒ 体量 = 卡的量级（KB）。
- **F2**：**全仓没有任何脚本清理** `out/.prompt.txt` / `.meta` / `.progress`（只有"写"与"读"；grep 25 处零清理）⇒ 站上 `out/` 属**按 proj 保留最近一次、永不删除**。
- **F3**：`workspace --archive` 是**无排除的整工作区 tar**（[:374](../../ops/station-bin/agent-cli.ps1#L374)）⇒ 当时的 `out/`（含 prompt）**随快照封存**，归档目录只增。
- **F4**：`strong-accept` **不变式 5** 的约束对象是**远端可见面**（"注入远端后不再落盘任何清单文件"，[IMPLEMENTATION.md:146](../../spec/d6-agent-standard/strong-accept/IMPLEMENTATION.md#L146)）—— 其目的是不把期望哈希交给能读工作区的模型，**不是**"主控侧不得记录"；`run.json` 已有同类先例（`content_digest`）。

**由 F1-F3 得出的关键判断**：**留痕已经发生，且有两份**（站上野生残留 + 归档 tar），只是**不在审计者视野内**。故"为减少留痕而不归档 prompt"在本框架**已不成立**；归档不是新增留存面，而是把同一份文本**搬进受控视野**。

## 决策（Decision）

### D1. 归档 prompt 全文（`out/.prompt.txt` → `prompt.txt`）

**理由**：`prompt_sha256` 要能被验，就必须有一份"被哈希的原文"；否则只能**重算**，而重算路径含**工具态**成分 —— profile 尾注由 `Resolve-Profile` 的参数表决定、sanitized 卡的 scrubber 是**有损**变换（[:888-902](../../ops/station-bin/agent-cli.ps1#L888-L902)）。⇒ 重算失败时审计方**无法区分"prompt 被换过"与"拼接逻辑变过"**，判据不可判定。

**历史旁证**：本框架**已吃过一次**"发给模型的东西 ≠ 以为发出的东西"—— **D-13/P1b**：卡正文曾被静默丢弃，模型因此自设计交付物并自写测试。prompt 正文归档使这类偏差**可直接比对**。

**成本**：3 行级代码；体量 KB；明文面**净增 0**（F2/F3）。

### D2. `.meta` / `.progress` **原文照收**（不改写、不规范化）

**理由**：规范化会引入**第二定义点**（原文本 vs 生成的规范文本），且"证据未被改动"从此不可验，阶段 2 的一致性判据会退化为"验我的解析器"而非验远端事实。原文照收 = 少写代码 + 文件 bytes 本身成为可哈希证据。

### D3. 当次 golden checksum **只进 `run.json`**（不另立文件）

落点：`accept_golden` 对象新增 `sha256` 与 `base` 两个键（现有 `cmd`/`passed`/`source`/`hidden_from_model` 不动）。

**理由**：① 与不变式 5 **不冲突**（F4：约束的是远端可见面，`run.json` 在主控、模型不可见）；② 另立 `golden.sha256` 文件 = **第二定义点**，两份可能不同步（本框架在 2026-09-16 一天内已因此吃两次教训：`claude.key` 拷贝、gitlink 指针）；③ 复验器可据此**动态生成** `echo "<sha>  <base>" | sha256sum -c`，无需第二份文件。

### D4. 顺带修三处（**必须同批**）

| # | 改动 | 理由 |
|---|---|---|
| D4a | `%TEMP%` 临时件**归档成功后才清理** | 五个件（out / meta / accept / golden / progress）**从不删除**，天天在漏 |
| D4b | 修 `if (Test-Path $env:TEMP)` 恒真空守卫（[:1129](../../ops/station-bin/agent-cli.ps1#L1129)） | 该条件恒真，等于没写 |
| D4c | **collect 失败时把证据留在原地并打印 `EVIDENCE_LEFT_IN_TEMP=<路径>`** | runDir 建不出时 `$runDir` 退化为占位串（[:1193-1197](../../ops/station-bin/agent-cli.ps1#L1193-L1197)）⇒ 归档路径失效；此时若清理就变成"**既没归档又被删**" |
| D4d | 5 个小文本证据件**合批单连接回收**（而非逐个 scp） | 实测 Win32-OpenSSH 每次建连 **14-17s** ⇒ 逐个 scp 会把 collect 从 5 次连接抬到 8 次（+50s/run）；合批后 collect **115s → 49s（省 66s/run）** |

**D4a 与 D4c 的耦合是本 ADR 的要点**：归档与清理**不能分批做** —— 只清理不归档 = 净损失；只归档不清理 = 泄漏继续；失败路径不特判 = 在最需要证据时把证据删掉。故三处**同批**，顺序固定为「**归档成功 → 才清理**」。

## 否决/比较对象

| 方案 | 否决理由 |
|---|---|
| **不归档 prompt**，改为"把拼接配方版本化"（记录 profile 表 / scrubber 版本号以让重算可复现） | 引入"配方版本"新概念；依赖每次逻辑变更**记得**改版本号（靠自觉 —— 本框架最不信的东西）；且 scrubber 的有损性使版本化**仍不能保证可复现**（正则等价变换不改变语义但改变字节）。**比归档正文更贵且更弱** |
| `.meta`/`.progress` **规范化后存** | 第二定义点；"证据未被改动"不可验（详见 D2） |
| 另立 `golden.sha256` 清单文件 | 第二定义点（详见 D3） |
| 归档与清理**分批**做 | 见 D4 的耦合分析 |
| 由编排管线**自产**证据声明（用户原提议的形态） | self-attestation：Mini Shai-Hulud 事件证明"格式正确、签名有效、可哈希自洽"但 builder 已被污染，而**推理站就是我们的 builder**。证据必须由消费方（主控）采集 —— 这正是本 ADR 的做法 |

## 后果与待办

**收益**
1. `run.json` 的验收结论从"转述"变为**可复核证据**：`.meta` 原文可与 `status/accept.passed/accept_golden.passed` **逐项对照**。
2. `prompt_sha256` 从**不可自证 → 可自证**（重算即验），并回答"模型看到的到底是什么"（`content_digest` 只答"产出是什么"）。
3. 可回答"**这次跑的是不是我期望的那份 golden**"（`accept_golden.sha256` + 仓库源哈希）。
4. `%TEMP%` 不再累积；collect 失败时证据可寻（`EVIDENCE_LEFT_IN_TEMP=` 可 grep）。
5. 阶段 1（manifest 规范化）/ 阶段 2（离线复验器）/ 阶段 3（异基座管线审计）的**前置条件**。

**代价与风险**
- `agent-out/<ts>/` 新增 5-6 件（prompt / judgment-record / progress-trace / accept-cmds / golden-cmd / [claude] stderr），单次 run 增量为 KB 级。
- **依赖**：若某项目将来把 `agent-out/` 纳入版本控制，prompt 会随之入库 ⇒ 阶段 1 需明确"`agent-out/` 永不入库"（现状各项目 `.gitignore` 已忽略）。
- **验证边界（诚实声明）**：**collect 失败路径（D4c）无法低成本端到端验证** —— 需人为让 `agent-out` 不可写，而派发前的 `Assert-AgentOutWritable` 探针（[:580-591](../../ops/station-bin/agent-cli.ps1#L580-L591)）会先拦住多数情形。该分支**仅代码走查**，不声称已端到端验证。

**待办（不在本 ADR 范围）**
- `.attach/` 与 `.state.json` 仍未收（阶段 1 评估是否需要）。
- 远端 `out/.prompt.txt` 等野生残留**依旧不清理**（本 ADR 只补"归档"这一侧；清理站在站上属另一决策）。
- 台账 `queue_s/run_s` 恒 0（缺口 6）、`attach` 无哈希（缺口 5）、门禁对 agent 证据零覆盖（缺口 7）—— 见上游调研 §10。

**实施期间踩到并修掉的三处（诚实记录）**

1. **GNU tar 的 `host:path` 陷阱**：本地解包 `tar -C C:\...` 被 tar 当成远程主机 —— `tar (child): Cannot connect to C: resolve failed`；加 `--force-local` 后**又不认反斜杠 Windows 路径**（`C\:\\Users\\…: Cannot open`）。⇒ **最终弃用 tar**，改逐件 `marker + base64` 文本通道（本文件既有手法），全程不经过本机原生工具的参数解析。run2 的失败是**优雅降级**实证：仅 5 件缺失、`TASK_DONE exit=0` 不变、并打印 `EVIDENCE_PULL_WARN`。
2. **PowerShell 5.1 原生命令参数解析**：`& $tar -czf $path …` 形式下 `$path` 会被当作 cmdlet 名执行（`The term 'C:\…tgz' is not recognized`）⇒ 本文件既有的**数组展开**手法（[:345-346](../../ops/station-bin/agent-cli.ps1#L345-L346)）是正解；虽最终未用 tar，此法已记录备查。
3. **验证卡自身的引号**：我写的 `accept: - "true"` 让 `Get-FrontMatter` 把**引号原样保留**在命令里（`"true"`），eval 后仍正常执行 ⇒ 是**我的断言错，不是代码缺陷**；顺带确认了一个解析器行为（**不剥 YAML 引号**），已登记为缺口。

**新增的两项观察（已登记，非本 ADR 修复范围）**

- **每次 ssh/scp 建连 ~14-17s**（5 次采样；`AddressFamily=inet` 省 3s、GSSAPI 无关；**ControlMaster 在 Win32-OpenSSH 9.5p1 不可用**：`getsockname failed: Not a socket`）⇒ 全框架所有 ssh/scp 调用点都付这笔钱（本 ADR 通过"合批"把 collect 的连接数从 8 降到 4）。属**框架级性能项**。
- 任务 run 的墙钟以连接数与 sync（213M）为主（实测单次 run ≈ 420s，其中模型运行仅 21-53s）。
