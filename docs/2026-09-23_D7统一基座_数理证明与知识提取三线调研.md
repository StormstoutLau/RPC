### 3.2 发现二：**三家的"半套机制"互补，且互补关系是精确的**

### 3.3 发现三：**本机群已有一个"完成信号与证据不同源"的真实实例**（T-1 的本地版）

> **`D:\Textbook` 的 Lean4 完成态**（E2，如实记录）：
> - `ARCHITECTURE.md` 声明 Stage 3.5 "ITERATIVE_FIX 10 轮迭代, 353→0 errors"、产出 "**lake build 0 errors (exit code 0)**"；
> - 仓库内保留的构建日志 `output/build_full.txt` **仍是 353 errors 的中间态**，未找到最终成功的构建日志；
> - 另：`CODE_WIKI.md` 记 "836 entries, **0 sorry**"，而磁盘实测 `AllChapters.lean` 为 **747 声明 / 736 sorry（≈98.5%）**。
>
> **这不必然是错误**（构建可能在别处执行、日志未回传；CODE_WIKI 明显过时）。
> **但它的形态与 T-1 完全一致**：**"完成"是文档的声明，不是可从证据复核的事实**。
> ⇒ 这正是 **D6-P1「事实源↔镜像一致性」** 与 **D6-P3 出站断言**要挡的东西，
> 也为"**每一份产物必须能被独立复核**"提供了**本机群自己的实例**（而非只引用外部案例）。

## 4. 统一基座的最小接口面（U-1~U-5）

> **设计原则**：**不新建系统，只定义"三项目共同的形状"**，每条都能映射到已有资产。
> 与 [ADR-0007](../adr/ADR-0007-证据流阶段推进路线与改动验证闭环.md) 的既有路线**不冲突**，是其上位收敛。

| # | 接口 | 今日三项目各自的做法 | 统一后 | 依据 |
|---|---|---|---|---|
| **U-1** | **统一产物身份（内容寻址）** | Auto_Prover `MD5[:16]`；Textbook `SHA256`(input_hash/code_hash)；Paper `md5`(幂等) | **一套算法**（建议 SHA256，含算法标识前缀以支持演进）+ **每个产物有唯一 ID** | §3.2；Ontoly RFC-0002 "content must not rely on timestamps" |
| **U-2** | **统一证据强度字典** | 四套 `L 编号` + Paper `strong/page_only/no_page` + Open_Data `L1/L2/L3` 与 `R1–R5` | **单一词典**，机读可判；**"未标注档位 = 默认不可信"**（沿用 Open_Data 纪律） | §3.1；上一版 M-9 |
| **U-3** | **统一依赖边格式（含 provenance 必填）** | 三套 DAG 实现、三种边类型表 | **一份边 schema**：`src / dst / kind / provenance(必填)`；**无 provenance 的边无效** | RFC-0002 invariant；上一版 M-1 |
| **U-4** | **失效规则 H-1~H-4** | **三家全缺** | 内容寻址 / **保守失效** / **无法安全判定 ⇒ 强制全量降级** / **失败不得部分覆盖** | RFC-0002；上一版 M-2 |
| **U-5** | **信任基座四问（V-1~V-4）作为验收项** | V-1 仅 Auto_Prover 参考包；V-2 真空；V-3 仅 Textbook 关键词级；V-4 仅 Textbook | **四项各自成一条可机判判据**（定义对应性 / 桥接完整性 / 公理白名单 / 构建可复现） | §1.3（真实事件提出的规格书） |

**⇒ 与既有 D7 批次的关系**：

- **U-1/U-3** 是 **D7-B（机械门先行）** 与 **D7-C（结论契约）** 的**前提**（无统一身份则门禁只能按项目各写一遍）；

- **U-5** 是**本次新增**，来源是 NS 事件（**这不是从社区抄的，是真实事件提出的**）。
