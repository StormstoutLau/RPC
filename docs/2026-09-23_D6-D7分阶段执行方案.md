### D6-P0 门禁底座　【最高优先：其它项都靠它保证不漂移】

> **为什么排第一**：P1–P3 的每一项都需要"改完有东西拦住漂移"。门禁自己是这个地基。
> 而且本会话已实证**门禁会静默降级**（常量层搬走后 `inventory` 报数 3→0 仍 PASS）——
> 底座不牢，后面全是假的。

#### P0-1 门禁调度器 struct

- **现状（E1 实证）**：`rpc_check.py` 用的是**扁平 `for c in selected` 串行循环**
  （`main()` 第 2570-2577 行），`CHECKS` 是平表，字段只有 `id/title/fn/quick/fix`。
  **没有** `needs` / `after` / 依赖图校验 / 有界并发 / `streamOutput`。
- **做什么**（按 ds `run-gates.ts` 的可映射部分裁剪）：
  1. **`needs`（必须 passed 才启动）与 `after`（只需 settle）两个新字段** —— 目前无依赖关系可表达。
  2. **启动期图校验**：空图 / **重复断言 id** / 引用**未知 id** / **依赖环**（DFS 报出 `a -> b -> a`）。
     ⇒ 在跑之前 fail，而不是跑到一半。
  3. **依赖级联的 `skipped` 必须算失败**（ds 原文规则）。
     ⚠ **"非执行"必须三分**（D6-P0-1；第三类由 §11.1-A 的分析补齐，2026-09-25 落地）——
     三者**后果不同**且**必须能被机器区分**（本仓头号失败形态 = "把两件事说成一件"）：

     | 类 | 触发 | 后果 | 呈现 |
     |---|---|---|---|
     | **MODE_SKIP** | `--quick`/`--only` **未选中**（模式性省略） | **合法，不计失败** | 结论区"已跳过 (模式=…)"一行 |
     | **SKIP_FAILED** | `needs` 里有 FAIL/SKIP_FAILED（依赖失败） | **算失败（阻断）** | `[SKIP_FAILED] ⊘` |
     | **WARN（环境降级）** | 缺 paramiko/pyyaml 等（**环境不具备**） | **不计失败，但必须可见** | `[WARN] ▲` + 明细 |

     ⇒ **唯一落点** = `ops/rpc_check.py` 的 **`run_checks()`**；**三类各一注入用例** =
     `tests/test_rpc_check_three_classes.py`（含"**三者后果互不相同**"断言）。
     ⚠ **已知的双重用途（如实标注，不假装干净）**：`WARN` 同时用于**"环境降级"**与**"执行后有非阻断发现"**
     （如 `evidence` 的可重放 gap / `plugins` 的已登记漂移）—— 两者对"**是否阻断**"的语义相同，
     差异只在**是否执行过**。当前**判定可接受**（明细区**逐项可读** ⇒ 未产生误判）；
     **若出现"只能看总数、看不到明细"的场景（如结论区只给一个黄灯数），则应加独立 `DEGRADED` 状态**
     （成本已勘明：约 13 处 `return "WARN"` + 计数/呈现 + `rpc.ps1` 的两处文案）。

### 11.1 D6 → 受理机制：三条通道

#### A. 语义级（`实测`）

`D6-P0-1` 要"**依赖级联的 `skipped` 必须算失败**"，同时要区分"模式性省略（`--quick`）"。

**⚠ 实测发现"非执行"有第三类，而 P0-1 的二分法容不下它**：

#### B —— **三站并发被执行，但被两个实现缺陷挡住**（`实测`，两次尝试均失败）

**第 1 次**（`-HostName A/B/C` 各一进程）：A 站那次仍在运行；B 站 `LOCK_HELD owner_pid=2968117 mode=exclusive` + `exit 3`；C 站同 ts 冲突。
**第 2 次**（B/C 各一）：两次拿到**完全相同的 `ts=202609232242536720`** ⇒ `EVIDENCE_PULL_WARN: …\agent-cli-ev-<ts>\.meta … being used by another process` + `COLLECT_FAIL: … '.workspace-diff.txt' … does not exist` ⇒ **互相踩踏**。

**Root cause ①（确定）：`task` 的目标站**只能由 `ROUTE_TABLE` 的 `station` 字段决定，**调用方无法覆盖**。

- 锁本来是 **per-(proj, 站)** 的（`$W/.agent-lock`，`$W = /home/<user>/agent-workspaces/<proj>`，[agent-cli.ps1:1510](../ops/station-bin/agent-cli.ps1)）⇒ **撞锁只可能是三次都在同一站**。
- `Invoke-Task`（[:1224](../ops/station-bin/agent-cli.ps1)）**没有 `$hostName` 形参**，靠动态作用域取顶层 `$HostName`；而顶层该参数的注释语义是 **lock/workspace 的"目标主机"**，不是 task 的路由覆盖（[:19](../ops/station-bin/agent-cli.ps1)）。⇒ **`-HostName A|C` 对 task 不构成"指定站"的通道。**
- ⇒ ⇒ **要三站并发，唯一通道是"每站一个出网 alias"**（如 `ultra-a`/`ultra-b`/`ultra-c`，与既有 `m27-q4ks-a/-b` 同法）。
  ⚠ **但这会撞另一条纪律**：`ROUTE_TABLE` 注释明写"新 id 取 `secrets/openrouter.conf` 的 `harness_priority` 前两档…**本表只镜像，不新立模型清单**" ⇒ **加 per-station 别名属于扩表，须裁定**。

**Root cause ②（确定）：并发命名空间未按站/进程隔离。**
`$ts = [DateTime]::Now.ToString('yyyyMMddHHmmssffff')`（[:1511](../ops/station-bin/agent-cli.ps1)）**在两次并发里取到同一值**，而 `%TEMP%\agent-cli-ev-<ts>` 与 `agent-out\<ts>` **都不含站与 pid** ⇒ 同 ts 即互踩。
（对照：`TMP_ROOT` 早已用 `RUN_TOKEN` 做过 per-invocation 隔离（[:50](../ops/station-bin/agent-cli.ps1)），**`agent-out` 与 evidence 临时目录却没有跟上**。）
