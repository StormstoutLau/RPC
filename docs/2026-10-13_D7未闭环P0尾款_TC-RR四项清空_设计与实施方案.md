## 2. 设计（四项）

### 2.1 `golden.checksum`（D1 口径 + P0 固化）
- **gap 条件改为**：`(goldenActive) -and (-not checksum)`。**理由**：§1.5 的红线 3 射程 = 「**有 golden 时**在 P0 固化其哈希」；无 golden ⇒ 该项**不适用**（不是"本仓不提供"）。
  ⚠ 这与 `seq` 改判同类——**是口径纠正**（旧逻辑把"不适用"报成了"缺口"⇒ 同款"永久灰度"病），本方案**明写**、可回改。
- **checksum 来源**：call-site 把 `accept-golden.source` 当**文件路径**解析（`Test-Path` 可及 ⇒ `Get-FileHash`）⇒ 传入 `New-TaskContract -GoldenChecksum`；不可及/无 golden ⇒ `''`（有 golden 但不可及 ⇒ **仍报**，如实）。

### 2.2 `attempt`（D4 映射）
- body `.meta` **追加一行** `RESUME_ATTEMPTS=$CONT_ATTEMPT`（收尾写点，终值 ✔）。
- collect 解析（F6 同款）⇒ `New-RunReport -Attempt <n>`；`attempt = n if n≥1 else $null`。
- **语义**（写进 §1.6）：本仓的 `attempt` = **该 run 内 opcode 执行尝试数**（站上内环计数；**不含跨 run 的 agent-resume**——那是另一轴，本仓未合流，留白明写）。
- claude 备路：其 collect 不解析 `.meta`（现状）⇒ 备路 run 该槽**仍报**，如实（不假装读到）。

### 2.3 `evidence[]`（RR，D3 本地映射）
- `evidence = @(@{ anchor='agent-output.txt'; digest=$Run['content_digest'] })`（digest 非空时；否则空表+gap）。
- **理由**：这就是"**接线到 run 产出侧**"的最小真值件（F7）；**不发明结构**之外的东西——`{anchor,digest}` 键名与 `ak-*`/锚点族同形，且**登记进 §1.6**（同 `run_id←task_id` 等既有"本地选择"先例）。
- ⚠ **留白**（写死）：更多件（`judgment-record.txt` 等）与更多锚类型**本批不放**——那需要逐件真值来源，**扩面即新批**。

### 2.4 `evidence_budget`（卡契约附加字段，D2 射程）
- **卡面语法**（附加式）：
  ```yaml
  evidence-budget:
    anchors: 3        # 事前**预算**：本任务预计需要核验的锚点数
    tool_calls: 10    # 事前**预算**：预计工具调用数
  ```
- 解析：白名单种子 + 嵌套模式（F3 先例）；`TryParse` 失败 ⇒ `$null`（⇒ **仍报**）。
- P0：`evidence_budget = $Fm['evidence-budget']`（原样透传；`anchors` 非 null ⇒ gap 清）。
- **D2 射程（写死）**：`gaps` 的报出逻辑**不动**（未声明卡照报）；"清空"判定 = **一次新契约卡真跑**（本批的确认 run 即用新卡声明）。
  ⚠ 存量 79 卡/第三方卡**不强制、不批量改写**（改写 = 内容修改，须另裁）。
