# scrubber 规则扩充裁定与影响面（2026-09-21）

> **状态：裁定完成 + 已按本方案实施（2026-09-21）。**
>
> **判据不是"能不能写出正则"，而是"这条规则是防线还是幻觉"。**
>
> **实施**：`Get-ScrubRules`（单一真值源）扩到 **9 条**；私钥块改**拒发**（fail-closed）；夹具 **43/43** + 变异自证 + 拒发路径实弹；落地项状态与诚实边界见 **§6**。
>
> **一句话结论**：机械 scrub 的**可靠边界 = "有固定格式前缀的凭据"**（可判性高、误伤≈0）；一旦进入**自然语言里的身份/拓扑信息**（用户名、手机号、身份证、内网 IP、主机名、绝对路径），**漏检与误伤同时爆炸** ⇒ 那类风险的正确防线是**选对档位（`local-only`）**，不是把正则越写越长。

---

## 1. 判据：三条轴（逐项都按这三条过）

| 轴 | 问什么 | 为什么它决定成败 |
|---|---|---|
| **① 可判性** | 能否**机械**识别，且**误伤≈0**？ | 无固定格式的形态（裸用户名）写不出不高误伤的正则 ⇒ 规则本身不成立 |
| **② 真敏感** | 在本项目威胁模型下，它是否构成**新披露**？ | `sanitized` 的下游有两种：**站上本地引擎**（我们自己的机器）/ **云端免费档**（第三方）。对前者，站上拓扑/路径**不是新披露**；对后者才是 ⇒ 同一形态的敏感度**随接收方变** |
| **③ 误伤代价** | 抹错会不会**静默破坏任务输入**？ | 这是本项目反复栽的坑族（"静默降级"/"看起来处理过了"）。**数字与标识符被改最隐蔽** —— 卡里一个 run ID 变成 `[REDACTED]`，任务照跑但结论错 |

**⇒ 加规则的门槛 = ①高 × ②高 × ③≈0 × 有实际出现路径。四条全中才加。**

## 2. 调研发现（5 条，均有证据，不是推测）

### 2.1 🔑 spec 早就写明"regex + gitleaks"，现状是**回退版**

| 出处 | 原文 |
|---|---|
| [DESIGN.md §193](../../spec/d6-agent-standard/DESIGN.md) | "`sanitized` 时 M3 先跑机械 scrubber（**regex + gitleaks**，§2.1 敏感路由定义），命中即拦截并报脱敏项" |
| [IMPLEMENTATION.md §106](../../spec/d6-agent-standard/IMPLEMENTATION.md) | "（正则清单：密钥模式 `sk-[A-Za-z0-9]{16,}`/邮箱/绝对路径 `D:\`/`F:\`；**gitleaks 若主控站有则挂，无则纯正则版**）" |
| 代码现状 | [`Invoke-Scrubber`](../../ops/station-bin/agent-cli.ps1) 注释自明 `no whitelist in MVP`，**只有 3 条正则** |

**实测**：主控站 `Get-Command gitleaks` ⇒ **未安装**（scoop/winget/choco/Program Files 四处常见路径也都没有）。

⇒ 现状 = IMPLEMENTATION 允许的**"纯正则版"回退**，**不是**实现漏项。但 DESIGN 那句"regex + gitleaks"让人以为 gitleaks 是**必需件** ⇒ 这个歧义要消掉（见 §6-P1）。

### 2.2 🔑 影响面边界：scrubber **只作用于 prompt**，`accept` 命令**不经它**

实测 [agent-cli.ps1 L1245-1267](../../ops/station-bin/agent-cli.ps1)：`$promptFull` = `[proj:x]` + 卡的 `task` 行 + **卡的 body**（clean-room 规格正文）+ **附件文件名** + 尾部变形；scrubber 只改 `$promptFull`。卡的 `accept` 是**另行 base64**、由站上 fused 脚本执行，**完全不消毒**。

⇒ 两条推论（都很要紧）：
- **6 张卡的 `accept` 里写着 `/home/scott-lau/agent-workspaces/paper/...`，这不构成"路径规则会误伤"的证据** —— 那条路径压根不经过 scrubber。**（若不加这条边界，我会把一个不存在的风险写成风险。）**
- 同时它是一条**诚实边界**：`accept` 的**内容**不在不变式②的消毒面内（它只去站上=自己机器，故不是出网泄露；但"消毒面"并未覆盖它）。**附件内容同理**（`scp` 原文，见 §5-3）。

### 2.3 🔑 "长度/前缀判据"会命中**本仓的合法标识符**（实证，这条最硬）

用本仓真实语料算的（脚本一次性，数字已固化在此）：

| 判据 | 对 3 个**真实 run ID** 的命中 | 对**合法编造号**的命中 |
|---|---|---|
| 身份证 `\b\d{17}[\dXx]\b`（长度） | **3 / 3 命中** ❌ | `110101199003072316` 命中 ✔ / 夹具探针 `…1234` 命中 ✔ |
| 身份证 **GB 11643 校验位** | **0 / 3** ✔ | `110101199003072316` 命中 ✔ / 夹具探针 `…1234` **不命中** ✔ |
| 银行卡 `\b\d{16,19}\b`（长度） | — | 夹具探针 `6222021234567890123` 命中 ❌（**Luhn 不通过** = 它不是合法卡号） |
| 银行卡 **Luhn** | — | `4111111111111111` 命中 ✔ |

**为什么这是"最硬"的数字**：本仓的 run ID 格式是 [`yyyyMMddHHmmssffff`](../../ops/station-bin/agent-cli.ps1) = **恰好 18 位数字**，全仓 **204 处**（`agent-chain.json` 104 处 + `OPEN-ISSUES` 20 + `ADR-0007` 23 …）。⇒ **一条"长度判据"的身份证规则，会把本项目最主要的证据句柄整片抹掉**，而它看起来还"工作正常"。

**手机号同样被实证**：`\b1[3-9]\d{9}\b` 命中 `18047253056`，而它是 [`_davidau_download.sh`](../../ops/station-bin/_davidau_download.sh) 里的**模型文件标识**（不是手机号）⇒ 规则会把一个合法的模型引用改成 `[REDACTED-PHONE]`。

⇒ **可推广的结论：对有校验位的标识符（身份证 mod-11-2 / 银行卡 Luhn），判据应当用校验位，而不是长度或前缀。** 校验位把"误伤 3/3"降到"误伤 0/3"，**同时仍认合法号** —— 这是本次唯一一个"既更准又更少误伤"的形态。

### 2.4 现网规模：22 张卡里 `sanitized` **只有 1 张**

| 档 | 张数 | 说明 |
|---|---|---|
| `local-only` | **18** | 不经 scrubber（`$sens -ne 'sanitized'`） |
| `public` | 3 | 不经 scrubber（定义上无约束） |
| **`sanitized`** | **1** | 就是脱敏器自己的验收卡 [`sanitized.md`](../../spec/d6-agent-standard/test-cards/sanitized.md) |

⇒ **今天的 blast radius ≈ 0**。本裁定定的是**将来的语义**，不是"在救火"。**优先级应如实标注为"低-中"**，别包装成紧急项。

### 2.5 反复出现的三类形态是**项目的日常寻址方式**（实证计数）

| 形态 | 全仓出现量 | 性质 |
|---|---|---|
| `.local` 主机名 | **212 处 / 53 文件**（`SSH_OPENCODE_SETUP` 35、使用手册 28、`UPGRADE_SOP` 14、`cluster-watchdog` 9 …） | 本项目**主要寻址方式** |
| `/home/<user>/...` | **211 处 / 100 文件** | 写站上路径的**默认方式** |
| `10.10.1x.x` / `192.168.1.x` | `inventory/net.yaml` 是**权威真值表**（段位/主备路由/主机名映射全在里面） | 网络真值，非敏感数据 |

⇒ **这三类不是"泄漏面"，是本项目的工作原理本身**。把它们抹掉 = 抹掉任务可执行性。

## 3. 逐项裁定（14 项）

**裁定 = 加 6（凭据类）+ 不加 8（身份与拓扑类）。**

| # | 形态 | ①可判 | ②真敏感 | ③误伤（实证） | 裁定 |
|---|---|---|---|---|---|
| 1 | GitHub PAT `ghp_` / `github_pat_` | 高（前缀锚定） | 高（可直接推仓，且本仓有 GitHub 红线） | 无（全仓 0 真例） | **加** |
| 2 | AWS `AKIA`/`ASIA`/`A3T` | 高 | 高 | 无 | **加** |
| 3 | Slack `xox[baprs]-` | 高 | 高 | 无 | **加** |
| 4 | JWT `eyJ…`.`…`.`…` | 中高（base64url 的 `{"`） | 中（常是 bearer 凭据） | 低 | **加** |
| 5 | `Bearer <长串>` | **中（泛）** | 中 | 中（会吃任何长不透明串） | **加，但收窄**：只在 `(?i)bearer\s+` 上下文、且 token ≥ 20 字符 |
| 6 | 私钥块 `-----BEGIN … PRIVATE KEY-----` | 高 | **高（最高）** | 无 | **加**，且**命中即拒发**（见 §5-1） |
| 7 | Linux 绝对路径 `/home/<u>/` | 中 | **低**（接收方多为站=自己机器） | **高**：§2.5 211 处，是默认写法 | **不加** |
| 8 | UNC 路径 `\\srv\share` | 中 | 中 | 低（本仓 0 真例） | **不加**：本集群**无 SMB 服务器** ⇒ 无威胁面（真出现再议） |
| 9 | 内网 IP `10.10.1x` / `192.168.1.x` | 高 | **低**：接收方是自己机器；且拓扑已在 inventory | **高**：真值表本身 + 卡/文档常态引用 | **不加** |
| 10 | `.local` 主机名 | 高 | **低-中**（同 9） | **高**：§2.5 212 处/53 文件 | **不加** |
| 11 | 用户名（裸词） | **不可判**（无格式可依） | 低（已被主机名/路径顺带暴露） | **极高**（命中每一次 `scott-lau` 提及） | **不加**（**不可判**，不是"暂缓"） |
| 12 | 手机号 `1[3-9]\d{9}` | 中 | 中（PII） | **实证**：命中模型标识 `18047253056` | **不加**（改由档位承担，见 §5-2） |
| 13 | 身份证 | 长度=**低** / 校验位=高 | 高（PII） | **实证**：长度判据命中 run ID **3/3** | **不加**；若将来要 ⇒ **必须校验位**（§2.3） |
| 14 | 银行卡 | 长度=低 / Luhn=高 | 高（PII） | **实证**：长度判据命中非卡号的编造值 | **不加**；若将来要 ⇒ **必须 Luhn** |

**"不加"的 8 项里，两种性质要分开记**（否则将来会被误读成"待办"）：
- **7-10、12-14 = 判据成立但选错工具** ⇒ 正确防线是**档位**（含 PII/拓扑的卡**必须** `local-only`）⇒ 登记为**规则**，不是待办。
- **11 = 判据不成立**（不可判）⇒ 永久排除，**不是"暂缓"**。

## 5. 反对意见 / 诚实边界

| # | 反对 | 处置 |
|---|---|---|
| 1 | **"命中即拦截"还是"抹掉继续"？** DESIGN §193 写"命中即拦截"，而三档定义写"sanitized→**脱敏后**远端"（=抹掉继续）。现状是抹掉继续 | ⚠ **歧义要显式裁定**。建议：**按"能不能安全抹掉"二分** —— 凭据类（key/email）**抹掉继续**；**私钥块/`BEGIN PRIVATE KEY` 命中 ⇒ 拒发（fail-closed）**，因为"卡里贴了整把私钥"说明**这张卡本身就不该出网**，抹掉会把它伪装成一张正常卡（同族于"看起来处理过了"） |
| 2 | **PII（手机/身份证/银行卡）不加规则 = 放任？** | 不是。**正确防线是档位**：含 PII 的卡**必须** `local-only`（P3 已使其实体不出网）。把 PII 押在正则上既会误伤（§2.3 实证）又会漏检（自然语言形态无穷）⇒ **regex 军备竞赛在这个方向上必输** |
| 3 | **附件内容不经 scrubber**（`scp` 原文，主路 L1227/1230、claude 路 L2290） | ✅ **2026-09-21 已实测成立**（探针卡 [`scrub-attach-probe.md`](../../spec/d6-agent-standard/test-cards/scrub-attach-probe.md) + 说明 [`…-notes.md`](../../spec/d6-agent-standard/test-cards/scrub-attach-probe-notes.md)）：**两路一致** —— 正文侧必被抹（`LINE1=[REDACTED-PATH]`），**附件侧原样**（`LINE2=D:\Paper\agent-out\secret.xlsx`）。**云端后果的硬证据**：claude 路 run `202609220011097576` 的模型是 `inkling:free`（第三方云），且 claude 自己的转录显示 `tool_use blocks=2`/`Read`×1、**原文进了模型上下文**（不是模型猜的）。⇒ **不变式②在附件上是空的**。**注意别与 §2.2 混**：`accept` 不经 scrubber 但只到站（自己机器），不是同类 |

| 5 | 本裁定的**收益有限**（今天只有 1 张 sanitized 卡） | 属实，**且应当明说**（§2.4）。价值在于：把 `sanitized` 的**语义边界定死**，避免将来"随手加条正则"（本项目已多次栽在"判据看起来在跑"上） |
| 6 | 6 条规则**不是我枚举的终点** | 对。所以 §6-P2 要求**规则清单同源 + 夹具强制覆盖率报告** —— 新形态没进规则必须**显式可见**，不能默认"应该覆盖了" |
