# 任务卡证据流"协同篡改"威胁——补充调研

> **日期**: 2026-09-17
> **上游**: 《任务卡证据流可重放性调研》（2026-09-16）§2.9 自承的残余风险 + 作者复评
> **姊妹篇**: [2026-09-16_任务卡证据流可重放性调研.md](./2026-09-16_任务卡证据流可重放性调研.md)
> **触发**: 复评指出——阶段 0 已回收 `.meta` 等原始记录，但 `.meta` 是**远端剧本自己写的**，只是从"wrapper 转述"升级为"builder 原始转述"，**仍未解决"读→改→还原"的协同篡改**。

### 本文核心结论（一句话）

> **在"执行方 = 唯一的证据写者 = 密钥持者"这一拓扑下，单点篡改是物理上无痕的（防不住）；可防的是把"无痕单点篡改"升级为"所有副本+外置锚全改的协同攻击"——即把证据的**锚**剥离出执行方的信任域。** 本框架的最优落点是：**prev_hash 证据链 + 主控外置链头 + 三站交叉见证**，且明确这**不是防篡改**，只是把"改了会被发现"的概率从 0 拉到趋向 1。

---

## 1. 威胁模型（先问对问题）

"协同篡改"必须拆成三个强度，防御成本天差地别：

| 强度 | 攻击者能力（负面但受限于） | 是否可防 |
|---|---|---|
| **T1 单执行进程越权** | 只写/改**一次运行**产生的记录，改后发现不了 | ✅ 可防（哈希链 + 外置锚）|
| **T2 执行站被攻陷（进程级）** | 可改写**该站所有历史证据** 且拥有该站**证据写入密钥** | ◐ 部分可防（仅当链头/密钥在该站之外）|
| **T3 攻击者=执行站 + 主控侧协助/泄露** | 可改写**全链**、拥有**所有密钥**、可对称回溯 | ❌ 物理不可防 |

**判定门**：防御设计的目标是把 T2→T3 的"跨界"变难（链头/密钥/见证者不能与执行站共存一个信任域）。若三者共域，则跌回 T3，一切记录退化为"builder 自述"，与 [Mini Shai-Hulud](https://slsa.dev/blog/2026/05/mini-shai-hulud-what-slsa-can-and-cannot-do) 同一结论。

**本框架关键事实**：执行站是 **A/B/C 三台 Linux 推理站**，证据回收方是主控（Win10 主控机）——**主控与执行站在不同物理机/信任域**。这是本方案可行的前提（§6 依赖它）。

---

## 2. 本框架当前的暴露面（为何"回收"不等于"可信"）

阶段 0 之后，`agent-out/<ts>/` 有了 `.meta` / `.prompt.txt` / golden-cmd / 当次 checksum，但这批文件的**权威锚**仍在执行站侧：

| 记录 | 写者 | 权威锚在哪里 | 协同篡改路径 |
|---|---|---|---|
| `.meta`（TASK_RC/ACCEPT_OK/...） | 远端剧本自写 | 执行站本地 | 执行站可"跑假判据→写真值"或"跑真判据→改结果" |
| `accept-output` / `golden-output` | 远端剧本写 | 执行站本地 | `sha256sum -c` 比对、golden 注入、结果判断都在**同一次远端执行**内 ⇒ "读字面量→改→还原"即可通过（[strong-accept](./../../spec/d6-agent-standard/strong-accept/DESIGN.md#L216) 自承）|
| run.json（主控构造） | 主控 | 主控 | 主控属独立信任域 → **结构化字段可信**，但它只"转述"从站上 scp 回来的字节，不增加站上部分的可信度 |

> **要点**：阶段 0 的价值不是"让记录可信"，而是"让记录可看、可复核、可定位"。它把"篡改"从**无痕**变成**有痕但主控侧无独立依据断言**——`sha256(prompt.txt)==prompt_sha256` 只能证明"回收的字节与构造时一致"，**不能证明"远端执行时的字节与回收的一致"**（回收本身就是一个可被 T2 拦截/替换的 scp 点）。

---

## 3. 核心不变量：为什么"协同篡改"防的是概率而非可能性

- **单写者拓扑下，任何只落在"会被改的那一侧"的证据都不足信**。这是公理，不是工程缺口。
- 因此防御的唯一杠杆 = **把若干"锚"放到执行方**改不到 **的地方**，令"彻底无痕"必须跨信任域改写 `N≥2` 个独立持有者。
- 现实的"锚"候选（按不可靠→可靠）：
  1. 执行站自己的其它进程（同态，T2 一并拿下）——**不可靠**
  2. 主控（异机）——**可靠**（本框架已具备）
  3. 冷介质/现阶段外置（脱机、只读）——**可靠且唯一防 T2 全量回改**
  4. 时间戳/公证服务（不可逆固化）——**可靠**，但引入第三方依赖
- **诚实结论**：最省钱且匹配本框架的就是主控。冷介质/公证是 T2 全量回改时才必须的升级。

## 4. 社区对策盘点（复用既有 §5 素材 + 本次归类）

| 对策 | 机制 | 解决哪个强度 | 来源 |
|---|---|---|---|
| **append-only + prev_hash 哈希链** | 每条记录含上一条哈希 ⇒ edit/delete/reorder 在**第一条断裂处**被定位 | T1（定位到"哪天起的不可信"） | [Promptise audit trail](https://docs.promptise.com/blog/detect-a-tampered-agent-audit-trail/) |
| **链头 root 外置** | 链首（root）持于不受执行方控制的实体，周期核对 | T2 的全量回改（改了历史但 head 不匹配） | 同源 + in-toto/SLSA 的信任根思想 |
| **观测方与执行方分离** | 只读 watchdog 独立记录"它观察到的"，与执行方自述对比 | T1/T2（不依赖执行方自述） | NIST AI RMF"建造者与验证者分开"、§5.4 |
| **签名密钥外置（HSM/冷签）** | 证据由不在线的密钥签名，签后不可在触发点旁签名 | T2 的"顺手伪造签名" | [任务卡证据流可重放性调研](./2026-09-16_任务卡证据流可重放性调研.md) §5.1 |
| **时间戳/不可变固化（区块链/RGP）** | 记录哈希冲入公共不可逆锚，事后不可抹 | T2/T3（对已公开者不可回改） | 公证时间戳类，T3 仍可"提前不记录" |
| **determinism contract + content-address** | 重放不产生新模型调用；内容寻址 cache | 无关篡改（可放行的补充） | [The Log is the Agent](https://arxiv.org/pdf/2605.21997.pdf)、ESAA §5.3 |

**关键判据（从上述提炼）**：
1. `/prev_hash 链 + root 外置` 是**本框架性价比最高**的组合（T1 全防 + T2 因主控锚而被察觉）。
2. 观测方分离**不扩证据面**，只提供"独立旁证"，是 stage 2 复验器可有。
3. 时间戳固化**不防"提前不记录"**（只能防"已记录后被抹"）——对"这条 run 根本没跑"这种攻击无效，需配合观测方。

## 5. 判定：哪些物理可行、哪些是幻觉

| 方案 | 可否证伪 | 说明 |
|---|---|---|
| prev_hash 链：能证"某条 run 之后的记录未被改" | ✅ | 若 root 在主控，执行站改任意后续记录会断链 |
| 断链定位：能证"从哪条起不可信" | ✅ | 对比主控 chain head |
| **"能证某条 run 的判定真的在站上跑过、结果真为 0"** | ❌ | 这是 T3/Judgement 级——只要 builder 主导，任何记录都不可独立证真；只能"无法证伪" |
| "回收的 prompt == 远端执行时 prompt" | ❌（仅 T1） | scp 回收点本身可被 T2 拦截替换；需旁证（见 §6 verdict） |

> **红线**：本文不承诺"防协同篡改"。只承诺"把无痕变成有痕 + 可断链定位"。任何声称能"证明判据未被篡改过"的表述都是幻觉（Mini Shai-Hulud 教训）。

## 6. 本框架最小实施方案（若推进）

> **前置依赖**：主控与执行站分离 = 已具备（§1）。这部分是"若做"的提案，需走 [ADR-0004](../../adr/ADR-0004-统一管理入口为唯一管理面.md) 三条合法路径后落地。

### 6.1 证据链（prev_hash + 主控外置头）

- 每条 run 的 `agent-out/<ts>/` 落幕后，主控为该 run 计算
  `run_digest = sha256( agent-output.txt ‖ accept-output.txt ‖ accept-golden-output.txt ‖ .meta ‖ golden-sha256 )`。
- 维护一个小文件 `agent-chain.json`（主控独占，0664，主控本人可写）：
  `{ "head_digest": <本run>, "prev_digest": <上run>, "chain": [<run_id→digest>...] }`。
- **head 另写一份到主控的非执行侧冷路径**（如 `_upstream/archive/`，git 提交）。

**判据**：
- `run_digest` 可随时由主控重算并逐项核对 → 任何站上改动在 `run_digest` 不符时被捕获（T1 全防）。
- 冷路径 head 与当前 `agent-chain.json#head_digest` 一致 → T2 全量回改原备检（改链需同样改冷路径）。
- prev_hash 逐个回放 → 断链定位到"从哪条起 N/A"。

### 6.2 独立旁证（观测方，可选加强，避开 T3's 提前不记录）

- `ops/cluster.py agent verify <run-id>`：只读，**不触碰站上**，对归档 `agent-out/<ts>/` 逐条 replay-op（复用 [阶段 1 草案 replay-ops](./2026-09-16_任务卡证据流可重放性调研.md#壹---evidence-manifest-字段草案阶段-1-用需走adrd3后落地)）。
- 输出 gap 表，不输出"评分"（沿用评审环 advisory 语义）。

### 6.3 明确不做

- 不引入 T3 级公证/链上化（成本高、收益低于"主控外置"在 T3 已稳的场景）。
- 不承诺"第二执行者复验"——那是完全不同的成本（需双倍算力）。

---

## 7. 诚实边界（不能证的事，白纸黑字写清楚）

1. **不能**证明"某条判据判定某次真的在站上跑过且结果为 0"——只有"无法证伪于主控持有的 head"级别。
2. **不能**防 T3（执行站 + 主控密钥/库全泄露）。真到 T3，`agent evidence` 与所有审计基础设施一样失效。
3. **不能**防"提前不记录"——攻击者直接跳过埋点产生的空窗，只靠证据链无从察觉，需观测方旁证。
4. **不能**把链条当知识产权/合规证据滥用（EU AI Act Art.12 属高风险系统，本框架不主张）。

---

## 8. 结论

- **阶段 0 已解决的**：记录可看、可复核、断链可定位。
- **本次补充解决（若推进）**：把"无痕篡改"升级为"需主控侧协同才能无痕"——护栏 = prev_hash 链 + 主控外置 head（§6.1），可选加观测方旁证（§6.2）。
- **明确不追求**：物理上不可能的"证明判据未被篡改"（§5 红线）。
- **真基准**：防御目标不是"让攻击者改不了"，而是"把改了的痕迹从 0 提到趋向 1，且改的成本压过收益"——这与其验证方法论"精确测量该相信到什么程度"完全同源。
