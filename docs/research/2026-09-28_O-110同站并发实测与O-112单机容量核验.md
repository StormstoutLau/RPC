## 1. 结论速览

**O-110（同站并发 × 模型规模）**

1. ★ **O-18 的「同站 2 并发 ~2.8× 恶化」在本口径下未复现** —— 固定 decode 工作量下，C=2 的单请求劣化只有 **1.13–1.45×**，而**聚合吞吐反而 +32–48%**。
2. **H-1a（batching 摊薄权重读取）成立**：llama.cpp 的 4-slot 服务在 C=2 时把权重读取摊薄，聚合吞吐**超线性**。
3. **H-1b（UMA 带宽硬顶）成立**：大模型（120b）的聚合吞吐在 C=2→C=4 **平台化**（1.48×→1.46%，零增益），单请求继续劣化到 1.9–2.3×。
4. ★ **H-1c（并发代价随模型规模上升）方向成立**：C=4 时小模型（20b）聚合仍涨（1.63×）、大模型（120b）不涨（1.46%），且单请求劣化 120b（1.90×）> 20b（1.77×）。
5. ⚠ **前提修正**：生产的 unsloth studio **默认就是 `--parallel 4`**（实测 `total_slots=4`）⇒ "同站多并发"不是我们新开的口子，而是**现役默认形态**。

**O-112（DS V4-Flash 单机容量）**

6. ★ **A 站 rpccache 实测 148 GiB**（登记值「51 G / 78 G」**已陈旧**）；它是纯缓存，可回收。
7. ★ **单机容量上界实测 ≈ 119 GiB**（= 59.03 GiB 权重撑出 61.84 GiB GTT，余 57.55 GiB）；**已证先例 103 GiB**（Qwen3.8-Flash-Next）。
8. ★ **各档真实体积（hf-mirror 元数据，零下载）**：最低档 **IQ1_S 76.9 GiB**、**Q2 档 84.6–90.2 GiB**、**Q3_K_M 119.3 GiB**。
9. ⇒ **判定**：**(B) 路线（原模型 + Q2/IQ2 档，77–90 GiB）单机可行且有余量**；**Q3 档（119.3 GiB）单机不可行**（≥上限）。**台账原文的「Q2 ≈ 71 G」偏乐观**（实测最低 76.9，Q2 档 ≥84.6）。

## 2. 方法与环境（E1）

| 项 | 值 |
|---|---|
| 站 | **B（192.168.1.32）** —— 权重在 B，且两档模型同站同引擎 ⇒ 单变量 |
| 引擎 | unsloth studio 自带 `~/.unsloth/llama.cpp/build/bin/llama-server`（ROCm/HIP，`b10715-92cedc867`，0.3.0-dev） |
| 实例参数 | 由 `cluster.py load <alias>` 生成：`-fa on --no-context-shift -c <conf> --kv-unified --cache-type-k/v q8_0 --flash-attn on` + studio 默认 **`--parallel 4`** |
| 观测口径 | `POST /v1/completions` 返回的 **`timings`**（llama.cpp 附加字段）= 手册"API timings"口径 |
| 负载 | 固定 prompt（34 tok）+ `max_tokens=512`（实测 `predicted_n` 恒 512）+ `temperature=0` + `cache_prompt:false`（强制每请求全量 prefill） |
| 变量 | **同站并发度 C ∈ {1, 2, 4}**；每档 3–5 轮，取**中位数** |

★ **为何必须用 `/v1/completions`**：studio 关闭了原生 `/completion`、`/slots`、`/metrics`、`/health`（实测均 404）⇒ 只剩 OpenAI 兼容面 + `/props`。另：8080 **仅监听 127.0.0.1** ⇒ 客户端必须**在站上跑**。

## 4. H-1 三假设判定

| 假设 | 判定 | 依据（E1） |
|---|---|---|
| **H-1a** batching 摊薄权重读取 ⇒ 同站 2 并发**不再 ~2.8×** | ✅ **成立** | C=2 单请求仅劣化 1.13–1.45×，**聚合 +32–48%**（超线性）⇒ 权重读取确实被摊薄 |
| **H-1b** UMA 带宽是硬顶 ⇒ 换栈也 ~2.8× | ◐ **部分成立** | 120b 的聚合吞吐 **C=2→C=4 零增益**（1.48×→1.46%）⇒ 存在带宽顶；但"换栈也 2.8×"**未测**（本测只在 llama.cpp 内） |
| **H-1c** 并发代价随「模型规模 / 单序列带宽占用」单调上升 | ✅ **方向成立** | C=4 时：小模型聚合仍涨（**1.63×**）、大模型**不涨**（1.46%）；单请求劣化 120b（1.90×）> 20b（1.77×） |

**⇒ 对 O-18 的处置建议（不改判定，只加口径）**：`O-18` 的「扇出优先跨站各 1 并发」**作为调度纪律仍成立**（它管的是"谁的错"可归因、长上下文不被切薄、USB4 层间通信），**但其"物理依据 ~2.8×"应降级为"仅在特定负载形态（短输出/墙钟口径）下成立"**，并**按模型规模分档**（H-1c）。

## 5. 诚实边界（必须与结论同读）

1. ★★ **绝对吞吐与手册 §3.5 表不可比** —— 本测 prompt 仅 34 tok + 512 生成 + `--parallel 4`（每 slot ctx 被 4 分）；§3.5 的 gpt-oss-120b「50.3–54.2 t/s」是长生成/ctx 65536 口径。**只有本测内部（同机同轮）的 C1/C2/C4 相对值是结论**。
2. ★★ **O-18 原始读数与本测不同量** —— O-18 的 `1.7→4.8 s` 是**墙钟**（含 prefill + 排队 + 短输出），本测是**纯 decode tg**。⇒ **不能用本测直接"推翻" O-18**，只能说"**在纯 decode 口径下 2.8× 不成立**"。
3. ⚠ **本仓对 O-18 的证据出处本身有两处互斥**：`BLINDSCAN-v2 §8.7.6` 写的是 **gpt-oss-120b-MXFP4 双机同权**；而 `O-110` 原文写「300B 级层分布大模型」。⇒ **登记为"同一事实两处出处，口径待统一"**（属本仓已登记的"把两件事说成一件"同族）。
4. ⚠ **单请求 tg 轮间方差大**（120b C=1 实测 57–99 t/s，C=4 最大 78–157）⇒ 全部用**中位数**；小样本（3–5 轮）不构成置信区间。
5. ⚠ **"现役 300B 级"档未能纳入**：GLM-5.3-Flash（320B / 146 GiB）**无法单机加载**，只能双机 RPC ⇒ 与"同站并发"**不同拓扑**，不可比。⇒ 本轮"两档规模"落在 **11 GiB 与 59 GiB**（6× 权重差、1.4× 激活差）。
6. ⚠ **`--parallel 4` 使每 slot ctx 被 4 分**（20b：8192；120b：32768）—— 长上下文场景的并发代价**未测**。

## 7. O-112 判定（D-1 段）

1. ★ **总站内存不是瓶颈，权重体积才是** —— A/B 各 124.9 GiB，单机 GTT 上界 ≈119.4 GiB。
2. ★ **(B) 路线（原模型 + Q2/IQ2 档）单机可行且有余量**（77–90 GiB，留 ≥29 GiB）⇒ 依 `O-112` 既裁的「**若 B 已够，则 A 无必要**」，**A 路线（REAP 剪枝）在本集群的必要性进一步下降**。
3. ★ **Q3 档单机不可行**（119.3 GiB ≥ 上界）—— 那正是**现役双机**的量级；故"想单机"必须落到 **IQ3/IQ2/IQ1** 档。
4. **rpccache 148 GiB 可回收**，但对上述判定**无影响**（它是磁盘缓存，不占 GTT）。

## 8. 未实测登记

1. ★ **(B) 路线的"同题对照"（准确率）未做** —— 需先下载任一 Q2/IQ2 档（**77–90 GiB**），**非零成本** ⇒ 属"**需先裁是否下载**"的决策点（`O-112` D-1 原文把这一半写成零成本，**就地更正为：D-1a 零成本（本文件）· D-1b 需一次下载**）。
2. **Q3 档的真实加载实测未做**（本机无该档权重；下载 ≈119 GiB）⇒ 6.3 的 ❌ 是**算术判定**，非加载实证。
3. **`n_ubatch` 扫描未做** —— 本轮刻意固定默认（按 `O-110` 判据"同 n_ubatch"）。
4. ★ **与 O-18 原始读数可直接对照的形态未复现** —— chat 路径 + 长系统提示 + 墙钟口径（那才是 1.7→4.8 s 的形态）。
5. **换栈（vLLM）侧的 H-1b 未测** —— 本测只在 llama.cpp 内 ⇒ "换栈也 2.8×"仍无实测。
6. **长上下文场景的并发代价未测**（`--parallel 4` 下每 slot ctx 被 4 分）。
7. **A 站 rpccache 未实际回收**（只核"可回收性"）。
