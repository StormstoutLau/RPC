### 1.1 关键 E1 发现（决定解法边界）

1. **实例 conf 只被 bash `source`，不是 systemd `EnvironmentFile`**：站上 `llama-server@.service` 只有 `ExecStart=/usr/local/bin/llama-serve-instance %i`（无 `EnvironmentFile=`）；[llama-serve-instance L3](../../ops/station-bin/llama-serve-instance#L3) 明说「systemd EnvironmentFile 无法表达条件参数，故用 wrapper」。⇒ **`%q` 的 systemd 兼容性问题在本仓不成立**，但**文本解析器**的兼容性问题成立（下条）。
2. **conf 有文本解析消费者**：[rpc_check.py L5066](../../ops/rpc_check.py#L5066) 用 `sed -n 's/^MODEL_PATH=//p' | tr -d '"'` 读权重路径；`%q` 产出的 `$'...'` 不会被 `tr -d '"'` 剥掉 ⇒ 权重检查会读到错误路径。⇒ **不能直接照搬「用 `%q`」**，必须同时升级读取侧，或改用双引号 + 转义。
3. **模型落点有三种**：[cluster_model.py L48-52](../../ops/cluster_model.py#L48-L52) 已写死三类（`gguf/<repo>/<file>` · `gguf/<repo>/<Model>-GGUF/<f>` · `gguf/<repo>/<Model>-GGUF/<QUANT>/<f>`），扫描用 `-mindepth 2 -name '*.gguf'`（文件级）。⇒ 正确的定位规则**已经存在**，缺的是把它抽成共享实现。

## 3. 逐项分析

### 3.1 #3 模型定位：文件枚举 vs 固定目录深度

**外部事实（E3）**

- GNU `find`：`-maxdepth levels` =「下探至多 levels 层目录」；`-mindepth levels` =「不处理低于 levels 层的项」——深度是**相对命令行起点**的层数（[GNU Findutils · Directories](https://www.gnu.org/software/findutils/manual/html_node/Directories.html)）。
- 因此 `find /data/models/gguf -mindepth 2 -maxdepth 2 -type d` 只会命中 **depth=2 的目录**（`gguf/<repo>/<sub>/`）；而 `gguf/<repo>/<file>.gguf` 的 `<repo>` 是 **depth=1 目录**，**不会被命中** ⇒ `REPO` 为空 ⇒ `repo not found`。这与评审原文的触发场景逐字一致（E2）。

**本仓事实（E1）**

- [infer-load L70](../../ops/station-bin/infer-load#L70) 的 `ALL_ALIASES` 已用 `-mindepth 2 -name '*.gguf'`（**文件级**），能看见仓库级直放；
- [L115](../../ops/station-bin/infer-load#L115) 的 `REPO=` 仍是 `-mindepth 2 -maxdepth 2 -type d`（**目录级**）⇒ 同一脚本里两套规则。
- `infer-list` 已改为文件级分组（`find ... -name '*.gguf'` 后按路径分组），与 [cluster_model.py L48-52](../../ops/cluster_model.py#L48-L52) 的三种落点一致。

**可迁移机制**

- 把「别名 → 模型目录（或直接文件）」的规则收敛为**一份共享实现**，由 `infer-load` 与 `infer-list` 共同 `source`；
- 规则 = **先枚举 `*.gguf` 文件，再按路径分组**，而不是按固定目录层数找目录；
- 三种落点都要有测试：`gguf/<repo>/<f>`（depth-1 仓库级）、`gguf/<repo>/<Model>-GGUF/<f>`、`gguf/<repo>/<Model>-GGUF/<QUANT>/<f>`。

**不可照搬**

- 外部只提供 `find` 语义，不提供本仓的三种落点；**规则真值必须在 `cluster_model` / 共享函数**，不能在两个脚本里各写一套。
- 不建议把主控侧的 Python `group_by_model` 直接搬到站上（站上是 bash，无 Python 依赖保证）；应**移植规则**，不是移植实现。

**建议的最小契约**

```
model_scan()            # 输出 alias|模型目录|大小|主gguf（文件级分组）
model_dir_for_alias()   # 输入 alias，输出模型目录或空
```
- `infer-load` 首次生成 conf 与 `infer-list` 都调用同一函数；
- `infer-load` 在 `REPO` 为空时打印**候选 alias 列表**（可诊断），而不是只报 `repo not found`；
- 先验红：仓库级直放 + 无 conf ⇒ 修复前 `repo not found`；修复后 conf 的 `MODEL_PATH` 指向该文件。

### 3.2 #4 conf 写入的引号与 `sed` 转义

**外部事实（E3）**

- ShellCheck **SC2086**：不加引号的展开会做 **word splitting + glob expansion**；含空格/换行/glob 字符时脚本会坏（[SC2086](https://www.shellcheck.net/wiki/SC2086)）。
- Bash `printf '%q'`：输出「可被 shell 重新读入」的转义形式（[Bash Builtins](https://www.gnu.org/software/bash/manual/html_node/Bash-Builtins.html)）；GNU coreutils 的 `%q` 对不可打印字符用 POSIX `$'...'` 形式（[GNU printf](https://www.gnu.org/software/coreutils/manual/html_node/printf-invocation.html)）。
- GNU `sed` 的 `s` 命令：替换串里的 **未转义 `&` = 整个匹配**；分隔符（本文用 `|`）出现在 regexp/替换里必须前置 `\`；要输出字面 `\`、`&`、换行也须转义（[GNU sed · s Command](https://www.gnu.org/software/sed/manual/html_node/The-_0022s_0022-Command.html)）。
- systemd `EnvironmentFile=`：值两端不加双引号时会**剥掉首尾空白**（[systemd.exec(5)](https://manpages.ubuntu.com/manpages/xenial/man5/systemd.exec.5.html)）。⚠ **本仓实例 conf 不走 EnvironmentFile**（§1.1），此条只作为「双消费者格式差异」的对照，**不是**本仓约束。

**本仓事实（E1）**

- `conf` 由 [llama-serve-instance L10](../../ops/station-bin/llama-serve-instance#L10) 与 `infer-load` 各自 `source`；
- [rpc_check.py L5066](../../ops/rpc_check.py#L5066) 用 `sed ... | tr -d '"'` 读 `MODEL_PATH` ⇒ **只认双引号，不认 `$'...'`**；
- [infer-load L176](../../ops/station-bin/infer-load#L176) 的 `sed -i "s|^$1=.*|$1=$2|"`：`$2` 未转义，含 `|`/`&`/`\` 会写坏；且 `sed -i` 非原子（写一半失败会留坏 conf）。

**方案对照（E4 推断 + E3 依据）**

| 方案 | bash `source` | 文本解析器（`tr -d '"'`） | 结论 |
|---|---|---|---|
| 甲：`printf '%q'` | ✅ | ❌ `$'...'` 不会被剥 | 需同步改解析器；否则 `rpc_check` 权重检查读错 |
| 乙：双引号 + 转义 `\` `"` `$` `` ` `` | ✅ | ✅（现有 `tr -d '"'` 可用） | **推荐**；但含 `"`/`\` 的路径需读取侧反转义 |
| 丙：不引号 + 拒绝特殊字符 | ✅ | ✅ | 最省事但**限制合法路径**（空格路径是评审的场景，不能拒） |
| 丁：改 JSON/TOML | ✅（需解析器） | ✅ | 改动面过大，不适合 P1 |

**推荐（乙 + 原子写）**

1. **单一写入口** `conf_set_kv KEY VALUE`：输出 `KEY="<escaped>"`，转义 `\` `"` `$` `` ` ``；用 `mktemp` + `mv` **原子替换**，不再 `sed -i` 就地改；
2. **单一读入口** `conf_get_kv KEY`：剥外层引号并反转义；`rpc_check`/`cluster` 的文本读取改用它（或至少兼容「带引号/不带引号」两种形态）；
3. **首次生成 conf** 的 heredoc 改为对 `MODEL_PATH` 使用同一 `conf_quote` 函数；
4. **测试**：路径含空格、`&`、`|`、`"`、`\`、`$`、`*`（glob）；断言 `source` 后 `MODEL_PATH` 逐字节一致，且 `rpc_check` 读到的路径一致；含换行/`NUL` 的路径**拒绝**并报错。
5. **`set -e` 不是替代**：BashFAQ 105 明确 `set -e` 有大量例外（`if` 条件、管道非末段、命令替换子 shell 等）；关键写操作（`tee`/`mv`）必须显式 `|| exit`（这条与 #5 P2 共用）。

**不可照搬**

- **不要**只按评审原文「用 `%q`」落地——本仓有文本解析器，`%q` 会破坏 `rpc_check`；必须**写读同改**。
- **不要**把 systemd `EnvironmentFile` 的引号规则当成本仓约束（本仓 conf 不走它）。

### 3.3 #7 ds4 coordinator 监听默认

**外部事实（E3）**

- **CWE-1327**：绑定 `0.0.0.0` = 对本机所有 IP、所有可达网络开放；缓解 =「Assign IP addresses that are not `0.0.0.0`」或防火墙（[CWE-1327](https://cwe.mitre.org/data/definitions/1327.html)）。
- **PostgreSQL** `listen_addresses` 默认 **localhost**（只允许本地回环 TCP）；`*`/`0.0.0.0` 才监听全部（[PostgreSQL Docs](https://www.postgresql.org/docs/current/runtime-config-connection.html)）。
- **Ollama** 默认绑 `127.0.0.1:11434`；要暴露到网络须显式设置 `OLLAMA_HOST`（[Ollama FAQ](https://docs.ollama.com/faq)）。

**本仓事实（E1）**

- [infer-load L394](../../ops/station-bin/infer-load#L394) `--listen "${PP_LISTEN:-0.0.0.0}"`；
- `_davidau_start.sh:8` `--host 0.0.0.0`（README 称一次性脚本、有意保留）；
- ds4 PP 的 coordinator 需要被 worker 通过 **USB4 直连段**访问；`DS4_PP_MODELS` 在 [cluster_const.py](../../ops/cluster_const.py) 里声明（coordinator 站, worker 站）。

**方案对照（E4）**

| 方案 | 单机安全 | PP 可用 | 结论 |
|---|---|---|---|
| 甲：默认 `127.0.0.1`；PP 必须显式 `PP_LISTEN` | ✅ | 需显式 | **推荐**：安全默认 + 显式暴露 |
| 乙：默认取本机直连段 IP | ✅（仅直连段） | ✅ | 需按拓扑推导；多直连段站（B 有 A-B / B-C 两段）要选对 |
| 丙：保持 `0.0.0.0` + 防火墙/认证 | ❌（依赖外部） | ✅ | 与 CWE-1327 缓解相反；不作为默认 |

**推荐（甲 + 编排层传参）**

- `infer-load` 的 `PP_LISTEN` 缺省改 **`127.0.0.1`**；
- 多机 PP 由**编排层显式**传 `PP_LISTEN=<直连段 IP>`（`cluster.py` 已知 `DS4_PP_MODELS` 的 coordinator/worker 站，可推导段 IP）；`infer-load` 在 `BACKEND=ds4` 且 PP 目标非本机、`PP_LISTEN` 未显式给出时**响亮中止**（判不了 ≠ 选 0.0.0.0）；
- 启动日志打印**实际绑定地址**；门禁/预检可加「ds4 端口在 `0.0.0.0` 且非一次性脚本」的告警（先报数，不直接红）；
- `_davidau_start.sh` 作为一次性脚本，保留 `--host 0.0.0.0` 但在文件头标注「仅隔离网段使用」。

**不可照搬**

- 不能无脑默认回环：ds4 PP 的 worker 在另一台机器，回环不可达；必须由编排层显式传直连段 IP。
- 不要引入认证层（本仓无 daemon、无用户体系）；安全默认 + 显式暴露 + 日志留痕即可。

### 3.4 #10 Web UI token：常量时间比较 + 不进 URL

**外部事实（E3）**

- Python `hmac.compare_digest(a, b)`：用**避免内容相关短路**的实现，降低时序攻击风险；`a`/`b` 必须同类型（ASCII `str` 或 bytes-like）（[Python Docs](https://docs.python.org/3/library/hmac.html#hmac.compare_digest)）。
- **RFC 6750 §2.3**：把 access token 放 URI query 时，「URL 含 token 很可能被记录」（high likelihood that the URL containing the access token will be logged）⇒ **SHOULD NOT** 使用，除非无法用 `Authorization` 头或请求体（[RFC 6750 §2.3](https://www.rfc-editor.org/rfc/rfc6750#section-2.3)）。
- **Referrer-Policy: no-referrer**：省略 `Referer` 头，请求不携带任何 referrer 信息（[MDN](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Referrer-Policy)）。

**本仓事实（E1）**

- [cluster_web.py L400](../../ops/cluster_web.py#L400) `self.headers.get("X-Auth-Token", "") == self._token`；
- [L1437](../../ops/cluster_web.py#L1437) 启动日志打印 `http://127.0.0.1:<port>/?token=<token>`；
- 默认只绑 `127.0.0.1`/`::1`，但 `--host 0.0.0.0` 是可用参数。

**推荐（最小改动）**

1. 比较改 `hmac.compare_digest`（token 为 `secrets.token_urlsafe` 产出的 ASCII，类型匹配）；比较失败与长度不等都返回 401（不泄露长度差异）；
2. **保留** `?token=` 但只作为**一次性引导**：仅允许 loopback 绑定；校验通过后 `Set-Cookie: rpc_token=<token>; HttpOnly; SameSite=Strict; Path=/`，然后 `302 /`（剥离 query）；后续请求走 cookie 或 `X-Auth-Token`；
3. 所有响应加 `Referrer-Policy: no-referrer`；日志与错误信息**永不打印完整 token**（只打前 4 位或 hash）；
4. `--host` 非 loopback 时，**拒绝** `?token=` 引导（或强制 `--token` + header），并在启动日志显式告警；
5. 先验红：源码级断言「比较必须调用 `compare_digest`」；行为级断言「`/?token=...` 返回 302 + `Set-Cookie` 且响应体不含 token」「非 loopback 绑定 + query token ⇒ 401」。

**不可照搬**

- 不需要完整 OAuth 资源服务器/ JWT；本仓是本地单用户 UI，**常量时间比较 + 引导后剥离 + no-referrer** 已覆盖评审指出的两类风险。
- 不要把 token 放 `localStorage` 后再用 query 传递（前端现有 localStorage 方案可保留，但引导链接应只用于换取 cookie）。

## 4. 可迁移 / 不可照搬总表

| 可迁移 | 依据 | 不可照搬 | 理由 |
|---|---|---|---|
| 用**文件清单**枚举模型，再按路径分组 | GNU find 深度语义 + 本仓三落点 | 把 K8s/其他系统的固定目录布局搬来 | 本仓三落点由 `cluster_model` 定义 |
| 单一写入口 + 单一读入口 | ShellCheck SC2086 + GNU sed 转义 | 只改写入侧、不改读取侧 | 文本解析器会读错 `%q` |
| 双引号 + 转义 + 原子替换 | Bash/sed 语义 | `sed -i` 就地改关键 conf | 非原子、转义难完备 |
| 安全默认 = 回环，暴露须显式 | CWE-1327 / PostgreSQL / Ollama | 默认 `0.0.0.0` + 事后防火墙 | 依赖外部配置，默认即暴露 |
| `compare_digest` + token 不进 URL | Python / RFC 6750 / MDN | 完整 OAuth 资源服务器 | 本地单用户 UI，过重 |
| 关键写操作显式 `\|\| exit` | BashFAQ 105 | 只加 `set -e` 就认为安全 | `set -e` 有大量例外 |

## 5. 结论与优先级

### 5.1 P1 内部排序（风险 × 成本）

| 顺序 | 事项 | 理由 | 预计改动面 |
|---|---|---|---|
| 1 | #10 token 常量时间 + 引导剥离 | 改动最小、风险明确、无拓扑影响 | `cluster_web.py` 2–3 处 + 测试 |
| 2 | #4 conf 写读同改 | 影响 conf 正确性；需同时改 `infer-load` 与 `rpc_check` 读取 | `infer-load` 1 个写函数 + `rpc_check` 1 个读函数 + 测试 |
| 3 | #3 模型定位共享实现 | 首次加载阻断；需抽共享函数 + 三落点测试 | `infer-load` + `infer-list` + 共享 lib + shell 测试 |
| 4 | #7 ds4 监听默认 | 需拓扑决策（PP 显式传参）；改动小但牵涉 `cluster.py` | `infer-load` 默认值 + `cluster.py` 传参 + 日志/预检 |

### 5.2 建议的最小落地契约

1. **共享模型定位**：`model_scan` / `model_dir_for_alias` 一份实现，`infer-load`/`infer-list` 共用；三落点测试。
2. **conf 写读契约**：`conf_set_kv`（双引号 + 转义 + 原子替换）与 `conf_get_kv`（剥引号 + 反转义）；`rpc_check` 读取改用它。
3. **ds4 绑定**：默认 `127.0.0.1`；PP 由编排层显式传直连段 IP；未显式 + 非本机 ⇒ 中止；日志打印实际绑定。
4. **Web 鉴权**：`compare_digest`；`?token=` 仅 loopback 一次性引导换 cookie；`Referrer-Policy: no-referrer`；日志脱敏。

### 5.3 先验红测试方向（Step 9 用）

| # | 先验红场景 | 修复后断言 |
|---|---|---|
| 3 | 仓库级直放 `gguf/<repo>/<f>.gguf` + 无 conf | 修复前 `repo not found`；修复后生成 conf 且 `MODEL_PATH` = 该文件 |
| 4 | 路径含空格 + `&` + `\|` | `source` 后逐字节一致；`rpc_check` 读取一致；conf 未被 `sed` 污染 |
| 7 | 未设 `PP_LISTEN` 起 ds4 PP | 修复前 cmdline 含 `0.0.0.0`；修复后含 `127.0.0.1`；显式传直连段 IP 时按传入值 |
| 10 | `/?token=<token>` | 修复前 `==` 比较、token 留在 URL；修复后 `compare_digest`、302 + `Set-Cookie`、响应/日志不含完整 token |

### 5.4 不在本批（P2）

`#5 set -euo 扫荡` · `#6 遗留 systemd 单元` · `#9 硬编码用户/主机名` · `#8 拆文件/分目录` · `CI 接入`。其中 #5 与 #4 共享「关键写操作显式检查」的纪律，可在 #4 落地时顺手建立**写操作检查模板**，但**不扩大 #4 的射程**。
