## 2. #8C：`agent-cli.ps1`（E1）

| 指标 | 实测 |
|---|---|
| 行数 | **7406** |
| `function` 定义 | **116** |
| 外部调用面 | `rpc.ps1`/`cluster.py` 的 `agent` 子命令、站上任务派发、`agent-cli-smoke.sh`、CI 的 `py-tests`（经夹具） |
| 直接解析该文件的夹具 | `_fm_golden_test.ps1`（3419 行，663 条断言）· `_probe_fallback.ps1`（~536 行，提取**全部** `FunctionDefinitionAst` 再覆盖 stub） |
| 测试引用 | 12 个测试文件 |
| `rpc_check` 引用 | 24 处（ps1-golden / 断言计数 / 路径常量） |
| 文档行号引用 | **63 处 `agent-cli.ps1:NNNN`** + **198 处 `agent-cli.ps1#LNNNN`** = **261 处**（分布：ADR / OPEN-ISSUES / 调研 / 手册 / spec） |
| 编码纪律 | 含非 ASCII 的 `.ps1` **必须** UTF-8 BOM（`syntax` 的 `ps1-bom` 子判据，E1） |

**拆分形态的硬约束**：

1. **入口可从 `%TEMP%` 运行**：`split` 子命令把自身 BOM 副本落到 TEMP；`$Script:REPO_ROOT` 走 `AGENT_CLI_REPO_ROOT` 兜底（O-161）。⇒ 被 dot-source 的 lib **不能**用 `$PSScriptRoot` 找彼此，**必须**用 `$Script:REPO_ROOT` 或由入口传入的绝对前缀。
2. **两个夹具按"单文件"AST 解析**：拆成多文件后，`$content` 必须改为**有序拼接**（入口 + lib 固定顺序）。`_probe_fallback.ps1` 的"stub 必须在提取之后"顺序不变量随之变成"拼接顺序 = 定义顺序"。
3. **PowerShell 函数在调用时解析**：lib 之间的**函数**互相引用不要求定义顺序；但**顶层赋值**（`$Script:ROUTE_TABLE = ...`）按加载顺序生效 ⇒ 入口只能 dot-source 后再 dispatch。
4. **261 处行号引用**：拆完即成为"指向错误行"的静默失效（`doclinks` 只判文件存在，不判锚点语义）。这是 #8C 的**主要成本**，不是代码量。

**可选的收益边界**（E4）：把 `scrubber 规则/纯函数`、`D7 三信封/判据`、`judge 表/路由表`、`frontmatter` 这几块抽出，约可减 **2000-2800 行**；主流程（task/review/workspace/accept）留在入口。**不建议**一次把 116 个函数全部搬走。

## 5. 结论与建议

1. **8B 先做**：纯 Python、有 65 个测试当网、门面可以做到"调用方零改动"；协议层（2285 行 / 高测试覆盖）是最安全的第一刀。
2. **8C 后做且收窄**：只抽"低行号引用、纯数据/纯函数"的块（scrub 规则、D7 判据、表），主流程留在入口；**261 处行号引用**需要一条明确政策（见 DESIGN），否则就是"搬家后静默误导"。
3. **两刀都沿用**：先锁行为 → 门面重导出 → 一刀一提交 → 搬家后复核所有"扫文本"门禁的计数与清单。

**未实测登记（E4）**：具体抽取顺序与行数、夹具拼接后的 AST 行为、TEMP 副本下 lib 解析路径 —— 需 Step 2/3 落地验证。
