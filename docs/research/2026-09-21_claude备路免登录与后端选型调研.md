# claude 备路「免登录 + 后端选型」调研（2026-09-21）

> **结论先行**
> 1. **`claude` CLI 可以完全不登录使用** —— 登录只服务于 **Anthropic 官方服务**；把 `ANTHROPIC_BASE_URL` 指向任意**兼容 Anthropic Messages API（`/v1/messages`）** 的端点即可。本项目 **A/B 站早就是这么跑的**（指向站内本地引擎），根本不涉"绕过地区限制"。
> 2. **控制台侧差的只有一处**：免登录要造的两个「门槛文件」**已经在本机存在**（`~/.claude.json` 的 `hasCompletedOnboarding=true`、`~/.claude/config.json` 的 `primaryApiKey="any"`），唯一缺的是 `~/.claude/settings.json` 里的 **`env.ANTHROPIC_BASE_URL`** ⇒ 缺它就回落 `api.anthropic.com` ⇒ 报 `Not logged in`。
> 3. **决策（用户裁定 2026-09-21）：后端 = OpenRouter 优先，工作站本地模型备选。** 本次**只落档、不实施**。
> 4. ⚠ **落地前必须解决的前置事实**：主控站本地跑 claude 的**完整工具型任务**会被 **Trae 沙箱拦**（见 [2026-09-14 调研 §8.5](2026-09-14_OpenRouter接入与agentic-harness门禁调研.md)）；**已实证的可用路径是经 SSH 在站上跑 claude** —— 这与"工作站本地模型备选"指向同一形态（**claude 备路改在站上执行**）。

---

## 1. 问题

D6 的 claude 备通道（`Invoke-Task-Claude`）实测失败，`agent-output.txt` = `Not logged in · Please run /login`。
根因不是"缺账号"，而是：**控制台 claude 没有任何 base URL ⇒ 默认打官方端点 ⇒ 官方端点需要登录**。

## 3. 免登录机制（社区 + 本项目双证）

**三件套**（社区通行做法，本项目 6.1/8.1 亦同）：
1. 跳过登录引导：`~/.claude.json` → `{"hasCompletedOnboarding": true}`
2. 伪造 key 门槛：`~/.claude/config.json` → `{"primaryApiKey": "<任意串>"}`
3. 指向兼容端点：`env.ANTHROPIC_BASE_URL`（+ `ANTHROPIC_AUTH_TOKEN`；**`ANTHROPIC_API_KEY` 须显式置空**，否则回落官方端点）

**端点硬要求**：必须实现 **Anthropic Messages API**（`/v1/messages`、流式、tool use）。仅 OpenAI 兼容（`/chat/completions`）**不能直接用**，需要转换层（cc-switch 的 `enableLocalProxy` 就是干这个的）。

**诚实的强度边界**：这是"旁路"（造门槛文件绕过登录引导），社区反馈新版仍可用，但**官方随时可能收紧** —— 无保证。

## 4. 后端选型（用户裁定：OpenRouter 优先 → 站上本地模型备选）

### 4.1 首选：OpenRouter
**既有基建（本节不重复造轮子）**：
- 主控已有加载器 `ops/station-bin/_env_openrouter.ps1`，且**已支持 `-ForClaude` 开关**一键注入三件套
- **B 站已端到端实证**：`claude -p "<task>" --model thinkingmachines/inkling:free` 真实创建并跑通 `fizzbuzz.py`（[2026-09-14 §8.4](2026-09-14_OpenRouter接入与agentic-harness门禁调研.md)）
- 密钥治理：`secrets/openrouter.key` + `cluster.py egress`（免费档 RPM20/日额度）+ `Invoke-JudgeHttp` 的令牌桶/退避

**必须记住的三条既有结论**：
1. **`:free` 档有 agentic-harness 门禁**：裸 API 403，而 **claude code 被识别为 harness ⇒ 可用**（这恰好是我们要走的形态）
2. **主控站 IPv6 到 openrouter.ai 被黑洞** ⇒ `.NET Invoke-RestMethod` 超时；`curl -4` / claude code 走 IPv4 正常
3. **`ANTHROPIC_API_KEY` 必须显式置空**，否则 claude 回落官方端点

### 4.2 备选：工作站本地模型
即"站上 claude + 站内引擎"（站上既有配置**开箱可用**，见 §2.2/§2.3）。
适合：OpenRouter 额度耗尽 / 网络不可达 / **卡是 `local-only` 不宜出网**时。

本次**不推翻** [2026-09-14 调研](2026-09-14_OpenRouter接入与agentic-harness门禁调研.md)，只补两块它没覆盖的：

## 5. ⚠ 关键约束与风险（实施前必须处理）

| # | 约束 | 说明 |
|---|---|---|
| R1 | **主控本地跑 claude 的完整任务被 Trae 沙箱拦**（[§8.5](2026-09-14_OpenRouter接入与agentic-harness门禁调研.md)） | 被拦路径：`~/.claude/sessions/*`、`session-env/*`、`plugins/*`、`telemetry/*`、`.claude.json.tmp.*`、`AppData\Local\claude-cli-nodejs\Cache\**`。**简单 `-p` 冒烟可过，带工具调用的完整任务被拦**。⇒ **`Invoke-Task-Claude` 现在"在控制台本地 spawn"的形态，与真正可用的路径（站上跑）不一致** —— 这是本调研最要紧的结论 |
| R2 | **数据边界 / local-only** | OpenRouter = **数据出网**。本项目卡**大量是 `local-only`**（Paper/Cpp_Hub/Auto_Prover）。**自动 fallback 若无敏感度闸，会把本地内容送出去** ⇒ 需按 `sensitivity` 设闸（用户裁定：**本次只落档**，实施时再定） |
| R3 | **额度** | OpenRouter 免费档 20 req/min + 日 50（未充值）/1000（曾充≥$10）；429 计入配额 ⇒ 备路是"救急"而非"常态替代" |
| R4 | **`unsloth.key` 每次加载重铸** | 站内产物型凭据 ⇒ 若控制台要直连站上引擎，`apiKeyHelper` 必须**动态取**（ssh 读）而非固化；这也是 `secrets pull` 存在的原因 |
| R5 | **cc-switch 会改写 `~/.claude/settings.json`** | 它的 localProxy 会注入 `ANTHROPIC_BASE_URL=http://127.0.0.1:<port>` + gateway token ⇒ **与 D6 手工写的 env 互斥/相互覆盖**；且门禁 `stations` 有"三站 settings.json 一致"判据，改动需同步认知 |
| R6 | **`:free` 模型的能力上限** | `inkling:free` 等是轻量模型，**tool use / 长任务质量未验**；作为"死锁兜底"够用，但不应期望等价于 opencode 主路 |

### 7.3 ⚠ 本次新增的**阻断级实测发现**：Claude 原生型号名 = 仍撞地区墙
| 型号 | 经 OpenRouter 的结果 |
|---|---|
| `claude-opus-4-7`（原顶层 `model`） | **403 `This model is not available in your region.`** |
| `claude-sonnet-4-5`（= ROUTE_TABLE 的 `claude` 别名） | **403 同上** |
| `claude-opus-4-1`（= ROUTE_TABLE 的 `claude-opus` 别名） | **403 同上** |
| `thinkingmachines/inkling:free` / `nvidia/nemotron-3-ultra-550b-a55b:free` | `OK` ✅ |

**含义（要紧）**：走 OpenRouter **并不能**用 Claude 原生型号名绕过地区限制 —— 那些 id 会被 OpenRouter 路由到**真实 Anthropic 上游** ⇒ 照样 403。**必须使用非 Anthropic 上游的模型**。
⇒ **对 D6 备路的直接后果**：`ROUTE_TABLE` 里 `claude`→`claude-sonnet-4-5`、`claude-opus`→`claude-opus-4-1` 两个入口，经 OpenRouter **都会 403**；自动 fallback 现在用的 `$fbModel='claude'` ⇒ **会 403**。**必须重映射到 OpenRouter 可服务的模型**（否则"备路免登录"只解决了认证、没解决可用性）。
