## 1. 执行摘要

1. **ds4 裁定 = 清模型、留引擎**（相对 ADR-0010 v1.2 的"引擎 + 模型均冷藏"**收窄一步**）。理由：① ADR 立项的核心动因「跑 llama.cpp 跑不了的架构」**已被吞并** —— `glm5next` 变体 + 双机 RPC 已跑通 **11.2–11.9 t/s**，而 ds4 单机 `--ssd-streaming` 只有 **0.41–0.44 t/s（慢 27×）**；② B 站磁盘最紧；③ 引擎本体仅 **302–399 MB**，保留成本≈0；④ ADR 原文即写明「**模型可重下**」。
2. **那份 190 GB GLM 的身份已确证**：`GLM-5.3-Flash-Q4_K.gguf` = **190,875,526,464 B（177.8 GiB）**，落在 B/C 两站的 `~/ds4/gguf/`，**两份共 355.6 GiB**。**只有 ds4 能读**（ds4 转换器专属张量命名，`kda_like=510`）；现役 llama.cpp 那份是 **UD-IQ4_XS 146.1 GiB**，**是另一份文件、不是同一个**。同源兄弟 `glm53-q2`（90 GB）**已被删过**。
3. **已于 2026-09-29 执行完毕**（见 §5）：ds4 专属量化在两站删除（**省 355.6 GiB**，B 612 G→790 G free · C 867 G→1.1 T free）；[ADR-0010](../../adr/ADR-0010-DwarfStar第二引擎引入立项.md) 升至 **v1.3**，处置改为「**引擎保留 / 专属量化清退（可重下）**」。

## 3. 清退方案（清模型、留引擎）

### 3.1 清退对象（精确，二处）

| 站 | 路径 | 体积 | 属主 | 删除方式 |
|---|---|---|---|---|
| B | `~/ds4/gguf/GLM-5.3-Flash-Q4_K.gguf` | 190,875,526,464 B | **root** | **需 `sudo`** |
| C | `~/ds4/gguf/GLM-5.3-Flash-Q4_K.gguf` | 190,875,526,464 B | `scott-lau` | 普通删除 |

**净收益 = 355.6 GiB**（B 612 G → ~790 G free；C 867 G → ~1.05 T free）。

### 3.2 明确保留（不删）

- `~/ds4/` 下的**引擎与工具链**（`ds4` / `ds4-server` / `gguf-tools` / `cuda` 等，302–399 MB）—— ADR-0010 的"引擎保留冷藏"不动；
- 全部**登记与入口**（`DS4_PP_MODELS` / `BACKENDS` / ports 9911 / `spec/ds4-backend/DESIGN.md`）—— 引擎还在，入口仍成立；模型重下即可复跑。

### 3.3 ⚠ 不可逆性（如实标注）

- 模型**理论上可重下**（ADR 原文），但**实测重下并不顺利**：`./download_model.sh glm53-q4` 曾因 **hf-mirror 不提供 Xet 端点** ⇒ huggingface_hub 回落常规 HTTP ⇒ 触发 **>50 GB 常规下载上限**而失败；最终靠 `lm-download@ds4-glm53-q4` + 分段并行 Range 才落地（见 [DwarfStar 前置核验](./2026-09-28_DwarfStar前置核验与ROCm工具链安装决策.md) §下载）。
- ⇒ **删除 = 高成本可逆，不是零成本可逆**。这是本方案唯一需要人为承担的风险，已如实写在此处。

### 3.4 门禁与回滚

- 门禁：`py ops/rpc_check.py --quick`（预期无红灯 —— `rpc_check` 零 ds4 断言；`ports.yaml` 9911 为纯登记）。
- 站上复核：`df -h`（期望 B/C 各 +178 G）· `ls ~/ds4/gguf/`（期望空）· `du -sh ~/ds4`（期望 302 M / 399 M）。
- 回滚路径：`lm-download@ds4-glm53-q4`（含分段并行加速），见 §3.3。
