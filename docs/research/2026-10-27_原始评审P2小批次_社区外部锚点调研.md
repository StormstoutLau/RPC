## 2. 外部锚点（E3）

| 主题 | 事实 | 来源 |
|---|---|---|
| systemd 段位 | `StartLimitIntervalSec=` / `StartLimitBurst=` 是 **`[Unit]`** 的键；`[Service]` 里写会被报 Unknown key 并忽略 | [systemd.unit(5) · Debian](https://manpages.debian.org/bullseye/systemd/systemd.unit.5.en.html) |
| systemd 重启限速语义 | `StartLimitIntervalSec=0` 关闭启动速率限制（默认取 `DefaultStartLimitIntervalSec`）；配合 `Restart=always` 才能"无限兜底" | [systemd.unit(5) · Debian](https://manpages.debian.org/bullseye/systemd/systemd.unit.5.en.html) |
| `User=` 取值 | 只接受**单一用户名或数字 UID**；系统服务默认 `root` | [systemd.exec(5) · Debian](https://manpages.debian.org/stretch/systemd/systemd.exec.5) |
| `%u` 说明符 | 是"运行 service manager 的用户"；系统管理器下解析为 `root`，**不受 `User=` 影响** | [systemd.unit(5) · freedesktop](https://www.freedesktop.org/software/systemd/man/latest/systemd.unit.html) |
| GitHub Actions 工作流文件 | 必须放在 `.github/workflows/`；`permissions:` 可最小化 `GITHUB_TOKEN` | [GitHub · Workflow syntax](https://docs.github.com/en/actions/writing-workflows/workflow-syntax-for-github-actions) |
| `setup-python` 推荐权限 | 官方 README 示例使用 `actions/checkout@v7` + `actions/setup-python@v7`，并建议 `permissions: contents: read` | [actions/setup-python](https://github.com/actions/setup-python) |
| Ubuntu runner 预装 | `ubuntu-24.04` 镜像预装 **ShellCheck 0.9.0**、Bash 5.2.21、Git 2.55、Python 3.12.3 | [runner-images · Ubuntu 24.04](https://github.com/actions/runner-images/blob/main/images/ubuntu/Ubuntu2404-Readme.md) |
| Windows runner | `windows-latest` / `windows-2022` 提供 Windows PowerShell 与 Git for Windows（Git Bash）；`setup-python` 可装 3.12 | [runner-images](https://github.com/actions/runner-images) · [setup-python](https://github.com/actions/setup-python) |
| ShellCheck 严重度 | `shellcheck --severity=error` 只在 error 级失败，warning/info/style 不阻断 | [ShellCheck](https://www.shellcheck.net/) |

**不可照搬**：

- 不要把 `%u` 当成"跟随部署用户"的解法 —— 对系统单元它恒为 `root`（E3），会直接把服务跑成 root。
- 不要用 GitHub Actions 的 `ludeeus/action-shellcheck@master` 作为唯一方案 —— 第三方 action 是供应链面；Ubuntu 24.04 已预装 ShellCheck，直接调用即可，少一个依赖。
- 不要在 CI 里 `ssh` 三站跑 `rpc_check` 全量 —— 公网 runner 无 LAN 可达性，也不应持有内网密钥。

### 3.1 #6：修正还是归档

**推荐甲**：与 `rpc-server@.service` 的既有修法同型（该文件已留注释说明"原写在 `[Service]` 无效"），改动最小、可机器判据。

### 3.2 #9：收敛到"每个执行域一份派生规则"

**核心判断**：不存在"一个文件让 bash / PowerShell / systemd 都读"的轻量方案：

- 站上 shell 与主控 Python 是**不同机器**，不能读同一份 `inventory/net.yaml`；
- systemd 单元**不能**做环境变量展开（§2），`User=` 必须落字面量或由安装步骤替换。

因此最小契约不是"消灭所有字面量"，而是：

| 执行域 | 单一派生规则 | 落点 |
|---|---|---|
| 主控 Python | `STATIONS` 是 host/user 唯一真值 | `cluster_const.STATIONS`；`cluster.py SERVICE_USER` 从它派生；面板 URL 用 LAN IP |
| 站上 bash | **服务用户 = `$(id -un)`**；家目录 = `$HOME`；站间地址 = 直连段 IP | `infer-load` / `infer-unload` / `infer-list` / `cluster-watchdog` |
| PowerShell（主控） | `REMOTE_USER` / workspace 根 = 单一常量块（可被环境变量覆盖） | `agent-cli.ps1` L41-43 |
| systemd 单元 | **部署身份**，不做运行时派生；换机时由安装者统一替换 | `ops/*.service` 的 `User=`/`Group=` |

**明确保留的字面量（写清理由）**：

- `STATIONS` 的 `user: "scott-lau"`：主控 Python 的唯一真值，不再散落。
- 单元 `User=`/`Group=`：systemd 语义所限（E3），且这是**部署身份**而非凭据；换机只需改 4 个文件的一处。
- `infer-list` 的 `SELF` 判定（`hostname -s` 映射 A/B/C）：这是**本站识别**，不是 SSH 身份；保留。
- `cluster-watchdog` 的 `PEER` 主机：A/B 部署差异，改为"部署时指定"（`PEER` 变量）而不写死 `.local`；是否改 IP 待 DESIGN。
- 冻结探针 / 历史文档：不碰。

**最小契约**：

1. 活跃 bash 脚本不再出现 `scott-lau@` 与 `.local`（`SELF` 的 hostname 映射除外，白名单）。
2. `infer-load` 的 `AWORK` 改为 `$(id -un)@10.10.10.1`（A-B 直连段，ADR-0006 已是 IP 寻址）；`/home/scott-lau/...` → `$HOME/...`；`RPC_USER` 缺省 `$(id -un)`。
3. `infer-list` 的 `NODE` 改为 `$(id -un)@<LAN IP>`；删除 `.local` 兜底（LAN 已静态，见 `net.yaml` L110-120）。
4. `infer-unload` 的 `$HOME` 与 `RPC_USER` 同上。
5. `cluster-watchdog` 的 `PEER_USER` 与 `chown` 改为 `$(id -un)` / `$(id -u):$(id -g)`；`PEER` 改为可配置变量（无 `.local` 默认）。
6. `cluster_const` 面板 URL 从 `.local` 改 LAN IP；`cluster.py SERVICE_USER` 从 `STATIONS` 派生。
7. `agent-cli.ps1` 的 `REMOTE_USER` / workspace 根集中为一块，允许 `RPC_REMOTE_USER` 覆盖；A/B 主机函数保留（拓扑映射）。
8. 判据：`tests/test_identity_literals.py` 扫"活跃运行时清单"（`inventory/ops.yaml` 的 `station_runtime` + `cluster*.py`），命中 `scott-lau@` / `.local` 即 FAIL；单元/文档/冻结探针白名单。

### 3.3 CI：两个 job，不做"全量门禁"

**最小工作流**：

```yaml
name: ci
on:
  push:
  pull_request:
permissions:
  contents: read
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true
jobs:
  py-tests:
    runs-on: windows-2022          # PowerShell 5.1 + Git Bash；与本地主控同构
    timeout-minutes: 30
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-python@v7
        with:
          python-version: '3.12'
      - run: pip install paramiko pyyaml
      - run: python tests/run_py_tests.py
  shellcheck:
    runs-on: ubuntu-24.04          # 镜像预装 shellcheck 0.9.0（E3）
    timeout-minutes: 10
    steps:
      - uses: actions/checkout@v7
      - name: ShellCheck（仅 error 级 + 活跃站上件）
        run: |
          shellcheck --version
          shellcheck --severity=error \
            ops/rpc-nodes \
            ops/station-bin/infer-load \
            ops/station-bin/infer-unload \
            ops/station-bin/infer-list \
            ops/station-bin/llama-serve-instance \
            ops/station-bin/rpc-serve-instance \
            ops/station-bin/cluster-ttl \
            ops/station-bin/load-gate \
            ops/station-bin/load-mem-gate \
            ops/station-bin/wait-gtt-release \
            ops/station-bin/model-locate.sh \
            ops/station-bin/conf-lib.sh \
            ops/station-bin/conf-get
```

**取舍**：

- `py-tests` 放 Windows：`test_rpc_check_ps1_golden` 需要 PowerShell；`test_conf_lib`/`test_model_locate` 需要 Git Bash。Ubuntu 上跑全套会因 PowerShell 路径/编码出现平台性失败，不能作为"代码回归"信号。
- `shellcheck` 放 Ubuntu：预装、零安装、零第三方 action；`--severity=error` 防"历史 warning 洪水"。
- **不跑** `rpc_check` 全量 / `gates` / `stations`：公网 runner 无三站 LAN；这些继续留在本地 pre-push。
- 首推后必须观察首次运行（E4：Windows runner 的 Git Bash 路径、`paramiko` 依赖、`test_rpc_check_ps1_golden` 的 PowerShell 可用性都需实跑确认）；失败按 §5 处置，不放宽判据。
