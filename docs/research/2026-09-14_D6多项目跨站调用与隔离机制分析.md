## 3. ⚠️ Cpp_Hub 适配不一致（调研发现）

### 3.1 双路径事实
- **`d:\RPC\spec\d6-agent-standard\Cpp_Hub`**：存在，但为 **gitlink 薄壳**，仅含 `scaffold/ src/ tests/ agent-out/ CMakeLists.txt README.md`（2026-09-12 Cpp_Hub-001 试点产物）。
  > **现状注记（2026-09-16）**：该 **gitlink 已被摘除并吸收为普通文件**（A1；`git rm --cached` 摘 160000 指针 → 删目录内 `.git` → `git add` 吸收 6 个实体文件；备份 `OneDrive\RPC-backup\20260916-Cpp_Hub-gitlink\`，含完整 `git bundle`）。⇒ 上文"薄壳"形态已不存在，现在它就是仓库内的一份**普通样本目录**（`agent-out/` 仍被忽略）。**但映射不一致问题仍在**：`$PROJECTS['Cpp_Hub']` 与 `cpphub-001` 卡的实际目标仍不一致（该卡已标 `status: retired`，登记于 OPEN-ISSUES `cpphub-001` 行）——故"需修复后才能安全调用"这一结论**仅对映射那一半仍然成立**。
- **`F:\Cpp_Hub`**：真实主项目，含 `benchmarks/ build_cuda/ build_m3hdr/ build_capi/ cpphub_src.tar.gz cpphub_sync.tar.gz` 等。

### 3.2 影响
1. **同步错误项目**：当前 `$PROJECTS['Cpp_Hub']` 指向 gitlink 薄壳，D6 派发时同步的是薄壳而非 `F:\Cpp_Hub` 真源 → 模型看不到真实代码。
2. **缺 `.agentsync`** → 回退 python 模板排除规则 → `build_*/`、`benchmarks/`、`*.tar.gz`、`*.obj` 等大目录/大文件全部打包 → 大概率**撞 200MB 传输上限**（G4），tar 直接失败。

### 3.3 修复结果（2026-09-14 已执行）
1. `$PROJECTS['Cpp_Hub']` → 改指 `F:\Cpp_Hub`（agent-cli.ps1 L43）
2. 新建 `F:\Cpp_Hub\.agentsync`（29 条规则：排除 build_*/benchmarks/*.tar.gz/*.obj/CMakeCache 等）
3. 验证：`Get-AgentsyncExcludes` 正确读取 29 规则；F:\Cpp_Hub 排除后 sync 包估算 **18.1 MB**（远低于 200MB 上限）；AST 0 错误 + BOM 保留 + 离线回归 9/9 零倒退
4. **结论**: Cpp_Hub 从"已注册但指向薄壳"变为"可安全调用真源"，三项目适配全部完成

## 4. 用户项目接入方法（标准 + 隔离三要素）

任一新项目接入 D6 = **3 步**：

1. **注册**：`$PROJECTS` 加一行 `MyProj = 'X:\路径'`
2. **配隔离**：项目根建 `.agentsync`（排除 build*/venv/大文件/`.git`）
3. **派发**：`agent-cli task MyProj --card <卡> --model <m> --RemoteHost <A|B|C>`

框架自动完成其余隔离：
- **工作区隔离**：站上每项目独享 `~/agent-workspaces/<proj>`
- **并发互斥**：flock 层2锁，写锁独占/读锁共享
- **防污染**：`.agentsync` 过滤 + 产出仅回传 `agent-out/`，**源文件不回写**
- **同站并行兜底**：`isolate-xdg: true` 隔离会话数据库

### 隔离四层（项目文件不污染的保障）
1. **工作区隔离** — 每项目独立站上目录
2. **传输排除** — `.agentsync` 过滤，防大文件/构建产物上传
3. **并发互斥** — flock，防写冲突
4. **会话数据隔离** — XDG_DATA_HOME，防同站并行 db 写锁
