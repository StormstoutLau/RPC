## 1. 目标与范围

- **目标**: 三站统一安装系统 ROCm **7.2.4**，补齐本地 HIP 构建/诊断能力，消除 `amdgpu-install` 版本漂移。
- **铁律**:
  - 不破坏 bundled 推理路径（`~/.unsloth/llama.cpp/build/bin/` + `/opt/llama.cpp`），现役推理必须零影响。
  - 系统 7.2.4 注册后**不得遮蔽** bundled 库（判定依据 = `$ORIGIN` 解析先于 `ldconfig`）。
  - 全程可逆：破坏性操作前备份 + size 校验。
- **非目标**: 整体迁移任何推理框架；不装 `amdgpu-dkms`；不受本次影响 vLLM/ray/LM Studio。

## 2. 关键决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | **版本 = 7.2.4**（= 仓库 latest） | 官方产品号 7.14.0 在 `repo.radeon.com/rocm/apt/` **不存在**；7.x 实测最高 = 7.2.4，`latest` 即 7.2.4；7.2 官方矩阵正式支持 gfx1151（Radeon 8060S / RDNA 3.5）。**方法论：版本号必须以 apt 仓库真实存在为准，pin 前须 `curl` 仓库根目录确认** |

## 3. 执行记录（B → A → C）

### 3.1 【B 站】试点（2026-09-17）
- **源修复**: 备份全部含 rocm/amdgpu 源 → amdgpu(6.3.3) 移 `.disabled`（仅 dkms，与 in-tree 冲突）→ rocm `.distUpgrade` 改名 `.list` → 单源 update 稳定收录。
- **安装**: `apt-get install rocm-hip-runtime`（dry-run 验证依赖纯用户态）。
- **结果**: `rocm-core 7.2.4.70204` / `hip-runtime-amd 7.2.53211` / `hsa-rocr 1.18.0`、gfx1151 枚举命中。
- **冒烟**: `infer-load gpt-oss-20b` → READY ✓ :8080 + `--device ROCm0`。

### 3.2 【A 站】清理 6.4.1 + 统一（2026-09-17）
- **假卸载实证**: `amdgpu-uninstall --rocmrelease=6.4.1` **软链到 amdgpu-install，是图形驱动卸载器**——只 purge 驱动包+源清理，**根本不卸载 ROCm 软件栈**；两次运行 END rc=0 但 55+ 个 rocm/hip/hsa 包全在、`/opt/rocm-6.4.1` 仍存。
  **教训: END rc=0 ≠ 卸载成功，判据必须核实包/目录状态。**
- **正确清理**: `apt-get purge` **63 个前端包**（rocm-core/hip-runtime/hsa-rocr/rocblas/comgr/miopen/rccl 等，涵盖 94 依赖），dry-run 确认无系统关键包误伤 → END rc=0 → `rm -rf /opt/rocm-6.4.1`。
- **收尾**: 残留 `amdgpu-install`/`amdgpu-core`/`libdrm-amdgpu*` 属图形驱动栈，保留。
- **统一**: 新建 `rocm.list` 指向 7.2.4 → `apt install rocm-hip-runtime` → 同 B（7.2.4.70204 + gfx1151）。
- **冒烟**: `infer-load gpt-oss-120b`（A 本地无 20b）→ READY ✓ :8080 + `--device ROCm0`，卸载回落。

### 3.3 【C 站】统一（2026-09-17）
- **源现状**: rocm/amdgpu/graphics 源全在 `backup-radeon-20260908/` **备份子目录（apt 不读取，未激活）**；keyring 在、7.2.4 仓库 200 可达。
- **统一**: **直接新建** `rocm.list` 指向 7.2.4（不动 backup 历史）→ `apt install rocm-hip-runtime` → 7.2.4.70204 + gfx1151。

## 7. 关键教训与方法论沉淀

1. **`rc=0` / 命令"完成" ≠ 成功**：`amdgpu-uninstall` END rc=0 却是假卸载。判据必须落到**状态核实**（包清单、目录、版本串），不只看退出码。
2. **版本号以仓库真实存在为准**：官方产品/release 号 ≠ apt 版本段。pin 前必须 `curl` 仓库根目录清单。
3. **"包在" / "安装成功"可能是假象**：apt 源破损时会**静默回落到旧源装旧版**；以版本断言收口。
4. **统一要"修源"为先**：B/C 源体制破损（`.distUpgrade` / backup 子目录未激活）是 root cause；源修对，安装才成立。
5. **runtime 即够**：`rocm-hip-runtime` 能跑 HIP 应用 + 枚举 gfx1151；`hipcc` 属 SDK，按需再装。控制 footprint。
6. **`$ORIGIN` 判据可 3 证互证**：预先 RUNPATH 探测 → 装后 ldd 遮蔽自证 → 门禁 backend 断言，三层独立证据闭环。
