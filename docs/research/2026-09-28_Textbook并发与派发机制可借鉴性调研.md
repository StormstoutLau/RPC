## 3. 可借鉴清单（按"移植价值 ÷ 成本"排序）

### ★★ 3.1 防"假并行"的后置判据（最值钱、成本最低）
- **它踩过的坑**（E2）：P1 脚本**声称 A/B 并行，实际全部只发 A 机**、B 完全闲置；根因 = **缺运行时可见性** + **预检只做 GET 未做 POST**。
- **它固化成的规则**（E2）：**规则 3.7** —— 前置 **GET + POST 双探**；后置断言 **每个端点 ≥1 次成功** + **失败率 < 50%**；修好后均衡度 **100%**。
- ★ **与本仓同族**：这就是本仓"**假绿四型**"里的「**判据什么都没判**」/「**看起来更硬其实没读到**」—— 一个**声称并行、实则单站**的派发器，与"门禁报 `0/0` 读成没问题"是同一个病。
- **移植建议**：给我们的跨站扇出加一条**同类后置断言**（**每站 ≥1 次成功** + 失败率上限），并纳入证据链/门禁。★ 我们已有站级计数与证据链基建，**成本低**。

### ★★ 3.2 动态工作窃取 > 静态分片 / 索引轮询
- **它的实测与推演**（E2）：静态分片下「快模型跑完就闲置，等慢模型独自完成剩余任务」⇒ `61+61+61+62` 中**总时间 = 最慢模型时间**；动态共享队列「谁空闲谁取」⇒ **总时间 ≈ 总量 ÷ 总吞吐**（快模型自动多干）。
- **它的实现**（E2）：`scripts/parallel_translate.py` `queue.Queue` + N 线程，**每个线程绑一个模型**，按"谁空闲谁取"；并有**类型路由**（`theorem` 只发给具备能力的模型，否则让出）。
- **另有一层**：A/B 端点用**奇偶索引轮询**（`endpoints[idx % 4]`），**不是负载均衡**。
- **移植建议**：本仓当前是"**跨站各 1 并发、按站指派**" ⇒ **1 并发/站时两者等价，现在不需要改**；但**若将来出现多模型/多站/多并发**（例如 EV-3 的 vLLM 双机），应采用**共享队列 + 空闲即取**，而非按索引分派。

### ★ 3.3 幂等 = "看产物存在"，以及"实时回传 > 站点状态依赖"
- **它的实现**（E2）：站点 runner `[ -f "$F" ] && { echo "skip batch $i (done)"; continue; }`（**产物存在即跳过**）；设计原则写为「**站点无状态化、任务分配幂等**」「**实时回传 > 站点状态依赖**」。
- ★ **与本仓的关系**（E1）：我们的 `O-22`（`.meta` 残留 ⇒ 二次 run 读到上次终态，误判"又超时"）与 `O-37`（`.progress` 读上一轮残留 ⇒ 假进度）**正是"站点状态依赖"的反面教材**。
- **移植建议**：评估把我们的 skip 判据从"**读 `.meta` 状态文件**"改为"**看产物存在 + 校验**"（或至少**双判**）。★ 与 `O-22`/`O-37` 同族，属"残留态"这一类。

### 3.4 常驻 / 持久化以消进程重启开销（**只借原则，不借形式**）
- **它的实测**（E2）：one-shot **6.7s/条**（726 条约 **77 min**）→ 持久化 REPL **0.045s/条**（**32.8s**）⇒ **148x**；实现 = `subprocess.Popen` 预加载 mathlib 一次 + `threading.Lock` 串行化 stdin/stdout，**3 worker 并行**。
- ⚠ **不能直接搬**：它的常驻对象是**验证器进程**（Lean REPL），而本仓「**零自加载**」禁的是**引擎自启 / 常驻 daemon**。★ **对象不同，禁令不可混谈**。
- **可迁移的是原则**：「**长任务里反复冷启动是最大隐性成本**」⇒ 对我们的意义是**保持引擎常驻**（现役已做到：`infer-load` 一次加载后常驻），**而不是新增常驻进程**。
- ⚠ 若将来要给 Lean4 / 工具类做常驻，**须先过 ADR**（与 EV-4「谁管生命周期」同族）。

### 3.5 DAG 调度器：失败优先 + **重试方法轮换**（观察）
- `scripts/atlas_eval/dag_scheduler.py`：状态机 `pending/in_progress/completed/failed/dead`；**失败任务优先**、attempt 少者优先；`max_retries=5`；★ **`retry_methods = [decompose, simplify, use_lemma, manual_review, change_model]`** —— **每次重试换一种方法**。
- **移植建议**：我们现在的重试是"**同方法重试**"⇒ **"重试方法轮换"值得借鉴**（避免同一失败原因反复撞墙）。⚠ 本项**降级为观察**（`O-110` 已占优先级，且此项需先有失败归因分类）。

### 3.6 错误文本归一化后再匹配（观察）
- `configs/fix_memory_rules.yaml`：把 `unknown identifier 'X'` 归一成 `unknown identifier '<ID>'` 再匹配历史修复记录。
- **移植建议**：**观察**（先核本仓有无对应物 —— **未核**）。其价值在"**按归一化签名问历史是否见过**"，与我们 FTA 的失败归因可能互补。

## 6. 追加调研：改用 agent CLI + 本地模型，能否提升准确率 / Lean 翻译效率 / 整体效率？（2026-09-28 追加）

> **触发**：用户问「`Textbook` 调的是 LM Studio **裸 API**；若改用工作站上的 **`opencode` / `claude code` 这类 agent CLI** 且**同样使用本地模型**，是否能提升 ① 准确率 ② Lean 翻译效率 ③ 整体效率？」
> ★★ **先说一个前提**：`Textbook` 的 `opencode` **接的是云端免费档**（`opencode/deepseek-v4-flash-free`），**不是本地模型** ⇒ **用户问的这个组合它没试过**；而这个组合**本仓天天在跑** ⇒ 本节证据**主要来自 `d:\RPC` 自身实测（E1）**，`Textbook` 侧只作口径参照。

### 6.1 ★★ 本仓**已有**分场景结论（直接命中，不是推测）

`ClaudeCode本地集群与子代理框架分析.md:108-117` 逐字：

| 任务类型 | 裸 API（`call_llm.py` 模式） | agent CLI（claudecode/opencode） | 判定 |
|---|---|---|---|
| 一次性问答/推理 | 直接生成，最快路径 | agent 外壳加系统提示 + 工具 schema 开销（**~2-4k token**），更慢 | **裸 API 胜** |
| **代码需编译测试迭代** | 生成后人工看错→改 prompt→重生成（旧档 4 模型通过率 **61.5–85.7%**，需多轮） | **agent 读编译错误自修复，一次任务多轮内部迭代** | ★ **agent 胜（本质增益）** |
| 长文档分析 | 单次调用即可（nemotron 96.5k needle 5/5） | 同质量，但 agent 可分块 + 工具辅助 | 持平（agent 略慢） |

**结论行 `:117` 逐字**：「"更高效"成立于 **agent 闭环价值**（编译-测试-修复迭代）与**本地模型零成本无限速**；**不成立于纯生成速度**（外壳有开销）。」

⇒ ★★ **Lean4 翻译恰好落在"代码需编译测试迭代"这一类**（`lake build` / REPL 验证）⇒ **机制上确有增益**：裸 API 只能"生成→人工看错→改 prompt→重生成"，agent 能"读编译错误→自修复"。
⇒ ★ **独立佐证**（第三方，E3）：`HARNESS-SAME-MODEL-BENCH-2026-09.md:23` —— 6 harness × **同一模型池**，最好 **76.2** / 最差 **52.4**，**23.8 分全部来自 harness**（与模型无关）。

**结论行 `:951` 逐字**：**"LM Studio 本地模型整体不如 Zen 远程模型"**（本地最高 **82.4%** vs 云端两次 **100%**）。

★★ **根因不是"agent"，是"本地模型的工具调用质量"**：
- **BS-2 本仓实测**：直连 gpt-oss-120b，**要求 3 个工具、单轮只返 1 个 `tool_call`**（`adr/ADR-0002…:62`、`spec/d6-agent-standard/BLINDSCAN-v2-orchestration.md:198`，wall 48.3s）⇒ 决策「**不押模型单轮多 `tool_call`**，押**编排层并发 HTTP**」（`ADR-0002:73`）
- 外部记录（E3）："**工具调用质量是真正瓶颈**：弱模型会 malform `tool_calls` 导致循环（有记录 **480B 级开源模型在 30K token 后出现工具调用幻觉回退**）"（`Agent生态升级…:1068`）
- ★ **死循环是新型失败模式**，且 **`opencode` 无内置循环检测/打断**，需人工监控（`SSH_OPENCODE_SETUP.md:872,901`）

### 6.3 ★★ "agent CLI" 不是一个东西：**同一 CLI 有两种模式**，结论相反

- ★ **A 站 `claude` 是"纯文本模式"**：`CLAUDE_CODE_DISABLE_TOOLS=1` —— "**3s 快速响应，但无工具调用能力**"（`三机推理集群使用手册.md:578`）
⇒ ★★ **无工具模式 = 裸 API + 更长的系统提示** ⇒ 与裸 API 比**只有开销、没有闭环增益**；**只有"有工具"模式才有增益**。
⇒ 因此"换 agent CLI"这个提法必须拆成两问：**① 换外壳（无工具）② 换闭环（有工具）** —— 结论完全不同。

### 6.4 ★★ 四条**本地环境特有**的代价（本仓实测，直接压"效率"）

| 代价 | 实测（逐字） | 对 Lean **批量**翻译的含义 |
|---|---|---|
| **系统提示冷 prefill** | **22.6k 系统提示 @ ~300 t/s ⇒ 首条消息 ~70-110s**（手册 `:495,:499-500`）· **33k 系统提示 ⇒ 首次调用 >25min 未完成被中断**（`:577`） | ★ `Textbook` 是 **229 / 720 条批量短任务** ⇒ **每条都吃这固定开销** ⇒ 摊销极差 |
| **无 prompt caching** | "本地后端**每轮重编码全部历史**，长会话延迟和成本上升；**30 秒/轮的体验底线要求约 15 tok/s 以上生成速度**"（`Agent生态升级…:1071`） | 大模型达不到该速率 ⇒ 每轮更慢 |
| **轮数上限 <50 轮** | `opencode` **O(N²) 退化**，50-80 轮起每步变慢（手册 `:502`）· `claude` 需 60-70% 时手动 `/compact`（`:508`） | 复杂定理的多轮迭代会撞上限 |
| 计量与超时 | **无头 run 不吐 usage**（`:404` ⇒ **无法算 token 成本**）· **无默认总超时**（`:556` ⇒ "无反馈挂起"） | ★ 与"**可审计 / 证据链**"要求冲突 |

### 6.5 ★★ 反过来看 `Textbook`：它的"闭环"**已经用外层管线拿到了**

- 它**不靠 agent CLI 就实现了闭环**：**远端 REPL 自验**把复验通过率从 **61.3%（84/137）→ 100%（53/53）**（`2026-08-20-greene-lean4-implementation.md:127-133`）
- 它的**修（fix）**是外层循环（`lean4_verification_loop.py`）；**翻译**是 work-stealing 队列 + **裸 API**
- ⇒ ★★ **判断：换 agent CLI = 把"外层已实现的循环"搬进模型内部** ⇒ **省编排、但把固定上下文开销搬进每一步**
  - 对**批量短任务**（它的主形态）⇒ **净效率大概率为负**
  - 对**少量长任务**（复杂定理 / 多文件工程）⇒ agent 更优

### 6.6 三条判定（直接回答三问）

| 问 | 判定 | 关键条件 / 依据 |
|---|---|---|
| **① 准确率** | ★ **能提升，但仅"有工具"模式，且取决于本地模型的 tool-calling 质量** | 机制 = **内化验证闭环**（读库 / 编译 / 自修复）⇒ 直接治 Lean 的高频失败（`Textbook` 记有"**LLM 幻觉了不存在的 Mathlib API**"、gpt-oss-120b **49% 幻觉率**）。⚠ **本地模型这条路本仓实测 0%–82.4%，云端 100%** ⇒ **换 agent CLI ≠ 白拿准确率**；★ 且它用**外层 REPL** 已拿到 61.3%→100% |
| **② Lean 翻译效率** | ⚠ **大概率下降**（吞吐 / 单任务时长），**除非模型够大且任务粒度够大** | **33k 系统提示 × 批量短任务 + 无 prompt caching + 每轮重编码**；`Textbook` 的 229/720 条形态**正是最吃亏的** |
| **③ 整体效率** | ★ **取决于"人工介入"占比**，不取决于生成速度 | 本仓结论行：**"更高效"成立于 agent 闭环价值 + 本地零成本无限速；不成立于纯生成速度**（外壳有开销） |
