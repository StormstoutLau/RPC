## 3. 可借鉴清单（按"移植价值 ÷ 成本"排序）

### ★★ 3.1 防"假并行"的后置判据（最值钱、成本最低）
- **它踩过的坑**（E2）：P1 脚本**声称 A/B 并行，实际全部只发 A 机**、B 完全闲置；根因 = **缺运行时可见性** + **预检只做 GET 未做 POST**。
- **它固化成的规则**（E2）：**规则 3.7** —— 前置 **GET + POST 双探**；后置断言 **每个端点 ≥1 次成功** + **失败率 < 50%**；修好后均衡度 **100%**。
- ★ **与本仓同族**：这就是本仓"**假绿四型**"里的「**判据什么都没判**」/「**看起来更硬其实没读到**」—— 一个**声称并行、实则单站**的派发器，与"门禁报 `0/0` 读成没问题"是同一个病。
- **移植建议**：给我们的跨站扇出加一条**同类后置断言**（**每站 ≥1 次成功** + 失败率上限），并纳入证据链/门禁。★ 我们已有站级计数与证据链基建，**成本低**。

### ★★ 3.2 动态工作窃取 > 静态分片 / 索引轮询
- **它的实测与推演**（E2）：静态分片下「快模型跑完就闲置，等慢模型独自完成剩余任务」⇒ `61+61+61+62` 中**总时间 = 最慢模型时间**；动态共享队列「谁空闲谁取」⇒ **总时间 ≈ 总量 ÷ 总吞吐**（快模型自动多干）。
- **它的实现**（E2）：`scripts/parallel_translate.py` `queue.Queue` + N 线程，**每个线程绑一个模型**，按"谁空闲谁取"；并有**类型路由**（`theorem` 只发给具备能力的模型，否则让出）。
- **另有一层**：A/B 端点用**奇偶索引轮询**（`endpoints[idx % 4]`），**不是负载均衡**。
- **移植建议**：本仓当前是"**跨站各 1 并发、按站指派**" ⇒ **1 并发/站时两者等价，现在不需要改**；但**若将来出现多模型/多站/多并发**（例如 EV-3 的 vLLM 双机），应采用**共享队列 + 空闲即取**，而非按索引分派。

### ★ 3.3 幂等 = "看产物存在"，以及"实时回传 > 站点状态依赖"
- **它的实现**（E2）：站点 runner `[ -f "$F" ] && { echo "skip batch $i (done)"; continue; }`（**产物存在即跳过**）；设计原则写为「**站点无状态化、任务分配幂等**」「**实时回传 > 站点状态依赖**」。
- ★ **与本仓的关系**（E1）：我们的 `O-22`（`.meta` 残留 ⇒ 二次 run 读到上次终态，误判"又超时"）与 `O-37`（`.progress` 读上一轮残留 ⇒ 假进度）**正是"站点状态依赖"的反面教材**。
- **移植建议**：评估把我们的 skip 判据从"**读 `.meta` 状态文件**"改为"**看产物存在 + 校验**"（或至少**双判**）。★ 与 `O-22`/`O-37` 同族，属"残留态"这一类。

### 3.4 常驻 / 持久化以消进程重启开销（**只借原则，不借形式**）
- **它的实测**（E2）：one-shot **6.7s/条**（726 条约 **77 min**）→ 持久化 REPL **0.045s/条**（**32.8s**）⇒ **148x**；实现 = `subprocess.Popen` 预加载 mathlib 一次 + `threading.Lock` 串行化 stdin/stdout，**3 worker 并行**。
- ⚠ **不能直接搬**：它的常驻对象是**验证器进程**（Lean REPL），而本仓「**零自加载**」禁的是**引擎自启 / 常驻 daemon**。★ **对象不同，禁令不可混谈**。
- **可迁移的是原则**：「**长任务里反复冷启动是最大隐性成本**」⇒ 对我们的意义是**保持引擎常驻**（现役已做到：`infer-load` 一次加载后常驻），**而不是新增常驻进程**。
- ⚠ 若将来要给 Lean4 / 工具类做常驻，**须先过 ADR**（与 EV-4「谁管生命周期」同族）。

### 3.5 DAG 调度器：失败优先 + **重试方法轮换**（观察）
- `scripts/atlas_eval/dag_scheduler.py`：状态机 `pending/in_progress/completed/failed/dead`；**失败任务优先**、attempt 少者优先；`max_retries=5`；★ **`retry_methods = [decompose, simplify, use_lemma, manual_review, change_model]`** —— **每次重试换一种方法**。
- **移植建议**：我们现在的重试是"**同方法重试**"⇒ **"重试方法轮换"值得借鉴**（避免同一失败原因反复撞墙）。⚠ 本项**降级为观察**（`O-110` 已占优先级，且此项需先有失败归因分类）。

### 3.6 错误文本归一化后再匹配（观察）
- `configs/fix_memory_rules.yaml`：把 `unknown identifier 'X'` 归一成 `unknown identifier '<ID>'` 再匹配历史修复记录。
- **移植建议**：**观察**（先核本仓有无对应物 —— **未核**）。其价值在"**按归一化签名问历史是否见过**"，与我们 FTA 的失败归因可能互补。
