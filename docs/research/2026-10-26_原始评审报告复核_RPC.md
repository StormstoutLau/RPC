**原文摘要（问题四类）**：归档脚本里有明文凭据；SSH 层不校验主机密钥；部署脚本基本不开 `set -e`、配置写入不加引号；控制面和门禁集中在几个 5k–10k 行的大文件里。805 个提交集中在约 50 天内，迭代很密，`ops/station-bin/` 里正式部署件和一次性探针混放。

### 1.2 十条发现（原文）

| # | 严重度 | 发现 | 原文要点 |
|---|---|---|---|
| 1 | **CRITICAL** | 归档脚本含明文账户凭据，且已进入 git 历史 | `archive/root-scripts/b5o_add_alerts.sh:6` 明文账号（邮箱）+密码；`b5o_list_alerts.sh:4-5` USER/PASS 为字面量；均在公开仓库且存在于多个历史提交（如 `fb15a7c` 的 git mv） |
| 2 | HIGH | SSH 控制面不校验主机密钥（`AutoAddPolicy`） | `ops/cluster_ssh.py:62` 用 `AutoAddPolicy()` 且未 `load_system_host_keys()`；同 LAN ARP 欺骗/冒充站 IP 可让主控把 load/unload/sudo 命令发给冒充主机；这是唯一建连入口 |
| 3 | HIGH | `infer-load` 首次生成 conf 仍按 depth-2 找仓库 | 别名解析（`:67-69`）已支持 `gguf/<repo>/<file>.gguf`（NF==2），但 conf 生成（`:112-114`）仍 `find -mindepth 2 -maxdepth 2 -type d`；新下载模型直放仓库级时，别名能解析、随后报 `ERROR: repo not found` |
| 4 | MEDIUM | 生成/修改 conf 时值不加引号、`sed` 不转义 | `infer-load:133-141` heredoc 写 `MODEL_PATH=${F}` 未加引号；`:151` 与 `llama-serve-instance:10` 都会 `source`；路径含空格时 `MODEL_PATH` 只拿到前半段，后半段被当命令执行；`:168` `sed` 未转义 |
| 5 | MEDIUM | 部署脚本普遍不开 `set -e`，关键写操作失败后继续 | 不含 archive 的 192 个 `.sh` 仅 15 个启用 `set -e`；站上主执行件（`infer-load:15` 是 `set -uo pipefail`，`llama-serve-instance`/`rpc-serve-instance`/`cluster-ttl` 是 `set -u`）都没开；`sudo tee "$CONF"` 失败仍打印「conf 生成」并 `source` 不存在的文件 |
| 6 | MEDIUM | 遗留 systemd 单元把 `StartLimitIntervalSec` 写在 `[Service]` | `ops/rpc-server.service:15`、`ops/llama-server.service:16` 均写错 section；systemd 报 Unknown key 并忽略；worker 连续崩溃 5 次后进入 failed，`Restart=always` 的兜底失效 |
| 7 | MEDIUM | ds4 coordinator 默认监听全部网卡 | `infer-load:348-350` 为 `--listen "${PP_LISTEN:-0.0.0.0}"`；`_davidau_start.sh:8` 也是 `--host 0.0.0.0`（README 称有意保留）；不设 `PP_LISTEN` 时 coordinator 开放在 LAN 所有接口，若协议无认证则可被同网段直接调用 |
| 8 | MEDIUM | 核心文件过大，`station-bin` 正式件与一次性探针混放 | `rpc_check.py` 10032 行、`agent-cli.ps1` 7071 行、`cluster.py` 5818 行，均远超 800 行上限；`station-bin` 214 个文件，大量 `_probe_*`/`_tmp_*`/`_qwen27_*` 与部署件同目录 |
| 9 | LOW | 运维用户名和主机名硬编码在多处 | `infer-load:16` 的 `AWORK` 写死 `user@host.local`；`cluster-watchdog:18,21` 的 `chown` 写死；`ops/*.service` 的 `User=/Group=` 写死；公开仓库暴露用户名/内网主机名，换机器要改多处 |
| 10 | LOW | Web UI token 用普通字符串比较，且放在 URL query | `cluster_web.py:400` 用 `==` 比较 `X-Auth-Token`；`:1428` 免输链接把 token 放 `?token=`；默认只绑本机风险低，`--host 0.0.0.0` 时会经浏览器历史/Referer/日志泄露 |

### 1.3 七条建议（原文）

1. 立即轮换 `archive/root-scripts/b5o_*.sh` 涉及的账户密码，清理 git 历史，并把 `archive/` 纳入 `secrets` 门禁。
2. `cluster_ssh._connect` 改为 `RejectPolicy` 加固定的 `known_hosts`。
3. 站上 bash 统一 `set -euo pipefail`，conf 写入用 `%q` 或引号，`sed` 改成安全替换。
4. 把 `infer-load`/`infer-list` 的模型定位逻辑合并成一份共享实现，补 depth-1 用例。
5. 拆分 `rpc_check.py`、`cluster.py`、`agent-cli.ps1`；`station-bin` 分开 `deploy` 和 `probes`。
6. 修正或归档两个遗留 systemd 单元，所有监听地址默认取直连段或回环。
7. 增加 CI（GitHub Actions）运行 `tests/run_py_tests.py` 和 `shellcheck`，不要只依赖本地 hook。
