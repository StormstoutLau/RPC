- **[写动作，需授权] 快照 + 追加**：

  ⚠ `--engine` 会往 conf **写** `LLAMA_SERVER_BIN` / `LLAMA_RPC_SERVER_BIN` ⇒ **必须靠快照一并还原**，否则留下引擎钉死。

## 9. 执行结果与失败分析（2026-10-11，E1 本会话实测）—— No-Go

> 本方案于 2026-10-11 执行完毕。结论 **No-Go**；按 §S7b 完成**生产零影响回退**。
> 证据落点： [metrics-log §PR #26610 形态验证执行结论](../spec/rpc-optimization/metrics-log.md)；台账 [TRACKER §1.5 EV-12](../spec/upstream-tracker/TRACKER.md)。

### 9.1 结论一句话

`-sm tensor` 在**加载期**（warmup decode）即触发 **worker 侧 `ggml_vk_build_graph` SIGSEGV**，head 因 worker 断连 ABRT ⇒ **服务从未起来**
（T3/T8 FAIL，余条不可执行）⇒ 全条制 **No-Go**。

### 9.2 失败因果链（逐环有证）

| # | 环节 | 证据（原始） |
|---|---|---|
| 1 | **worker SEGV（主因）** | A 站（worker `10.10.10.1`，host `scott-lau-NEX`）的 `ggml-rpc-server` **SIGSEGV**（`Signal: 11`）。apport `/var/crash/…ggml-rpc-server.1000.crash` 核心栈：<br>`ggml_vk_build_graph` ← `ggml_backend_vk_graph_compute` ← `rpc_server::graph_compute` ← `rpc_serve_client` ← `ggml_backend_rpc_start_server`（均 `libggml-vulkan.so.0` / `libggml-rpc.so.0`）。故障指令 `mov 0x60(%rax),%rax`（坏指针解引用）@ `ggml_vk_build_graph+2684` |
| 2 | **head 读张量收 EOF** | B 站 `llama-server`：`recv failed (bytes_recv=0, size_to_recv=8)` |
| 3 | **head 抛异常 → ABRT（次因/放大）** | `ggml-rpc.cpp:651: Remote RPC server crashed or returned malformed response` → 该 `std::runtime_error` 抛于 warmup decode（`common_init_from_params`）**无 handler** ⇒ `std::terminate` ⇒ `status=6/ABRT` |
| 4 | **确定性重启环** | worker SEGV 记 **16:12:57** 与 **16:19:47**（两轮）；head `restart counter is at 1/2`；`infer-load` 15min 健康超时（16:23:22） |

- **时序对齐**：head 起 16:07:29，`+5:25.9` = **16:12:54.9** 进入崩点；worker SEGV 记 16:12:57.3（core 落盘滞后数秒）⇒ **worker 先崩、head 后 ABRT**（非反向）。
- **说明**：`common_fit_params: llama_params_fit is not implemented for SPLIT_MODE_TENSOR, abort` 是 **W 级告警**（异常被 catch），**非崩溃原因**；
  其含义是 **tensor 模式下自动内存 fit 被跳过** ⇒ 少一道配置校验（盲点，非致命）。

### 9.3 归因（是"哪个 bug"，不是"哪个配置"）

- 崩溃发生在 **Vulkan 后端图构建**（`ggml_vk_build_graph`），且是 **worker 处理 RPC 下发的 `GRAPH_COMPUTE`** 时 ⇒
  属 **`-sm tensor`（张量切分）在 RPC/Vulkan worker 侧的缺陷**，**非** RPC 传输/协议本身（协议 `v8.0.0` 正常握手、worker 正常受理）。
- **次因是健壮性缺口**：head 对 worker 断连**不优雅退出**，而是未捕获异常 → core-dump。与仍在跟踪的上游 **#26724（"rpc 崩溃不 abort"，崩溃传导修复）** 同族 —— "worker 一崩、head 陪葬"。

### 9.4 边界与未分离项（如实）

- 本方案按 §4.1 **只测了不等分 `--tensor-split 3,1`**（对齐 #29501 的"不等分"触发条件）⇒ **无法分离**
  「**不等分特有问题**（#29501 族）」与「**`-sm tensor` + RPC/Vulkan 通面缺陷**」。**等分（N=2 → `1,1`）未测**。
- 但**两种解释对本集群都是 No-Go**：三机/多设备下"层/头数被整除"非常态，**不等分是常态**。
- 与 #30075 的关系：我们命中**加载期**崩溃，**比 #30075（2–3 次请求后退化）更早/更重**；#30075 的运行时退化本次**未触及**（服务从未起来）。是否同根，待上游确认。
