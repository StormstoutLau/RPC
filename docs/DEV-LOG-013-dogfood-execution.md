### 8.1 P0-3 的验证跑**顺带**跑出 A2 的卡面缺陷（如实记录）

- **A2 首跑结果**：`TASK_RC=9`（验收失败）· `RUN_S=28` · `OUT_BYTES=665`。
- **根因（一手，模型 stdout）**：`permission requested: external_directory (/home/scott-lau/scripts/*); auto-rejecting`
  ⇒ **站上 agent 只能读自己的工作区**，工作区外**一律 auto-reject** = **O-30 第一条的第二实例**。
- ⇒ **A2 卡（"遍历站上 `~/scripts/` 逐个 sha256"）在设计上就不可执行** —— 这是我的卡面错误（O-30 早已记录该约束，我未应用）。
- **处置（已落地）**：
  ① **卡区 README 新增纪律 7**："**卡的射程 = 平台注册的工作区根**"；
     ★ **边界是白名单、不是"工作区内外"** —— A1 的 `ls -1 ~/agent-workspaces`（工作区**外**的父目录）**成功**，
     而 A2 的 `cd ~/scripts` 被拒 ⇒ **我第一版写成"射程 = 工作区"又过宽，当场修正**（第 3 次"由一次观测推规则"的教训）；
     工作区根之外的取证**改由主控 ssh 直接做**；
  ② **O-30 详情节补第二实例 + 入册纪律**（并写明代价：据它写的卡首跑即废；白名单确切内容未定，站上无显式 `permission` 配置）；
  ③ **A2 状态标 ❌ 设计错误待改**（候选：改为只取证工作区根内 / 或该取证改由主控 ssh 执行、只把结果当输入）。
- **元意义**：**验证跑与业务跑合一** —— P0-3 为验一个一行修复而跑的卡，**同时**暴露了一张卡的设计缺陷。
  ⇒ 支持"**小步实跑**"优于"批量派发后统一收"。
