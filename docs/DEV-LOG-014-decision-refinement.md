## 3. D2 —— O-41 拆登记 vs 并入 D6-P1-1

### 3.1 一手事实

- **O-41** = 两条**性质不同**的疑似假绿：① `doclinks` 对绝对路径/盘符/URL/占位词**一律"不可判"跳过**（可写不存在路径而不报错）② `engine` 残留阈值 **2048MB 硬编码**（1.5GB 无监听残留被判正常）。
- ⚠ **O-41 来自模型产出**（B2 审计 `out/falsegreen.md`），台账已标"待复核"。

### 3.2 选项对比

| 选项 | 成本 | 收益 | 长期可维护性 |
|---|---|---|---|
| **A** 拆 O-41a/O-41b **独立登记** | 低（+2 行台账） | 每条**独立关闭判据** ⇒ 可机判、可追 | **最好** |
| **B** 不拆，聚合处理 | 低 | 聚合；但两条**病根与修法都不同**（范围收窄 vs 阈值可配）⇒ 互相拖 | 中 |
| **C** 只登记不加固 | 最低 | 最小动作 | 差：违反"宁可留白不可留误导" |

### 3.3 裁定

> **✅ 选 A（拆分登记）**，但**顺序必须是「先复核 → 再登记 → 加固另归批」**：
> 1. **先复核**（本仓纪律「判据必须先做数据侦察再写码」）—— 确认 `doclinks` 究竟判不判绝对路径、`engine` 阈值是否真硬编码；
>    **不凭模型报告直接登**（B2 质量高但仍是产出物）；
> 2. 复核成立 ⇒ 拆 O-41a/O-41b，各带关闭判据；
> 3. **加固**归入 **D6-P0-1 门禁自审批**（与 B2 其余发现同批），不单独开批。

> **★ 复核结果（2026-09-24，读码实证）—— 改变了"拆两条"的预设**：
> - **① `doclinks`：不成立**。`_doclink_bad`（[`rpc_check.py:680-702`](../ops/rpc_check.py#L680-L702)）**刻意**只判"仓库内相对链接"；
>   绝对路径/盘符/URL 属**射程外**（不可判），且**不可判数已报数**（输出行"…895 条不判"）⇒ 是**射程声明**、非假绿。
>   ⇒ **定性为「已知局限」并关闭**（加固会撞既有纪律「判不准的不进门禁」），**仅留痕**防再被当"新假绿"报一次。
> - **② `engine`：成立**。`RESIDUAL_RSS_MB = 2048`（[:2208](../ops/rpc_check.py#L2208)）⇒ `rss < 2048` 且无端口落 `else` ⇒ 判"正常"；
>   1.5GB 残留进程**字面**被放过 ⇒ **真缺口**，保留待加固（归 D6-P0-1），已写关闭判据。
> - ⇒ **实际落地：未拆两条**（① 非缺陷无需新号；② 在原 O-41 内保留）—— **这正是"先复核"的价值**：
>   若照预设计划直接拆，会**凭空造一条不存在的缺陷**。

## 4. D3 —— P2-3 给 A/C 增出网档别名

### 4.1 一手事实（★ 推翻路线总表 §13.9 的"须裁定"的顾虑强度）

- 现状：`lightning`/`ultra`/`free-1m` 全 `station='B'`（[agent-cli.ps1 ROUTE_TABLE](../ops/station-bin/agent-cli.ps1#L83-L85)）。

- 注释纪律"**本表只镜像、不新立模型清单**" = **禁新立 *模型***；`ultra-a` 用**同一 openrouter id** ⇒ **不构成违反**。
- 它是 **O-20 / O-28 RC①**（`-HostName` 对 task 无效 ⇒ 无法指定站）的**正解**。

### 4.2 选项对比

| 选项 | 成本 | 收益 | 长期可维护性 |

| **A** 加 `ultra-a/-c`(+`lightning-a/-c`) | **中**：改运行时，须门禁+正反用例 | 解锁**跨站并行**（O-18 安全区）；**修掉 O-20** | **最好**：与 `m27-q4ks-a/-b` 同构；代价=维护面 3 站×档位 |
| **B** 不加、维持串行 | 0 | 串行不阻塞任何事 | 最差：O-20 悬空，每次吃狗粮要绕 |
| **C** 用 `cli: claude` 主控备路并行 | 0（不改运行时） | 可并行 | 中下：靠"另一种执行器"打补丁 ⇒ 长期两套行为差异的隐性债 |

### 4.3 裁定

> **✅ 选 A，分三步**：① **前提核查先做**（三站 `opencode` 版本 + `openrouter` provider/key 同构；内存记载账户=主控+A 合并 / B / C ⇒ A、C 有通道，但**须实测确认**）；
> ② 只加**一档**（`ultra-a`/`ultra-c`）验证，命名沿用 `-<站>` 后缀；
> ③ **必配正反注入**：正例=同 proj 两站并行不撞锁；反例=同站两卡仍 `LOCK_HELD`。
> ⚠ 排序张力：按"③改运行时"应**最后**；但**若要近期做跨站任务（批 C / D7 预演），它升为前置**。

⇒ 豁免**失效后不会被告知** ⇒ 清单长期腐化（该删的没人删）。这与"**登记这个动作本身要在 review 里可见**"（ADR-0004 D2）相悖。

### 20.2 落地

- 纯函数 **`allow_unhit(allow_keys, hit_keys)`**（**唯一实现**）；
- 接入两处消费者：明细**逐条点名**"该豁免已可移除"；`note` 追加"⚠ 豁免未命中 N 条"；判据 PASS → **WARN（不阻断）**；
- 两处 `fix` 都写明"**把它从 …_ALLOW 删掉**"（黄灯必须能照做）。

### 20.3 ★ 关键性质：按 **set** 去重（否则误报）

doclinks 的真实形态是 **`已登记例外 2` 而清单只有 1 条** —— 同一 md 里**两条链接指向同一失效目标**。
⇒ 命中集合必须按 **set** 去重；否则会把"命中 2 次"误算成"1 命中 + 1 未命中" ⇒ **天天假黄灯**。
（离线护栏专门钉住：`allow_unhit({("m","t")}, {("m","t"),("m","t")}) == []`。）

### 20.4 先验红（真实门禁）

两处各加一条**假豁免**（一个不存在的 md 路径 / 一条并未失效的链接目标）⇒
`secrets` 与 `doclinks` **双 WARN**、明细逐条点名、并给出删改指引；结论 **PASS · 绿灯 0 / 黄灯 2 / 红灯 0**（**不阻断** ✓）。
还原 ⇒ 恢复 **PASS · 绿灯 14 / 黄灯 1 / 红灯 0**（黄灯 1 = 既有 evidence，与本项无关）。

### 20.5 净方法论收益

- **★ "豁免"必须有出口**：只登记"允许什么"、没有"何时不再需要"的自报 ⇒ 清单**只增不减**，久而久之没人敢动。
  （与 O-51"真值表建了没人读"、O-50"第二份枚举没人删"**同族**：**登记无出口 ⇒ 腐化**。）
- **自报用 WARN 不用 FAIL**：豁免多留一条**不是缺陷**，但**必须被看见**；用 FAIL 会逼人为了过门禁而乱删。
- **去重语义是判据的一部分**：同一个"命中"事件可能发生多次 ⇒ **必须按集合而非计数比较**，否则判据自己制造噪声。

## 21. D6-P2-1：cluster 模块依赖方向检查（**AST 分两类 import**）（2026-09-25）

> **来源**：Scott 指令"好的，执行吧"。依据计划 §3 P2-1。
> （**P2-2 排后**：它自己写着"既有 8 份 ADR 的处置"是 **§5 唯一仍需裁定的一条** ⇒ 需用户拍板。）

### 21.1 现状（实测）

`ops/cluster*.py` 共 7 个模块；拆出 5 个后 **"谁能 import 谁"零约束**：

| 层 | 模块 | 依赖 |
|---|---|---|
| L0 | `cluster_const` | — |
| L1 | `cluster_ssh` | const |
| L2 | `cluster_model` / `cluster_secrets` | ssh（+ const） |
| L3 | `cluster_egress` | const / ssh / secrets |
| L4 | `cluster` | 全部下层 |
| L5 | `cluster_web` | cluster |

### 21.2 ★ 核心：必须用 **AST** 分两类 import

实测到**一对顶层双向**：`cluster_web.py:34 import cluster`（**模块级**），而 `cluster.py:4801 import cluster_web`
在 `cmd_web` **函数体内**（懒加载）。**正则分不清"这行在不在函数里"** ⇒ 会把两类混成一个桶（本仓头号失败形态）。
两者**语义不同**：
- **模块级** = **导入期**依赖 ⇒ 有环 ⇒ `import` 当场就炸 ⇒ **真环，FAIL**；
- **函数内懒加载** = **运行期**耦合 ⇒ **不构成导入环**（它正是**刻意打破环**的手段）⇒ 只有**反向**才须登记。

⇒ `cluster_dep_edges()` 用 `ast` 分别收集（`_collect_imports` 遇 `FunctionDef/AsyncFunctionDef` 即停）。

### 21.3 四条规则

1. **新模块必须在 `cluster_layers` 登记层次**（否则 FAIL）—— 不然依赖方向又回到零约束；
2. **模块级图不得成环**（DFS 三色，报**每条环的完整链路**）；
3. **模块级边只能指向严格下层**（反向 / 同层 ⇒ FAIL）；
4. **反向懒加载须登记**（`cluster_lazy_allow`）；登记**未命中会自报"已可移除"**（复用 P0-2 的 `allow_unhit`）。

### 21.4 先验红（计划指定场景）

给 `cluster_const.py` 加 `import cluster_egress` ⇒ **FAIL**，报 **3 条环**（`const→egress→const`、
`const→egress→secrets→const`、`const→egress→secrets→ssh→const`）+ **1 条层序越界** `cluster_const(L0) → cluster_egress(L3)`；
还原 ⇒ **PASS**（7 模块 · 6 层 · 13 模块级边 · 1 懒加载边 · 违规 0）。

### 21.5 ★ 顺带被自己的门禁抓到的第一件事

加这条断言后 `CHECKS` 21 → **22 项** ⇒ **O-50 的 `manual-counts` 断言当场 FAIL**：
「手册声明的断言计数 (21 = quick 15 + 三站 6) 与真实不符 (真实 22 = quick 16 + 三站 6) ⇒ **加/删断言后忘了改手册 §2.4**」。
⇒ **上一轮建的断言当天就还债**（若没有它，手册会悄悄停在 21）。
顺带发现手册那份**检查项名单**也已陈旧（缺 `artifacts/sensitivity/facade/mirror`）⇒ 按 O-50 纪律标成"**样例**" +
指向权威 `rpc.ps1 check -List`。

### 21.6 净方法论收益

- **★ 同一个词（import）语义可能不同**："模块级"与"函数内"的 import 在"成环"上**一个是真环、一个不是**
  ⇒ 判据必须**按语义分桶**，而不是按字形（正则）分桶。
- **"层序"要先能表达，才谈得上检查**：没有 `cluster_layers` 那张表，"允许什么方向"就只是注释里的一句话；
  **把约定落成数据，它才会被机器执行**（同 O-51 的账）。
- **"新模块必须登记"比成环检测更防腐化**：成环是**事故**，没登记是**遗忘** —— 遗忘会让整张表慢慢失效。

  ⚠ **就地更正（同日）**：我最初把这条写成"5 件 vs 正常 9 件" ⇒ **错**。备路 runDir 的**正常件数就是 5**
  （实测：全部 claude run 都是 5 件，含多枚 exit=0 的干净 run）—— 我把**主路（opencode）的 9 件**当成了通用基线。
  ⇒ **论据换成不受件数影响的那条**：该 ts 下只有**一个** runDir，而两个 run 期望两个；
- 一跑报 `open local "…\claude-err.txt": No such file` + `agent-output.txt` 不存在 ⇒ **另一方 collect 的 `Move-Item` 把共享 scratch 里的文件搬走了**。

**机制**：两个进程**几乎同时**执行"`agent-out\<ts>` 不存在 ∧ `…claude-<ts>` 不存在 ⇒ 沿用该 ts" ⇒
**双方都通过**（经典的 check-then-act TOCTOU）。⇒ **加判据只是降低概率，不能消除**。

**★ 危害序（本次调研最重要的结论）**：**runDir 撞车 ≫ scratch 撞车**。
scratch 撞车丢的是**中间产物**（可重跑）；**runDir 撞车丢的是"证据单元本身"** —— 两个 run 写同一目录后，
`run.json` / manifest / agent 输出**混在一起且归属不可复原**，而 runDir 是**声明为不可回改**的东西
（本仓对它的所有判据、水印、链都建立在这一前提上）。

**根治方向（本仓已有正确做法，只是没统一）**
1. **runDir 原子抢占**：`New-Item -ItemType Directory` **不带 `-Force`** —— 已存在即**抛错**，捕获后递增 ts 重试
   （check-then-act 换成 create-or-fail）。同理主路的 runDir。
2. **scratch / 临时根一律用 `$Script:RUN_TOKEN`（Guid）**：主路本地临时根**已经是** `agent-cli-<RUN_TOKEN>`、
   备路**站上** scratch 已经是 `/tmp/p3_<Guid12>_*` ⇒ 只有"以 `$ts` 命名的本地 scratch"这一处是漏的（主路 `agent-cli-ev-<ts>` + 备路 `agent-cli-claude-<ts>`）。
3. `$ts` **只保留一个职责**：runDir 的**对外名字**（18 位数字形状被全仓引用与 scrubber 依赖）⇒ 不再兼任命名空间。

**⚠ 一条推理，明确标注未证实**：备路站上投递脚本 `/tmp/_p3_run.sh` 是**固定名**且 `scp` **非原子**
⇒ 理论上存在"另一 run 的 scp 截断正在执行的脚本"。本次实测到的 rc=7 **已归因 `$ts` 撞车**（且 `:3489-3497`
另有 **CRLF** 归因、已修）⇒ **不把 rc=7 算作它的证据**；要证它需专门实验（同站两 claude + 高频 scp 干扰）。

## 30. C1 跨通道闭环 + C3 回归（含 C3 自身一处**回归**与被它牵出的同族缺陷）（2026-09-25）

> 本节接 §29。执行顺序按用户授权：③ hammer 接线 → ② 本地模式 `.attach` 租约 → ① C1 跨通道。
> ★ 本节最重要的一条不是"做了什么"，而是 **② 的自证实验把 ① 的一处回归当场打了出来**。

### 30.1 ③ hammer 接线（`ps1-runstamp` 进 `CHECKS`）

- `$Script:PS1_RUNSTAMP` = `ops/station-bin/_runstamp_hammer.ps1`；`check_ps1_runstamp(ctx)` 跑 `-N 8 -SelfTest`，
  判据 = **正向 PASS ∧ 负向 PASS ∧ rc==0**（三合一，防"只看正向"被恒过型夹具骗过）。
- `CHECKS` 新增 `{"id":"ps1-runstamp", …, "quick": False}`。**为什么 `quick:False`**：它起 8 个独立进程 + 自旋屏障
  ⇒ 不进 pre-commit（秒级预算），进 pre-push / 全量。
- **手册计数 24 → 25**：手工改了断言总账行 `# 25 项断言 (quick 18 + 全量 7)`。**改完由门禁 `mirror` 精确点名**
  （它逐项核对 "手册声明的项数/quick 分布" == `CHECKS` 实况）⇒ 忘了改会被红，不是靠人记。
- 实测：正向 `n=8 uniq=8` PASS · 负向（同一把锤子打旧实现）`uniq=1`（另一次跑出 `uniq=3`）PASS —— 负向读数
  **随竞态浮动**，判据是"**< N** 即证明夹具看得见撞车"，故**不能**把某个具体值当预期。

### 30.2 ② 本地模式 `.attach` 租约（规则**只在有附件时**）

- 位置：备路 claude 的 `if ($attach.Count -gt 0)` 块内，**在** `projRoot\.attach` 复制**之前**。
- **规则精确**：无附件 ⇒ 压根不碰 `.attach` ⇒ **不取租约** ⇒ 良性并发不受影响（§30.3 的回归就是这么来的：
  凡"一律取"都会误伤良性配对）。
- key = `local/<proj>`（与站上 `st-<站>/<proj>` 是**两个不同资源**：一个写控制台 `projRoot\.attach`，一个写站上
  `WSROOT/<proj>`）⇒ 不互相阻塞。

### 30.3 ① C1 跨通道闭环：`Enter-ClaudeStationLease` → **`Enter-WorkspaceLease`**

- **通用化依据**：站上锁（`flock`）在**主 run 体内**，而两条通道的 `.attach` staging 都在**锁外** ⇒ "同站同 proj
  的两条通道"必须共**同一把逻辑锁**。故把单一用途的 `Enter-ClaudeStationLease` 改成 rwlock 语义的
  `Enter-WorkspaceLease -Key -Exclusive -Why`（排他=`FileShare.None`；共享=`FileShare.Read`+只读打开）。
- **三处调用点（同一 key 格式 + 同一把逻辑锁）**：
  | 通道 | key | 取模式 | 位置 |
  |---|---|---|---|
  | 主路 `Invoke-Task`（opencode） | `st-<站>/<proj>`（无站 ⇒ `local/<proj>`） | `$leaseX` | `# 3) sync source subset` **之前** |
  | 备路站上（claude） | `st-<站>/<proj>` | `$leaseX` | `if ($useStation)` 分支开头、**staging 之前** |
  | 备路本地（claude） | `local/<proj>` | `$leaseX` | `projRoot\.attach` 复制之前（仅**有附件**时） |
- **危险面单一来源**：`$dangerFace = $leaseX`（主路），`$leaseX = (($attach.Count -gt 0) -or $goldenActive)`。
- **e2e（危险面跨通道）**：同站同 proj 同时发 `main` + `claude`，两边都带附件 ⇒ **恰好一跑**（main `exit=0`；
  claude `REJECT main-workspace-busy`/`claude-station-busy` ⇒ `exit 3`）。

### 30.4 ★★ ② 的自证实验打出 ① 的**回归**（C3 第一版写死排他）

**现象**（我的跨通道**良性**对照 · case B：只读 · 无附件 · 同站同 proj）：

```
b-claude.out: REJECT claude-station-busy (exit 3) - 同站(B)同 proj(dogfood) 已有**备路**派发在跑
b-main.out:   exit=0
```

**根因**：C3 第一版把**两处备路**租约都写死 `-Exclusive $true` ⇒ 连**良性跨通道配对**（只读·无附件，
6 并发里就有 oc+cc 同站对）也被串行化 ⇒ capability 退化。

**⚠ 为什么没早发现**：我复跑了 `claude×claude`（危险面场景），**没复跑 6 并发**（良性场景）——
而 6 并发是**唯一**能看见"良性配对被误伤"的夹具。**教训：改锁模式必须同时复跑"危险面"与"良性"两套对照，
缺一套就会朝反方向翻车。**

**修**：两处备路租约都改成危险面 `$leaseX`（与主路**同一规则**）。

### 30.5 ★ 修回归时**牵出的同族缺陷**：判据位置 ⇒ 无附件 golden run 漏挡

把危险面判据从"有附件块内"上移到本函数开头时，发现原位置的**语义后果**：

> 判据原先只在 `if ($attach.Count -gt 0)` **块内**计算 ⇒ **无附件的站上 golden run** 读到 `$leaseX = $null`
> （= `$false` = **共享**），而 **golden 注入是共享面写入** ⇒ **危险序① 漏挡**。

即"V4 golden 正向（无附件但 golden ⇒ 排他）"在**主路**成立，在**备路**却因判据位置而失效 —— 典型的
**"同一件事两份判据"**（本仓头号失败形态）。**修**：判据上移到备路函数开头（两处租约**之前**）**单点**计算，
golden 段改成指针注释（不再另算一份）。
