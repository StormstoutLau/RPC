# 决策简报 — cluster.py 模块化重构：可行性、仓内约束与社区调研

- **日期**: 2026-09-23
- **状态**: **仅调研与方案（未改动代码）** —— 待 Scott 裁定后按增量路线实施。
  含**阶段 4：web 管理页视觉升级（huashu-design skill）**（§6）。
- **问题**: `ops/cluster.py` 当前非常臃肿，能否重构为模块化 / 高内聚 / 低耦合？
- **依据**: [ADR-0004](../adr/ADR-0004-统一管理入口为唯一管理面.md)、
  [spec/d2-cluster-cli](../spec/d2-cluster-cli/)、`inventory/ops.yaml`、`ops/rpc_check.py` 断言 `scripts`
- **证据等级**: E1=本会话实测（含命令与结果）；E3=外部文档/社区；E4=推断

## 1. 结论先行

> **可行，且应当做；但不是"重构"，而是"按现有接缝的增量抽取"。**
> 三条硬约束决定了它只能走增量路线：
> ① 仓内 `scripts` 门禁会让**任何新增未登记脚本直接 FAIL**；
> ② `cluster.py` 被 `cluster_web.py`/`rpc_check.py` 以 **46 个符号**（含 8 个私有）依赖 —— 兼容面是硬契约；
> ③ **单文件**是 `spec/d2-cluster-cli/IMPLEMENTATION.md` 写明的**有意设计**，拆分需 ADR 取代，不能随手改。
>
> **真正的第一阻碍不是"怎么拆"，而是"没有安全网"**：`tests/` 下**没有任何 cluster.py 单元测试**
> （只有 shell 集成测试）。社区案例（4000 行 god class）的第一步正是**先补特征测试**。

## 3. 仓内约束（决定方案形态，全部 E1）

### 3.1 `scripts` 门禁：新增模块必须登记，否则 FAIL

`rpc_check.py` 的 `_in_script_scope` = `ops/**` ∪ 仓库根顶层文件；
`_iter_governed_scripts` 按扩展名（`.py` 等）判定 ⇒ **任何新 `ops/cluster_*.py` 都进管辖范围**。
而 `check_scripts` 要求 `ops/` 下每个脚本 ∈ `entry | station_runtime | frozen_ops_scripts`（`inventory/ops.yaml`）。

> ⇒ **拆出的每个模块都必须登记**，否则 pre-commit 直接 FAIL 并点名。
> 现有 `entry` = `[ops/cluster.py, ops/cluster_web.py]`。

### 3.2 兼容面 = 46 个跨文件符号（硬契约）

`cluster_web.py` + `rpc_check.py` 共引用 `cluster.*` **47 处符号名**（去重后 46，含 8 个私有）：

```
公开(38): agent_audit, agent_audit_baseline_load, agent_audit_calib_status, AGENT_BEAT_STALE_S,
  agent_chain_verify, agent_ledger_freshness, agent_live, agent_runs, alias_of, AliasError,
  BACKENDS, cmd_load, cmd_load_on, cmd_ttl, cmd_unload, cmd_unload_on, collect_frames,
  collect_status, DEFAULT_STATION, estimate_load, group_by_model, parse_model_meta,
  pick_representative, probe_egress_station, probe_metrics, probe_providers, probe_secrets,
  probe_station, probe_versions, REPO_ROOT, resolve_alias, resolve_quant, ROUTE, RPC_MODELS,
  ssh_run, STATION_ROUTES, STATIONS, TTL_DEFAULT_S
私有(8): _link_model, _MODEL_META_SCAN, _reqlog_aggregate, _reqlog_station, _scan_models,
  _secrets_push, _secrets_verdict, _ttl_parallel
```

> ⇒ 拆分后 **`cluster.py` 必须保留为门面（facade）**，`from <module> import *` / 显式重导出，
> 使上述 46 个名字**在 `cluster` 命名空间下依旧可见**。否则 `cluster_web.py`/`rpc_check.py` 连锁断裂。
> 这同时是社区"**wrapper shim**"模式的适用场景。

### 3.3 ⚠ `ops/cluster/` 包名**不可用**（E1 实测）

同目录下 `foo.py` 与 `foo/`（含 `__init__.py`）并存时，**包优先**：

```
$ python -c "import foo"   # 同目录并存 foo.py + foo/__init__.py
同目录并存时, import foo 解析到 -> package foo/
```
> ⇒ 若建 `ops/cluster/`，`import cluster`（cluster_web / rpc_check 都用）会**解析到包而遮蔽 cluster.py**，
> 门面失效。**必须**改用不同名：`ops/cluster_<area>.py`（既有先例：`cluster_web.py`）
> 或独立包名（如 `ops/rpclib/`）。

### 3.4 设计意图需 ADR 取代

`spec/d2-cluster-cli/IMPLEMENTATION.md:24` 明写"**单文件** `ops/cluster.py` … + `ops/cluster_web.py`"，
`RESEARCH.md:48` 记录该形态是**调研后有意选定**（对比 cluster.ps1 等）。
⇒ 模块化 = **推翻一条已成文的设计决策**，须落 ADR（同 ADR-0001→0008 的纪律），不能作为普通重构。

## 5. 建议方案（分阶段，待裁定）

### 阶段 0（**前置，不可跳**）：补特征测试网
- 对**要抽取的函数**写 pytest 特征测试，**锁住当前行为**（含已知怪异行为，注释标注、不顺手修）。
- 优先覆盖无站上依赖的**纯函数**：`alias_of`、`resolve_alias`、`resolve_quant`、`group_by_model`、
  `parse_model_meta`、`pick_representative`、`estimate_load`、`_reqlog_aggregate`、`agent_ledger_freshness`…
- 判据：这些函数在当前实现下全绿；人为改坏一处 ⇒ 测试转红（**双向自证**，本仓纪律）。
- **收益即使不重构也成立**：这是目前完全缺失的能力。

### 阶段 1：抽"零耦合"的第一批模块（低风险）
按依赖分层**自底向上**抽，每批一提交、`cluster.py` 留门面重导出：

| 批 | 抽取内容 | 目标模块（命名待定，避开 `cluster/`） |
|---|---|---|
| 1a | 常量层（ROUTE/STATION_ROUTES/STATIONS/BACKENDS/端口/TTL/AGENT_*） | `ops/cluster_const.py` |
| 1b | SSH 层 + 探测层（`ssh_run`/`probe_*`） | `ops/cluster_ssh.py` |
| 1c | 纯函数工具（alias 解析、模型分组、meta 解析、reqlog 聚合） | `ops/cluster_model.py` |

### 阶段 2：抽"平面"与"命令组"（中风险）
凭据/出站/额度借用 → `ops/cluster_secrets.py`、`ops/cluster_egress.py`；
models/versions/studio/estimate → 各自模块；
**优先解决最长函数**：`cmd_agent`(360) 拆为 `agent` 模块内的多个职责函数。

### 阶段 3：`main()` 退化为纯派发表
参照 Click 多文件 CLI：`main()` 只做"子命令 → 处理函数"映射（本仓已是这个形态，仅需确认无逻辑残留）。

### 阶段 4：web 管理页视觉升级（huashu-design skill）
> 见 §6 专节。前置依赖：阶段 1 的门面稳定（`cluster_web.py` 依赖 `cluster.*` 46 个符号），
> 避免"一边抽模块一边改页面"两件事互相干扰。**可与阶段 2 并行**（改的是 HTML/CSS，不是模块）。

### 每批的固定纪律（社区共识的本地化）
1. 先测后搬；2. 一刀一提交；3. 红了 revert 切更薄的片，**不调试半成品**；
4. 门禁 `scripts` 登记同步更新（`inventory/ops.yaml` 的 `entry_modules` 类目）；
5. 搬完跑 `rpc_check --quick` + `cluster.py <相关子命令>` 实跑（**运行时验证不可省**，
   参考 2026-09-23 那次 `_collect_planes` 误删：语法门禁查不出 NameError）。
6. ⚠️ **凡门禁"扫描代码文本"的断言，搬家后必须同步其扫描清单** —— 否则门禁**静默降级成假绿**
   （不是变红，是最坏的一种：看着 PASS 但已空转）。
   实测案例（本批）：常量层搬进 `cluster_const.py` 后，`inventory` 断言的声明源仍只扫
   `cluster.py` ⇒ 报数从「声明源 **3** 模型标识」掉成「**0**」而**仍然 PASS**。
   修法：`rpc_check.py` 引入 `DECL_CLUSTER_FILES` 清单（入口 + 拆分模块）并逐文件扫。
   同类风险点（搬家时要逐个复核）：`aliases` 断言、`check_models`、任何 `_read_text(...)` 后正则的断言。
7. 🔴 **搬完必须做"漏导入"静态检查 + 实跑受影响命令**（本批踩到 **两次**，值得单列）：
   - 现象：`cluster_egress.py` 漏 `re`/`datetime`/`subprocess`/`threading`；`cluster_secrets.py` 漏 `json`/`threading`/`STATIONS`。
     语法门禁 PASS、`import cluster` PASS、**"符号可达"检查也 PASS** —— 因为缺失的名字只在**函数体内部**，
     不调用就不炸。只有 `cluster.py secrets status` / `egress` 真跑才暴露 `NameError`。
   - 根因：按"段"搬运时，段内用到的模块级名（stdlib 模块、其他域的常量）不会自动跟着走。
     尤其 `X.Y()` 形态（如 `threading.Thread`）逃过朴素的"函数调用名"扫描。
   - 两道防线（缺一易漏）：
     a) **AST 静态检查**：收集「模块级定义 + import + 内建」，再找 `Load` 型 `Name` 不在其中的
        ⇒ 一次列全部漏项（`__file__` 属误报，忽略）。
     b) **实跑受影响子命令**：`secrets status` / `providers` / `egress` / `egress borrow` / `models meta`
        / `versions` / `inbox` / `agent runs` —— 确认 exit 0 且无 `Traceback`。
   > 教训与 2026-09-23 那次 `_collect_planes` 误删同源：**语法/导入层面的检查都挡不住"只在运行时才炸"的缺陷**。
8. **拆模块的依赖顺序按"单向"排**（如 `cluster_egress` 依赖 `cluster_secrets._secrets_push`
   ⇒ 先抽 secrets 再抽 egress），避免制造循环依赖。

## 6. web 管理页视觉升级（阶段 4：huashu-design skill）

> **对象**：`ops/cluster_web.py` 内嵌的 `PAGE_HTML`（管理页，1421 行文件中的页面部分）。
> **触发**：用户要求"重构后的页面采用 huashu skill 美化"。
> **skill**：`huashu-design`（花叔Design）—— 用 HTML 做高保真视觉产出；
> 本仓走其中的**设计方向顾问（Fallback）+ 反 AI slop + 品位锚点 + 5 维评审**。

### 6.1 三条硬约束：huashu 默认栈与本仓冲突，须走其纯 HTML/CSS 分支（全部 E1）

| huashu 默认做法 | 本仓实况（实测） | 处置 |
|---|---|---|
| React + Babel（pinned CDN）+ 多 `.jsx` 文件 | 页面**零外部 CDN**、零外链、纯 vanilla JS + 系统字体（`'Segoe UI','Microsoft YaHei',system-ui`）；集群纪律 `local-only`/离线 | ❌ 不可用 CDN；走 huashu 明示的降级路径「**纯 HTML/CSS 不用 React，保证产出可用**」 |
| 「避免 >1000 行大文件，拆多个 JSX import」 | 无构建步骤（stdlib `http.server`），页面是 `PAGE_HTML` 内嵌常量 | ⚠️ **可选**抽资源文件（见 6.6）；不引入构建链 |
| display 字体避开 system fonts | **中文 + 离线**：CJK webfont 体积大且不能走 CDN | ⚠️ 用**字重/字号/字距/衬线回退**做层级（`Georgia`/`Songti SC`/`serif` 中文回退），或仅对**数字/标题**内嵌小型 latin display 字体 |

### 6.2 流程（huashu Fallback 的裁剪版）

1. **Phase 1 澄清**：受众 = 用户本人（单人管理台，10cm~1m 观看距离）· 核心信息 = 三站状态/模型/证据链/受理区 ·
   基调 = 冷静、可信、运维感（**非**营销页）· 输出 = 桌面浏览器。无品牌资产 → 走 Fallback。
   ⚠️ **本页无"具体产品/品牌"可考**，§1.a 核心资产协议**不适用**（huashu 明确：主题名 ≠ 品牌名，不空转找 logo）。
2. **Phase 2 顾问式重述**（≥200 字）→
3. **Phase 3 固化 design spec**（≥500 字，含尺寸：桌面 1440×900 为主基准）。
4. **Phase 3.5 图片前置**：本页属**工具/数据型 → 判定不需要图片**，**跳过取图**
   （huashu：「工具/数据/文档/纯观点型 → 可能不需要」）。⇒ **不引入任何图片资产**，避免 stock「灵感图」slop。
5. **Phase 4 三套逻辑并行出 3 版真实视觉**（同一份 spec，各自独立）：
   ① 秒数轮盘（`date +%S % 20 + 1`，从 40 风格库**网页半区**取）；
   ② 现实参照（选 1 个真实存在的、运维/监控类高水准界面做标杆，先 `WebSearch` 核实）；
   ③ 最佳设计师（深呼吸：最适合"单人技术运维台"的设计师/工作室，启用其设计哲学）。
   三版均纯 HTML/CSS、用真实内容。
   📁 **存放位置**：huashu 要求存"项目目录的 `design-demos/`"且**禁 `_temp/`**；
   本仓惯例是过程产物进 `tmp/`（gitignore，ADR-0004）。
   ⇒ **建议 `d:\RPC\tmp\design-demos/`**（满足"非 `_temp/`"且不污染仓库）；
   若要长期留档则改 `docs/design-demos/`（需注意 doclinks 门禁只管 `.md`，`.html` 不受影响）。
6. **Phase 5 用户看三版真实截图选**（**不给文字单选题** —— huashu「选择无效铁律」：没看到视觉的选择无效）。
7. **Phase 6 主干执行**：Junior pass（先 show 假设/placeholder）→ Full pass → 验证。
   最终成果**回灌进 `PAGE_HTML`**（页面仍是内嵌单文件；`design-demos/` 只作为设计过程留档）。

### 6.3 必须规避的 slop（针对本页形态具体化）

huashu 反 slop 表落到"运维仪表盘"上，最容易犯的是这几条：

| 禁 | 为什么在本页尤其危险 |
|---|---|
| **iconography slop**：每个卡片/指标都配装饰性 icon | 仪表盘天然有几十个数值 → icon 一配就是噪声；huashu：「装饰性 icon 每处都配」撞 slop |
| **data slop**：为了"看起来专业"加无意义数字/徽标 | 本页已有真实指标（bytes/B/s、证据链 117 条、gap 16），**不需要编**；编出来的会稀释真数据 |
| 紫/蓝渐变、圆角卡片 + 左 border accent | AI 落地页的视觉最大公约数；本页当前是朴素表格风，升级时最易滑向此处 |
| **GitHub-dark 偷懒解**（均匀深蓝 `#0D1117` + 通用霓虹 glow）| 运维台最诱人的"一键高级感"；huashu 点名此**特定组合**为 slop（非禁所有暗色） |
| emoji 作图标 | 同上 |

### 6.4 正向：信息密度分型 —— 本页是**高密度型**，不可误用减法（关键）

huashu「信息密度分型」明确：**产品核心卖点是"数据/上下文感知"时，每屏需 ≥3 处产品差异化信息**，
**减法是 fallback 不是普适律**。本页正属此型，且**天然已具备**差异化信息：

- 三站引擎态 + 口径分列（字节口径 vs 引擎耗时口径，**本仓特有**）
- 证据链（117 条 / 未入链 0 / 可重放 gap）+ 判官校准新鲜度
- 受理区跨项目进度 + 待办聚合（状态机派生"下一动作"）
- 门禁 15 项 + 处置建议（红灯必给下一步）

> ⚠️ **美化时最危险的错误就是把上面这些"为了简洁"删掉**。目标是**重构视觉而非削信息**：
> 保留全部信息，用层级（`text-wrap: pretty`、CSS Grid、字重/间距）让高密度可读。

### 6.5 品位锚点（本页 pursue list）

- **字体**：一个衬线/半衬线 display 用于标题与数字（离线可用范围内），正文用系统无衬线；
  **数字用等宽**（`Consolas`/`ui-monospace`）以对齐列 —— 顺带改善仪表盘可读性。
- **色彩**：**单 accent** 贯穿（本页已有 CSS 变量 `--bg/--card/--line/--fg/--mut` → **在其上调，不凭空发明新色**，
  huashu：⚠「所有临场发明的色都会让品牌识别度下降」）。
- **容器**：用诚实的边界/分隔，替代"圆角 + 左色条"。
- **签名细节**：留**一处**值得截图的质感（如证据链/受理区状态的时间轴式呈现），其余做到 80% 即可
  —— huashu：「一个细节做到 120%，其他做到 80%」。

### 6.6 交付形态与门禁（E1 实测）

- **默认**：成果回灌 `PAGE_HTML`（保持零外链、单文件、无构建）。
- **可选**：若 CSS/JS 膨胀到难维护，可抽为 `ops/cluster_web_assets/*.css|*.js`。
  ✅ **实测确认**：`scripts` 门禁的 `SCRIPT_EXT = (".py",".ps1",".sh")`，
  **`.css`/`.js` 不在管辖内**（探针文件 `git add` 后跑 `--only scripts` 仍 PASS、计数 212 不变）
  ⇒ **抽资源文件无需登记 `inventory/ops.yaml`**，比抽 Python 模块的自由度更高。
  ⚠️ 但注意 `_iter_governed_scripts` 还会捕获**无扩展名但带 shebang** 的文件 ⇒ 资源文件**必须带扩展名**。
