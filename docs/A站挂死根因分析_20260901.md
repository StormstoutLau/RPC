## 3. 机理链 (主假设, 置信度 ~70%)

```
m27 rpc-server 满载推理 (GTT 121G 高压力, 每token 38.7次RPC命令, GPU 有微空闲间隙)
        │
        ▼
[复合触发] cron 每分钟执行 bjork_deepfix recover 脚本
        (内容已随 /tmp 丢失; LM Studio 检查失败路径, 可能拉起 llama-server gpt-oss-120b 103G
         → Vulkan GTT 二次分配与 rpc-server 的 121G 竞争)
        │
        ▼
GFXOFF 状态机被扰动: GPU 空闲门控 on/off 切换与 TTM/KFD 内存路径竞争
        │
        ▼
amdgpu_device_delay_enable_gfx_off worker 在 SMU/RLC 寄存器交互中卡死
        (实证: 00:41:16 hogged 报告; worker 持 amdgpu 内部锁)
        │
        ▼
持锁阻塞: 后续 KFD 调度/TTM 分配/DC 显示路径排队 → CPU 核被 D 状态进程累积占据
        │
        ▼
渐进冻结: journald/CRON/ssh 饿死 (journal 静默) → 中断响应丢失 (管理网/USB4 死,
 B 站 90s 后见 TB 断链) → GPU 硬件队列独立继续跑已提交命令 (19.7 t/s 残余)
        │
        ▼
系统死透: 无 panic (softlockup 检测未配 panic), 看门狗杀不掉 D 状态, 强制断电恢复
```

**备选假设**:

- H3 (~10%): NEX 主板 SMU 固件/供电特异 (无法完全排除, 但 F5 一致的 ppfeaturemask + F4 cron 差异使其退居三线)

**与旧记录的两处修正**:
1. 前次记录"amdkfd_restore_userptr_worker 饿死"为误读 — 本次直接取证实为 `amdgpu_device_delay_enable_gfx_off` (B 站 kernel log 首次事故时只能报 B 站自身 worker, 无法看到 A 站内部)

## 5. 解决方案 (分级)

### L0 立即执行 (零风险, 最强嫌疑消除)

1. **删除 A 站 bjork_deepfix 两条 cron** (crontab 编辑删除)。脚本本体已随 /tmp 丢失, cron 每分钟在跑死链 (bash No such file)。此工具来源不明 (非本项目任何会话所建), 若需保留 LM Studio 自愈, 应重写为不碰 GPU 的检查。
2. 保留现有防护: 看门狗 (20s ping×3) + Beszel CPU 告警 95%/3min (已配)。

### L1 观测增强 (下次若再挂, 必抓到实锤)

3. **netconsole**: A 站 printk 实时镜像到 B 站 UDP (`modprobe netconsole netconsole=@/10.10.10.1/eth0,@10.10.10.2/`)。journal 静默 ≠ printk 静默 — 挂死最后遗言 (RCU stall 栈/hogged/panic) 可捕获。挂 B 站 systemd 持久监听。
4. **softlockup 全核栈 + panic**: 内核参数 `kernel.softlockup_all_cpu_backtrace=1 kernel.softlockup_panic=1 nmi_watchdog=1` — 软死锁 21s 时全核 backtrace 进 console (netconsole 收到) 并 panic 自动重启 (两站皆为无人值守推理节点, 自动重启优于死透)。可先只开 backtrace 不开 panic 跑一轮观察。
5. 清除无效 cmdline 参数 `amdgpu.wq_unbound=1` (不存在, 误导排查), 保留 `workqueue.cpu_intensive_thresh_us=5000` (hogged 报告有用)。

### L2 缓解 (L0 执行后仍复现时)

6. **禁 GFXOFF** (若 E2 实锤 gfxoff 路径): rpc-server 服务 ExecStartPre 设 `power_dpm_force_performance_level=high` (GPU 常驻高频, 抑制门控切换; 代价闲时 +10~15W); 或查证本代 ppfeaturemask 的 GFXOFF bit 后从 mask 清除。
7. 串行控制台 (USB-TTL 3.3V 线, ~20元) 接 A 站 debug 口, `console=ttyS0` — 硬件级最后遗言通道 (netconsole 死透时的兜底)。

### L3 根治

8. netconsole 抓到完整栈后 → 向 amdgpu/ROCm 上游报 bug (挂死栈 + 复现条件: gfx1151 + GTT 120G + RPC 负载 + gfx off) → 并入 #26610 升级窗口评估。
9. kdump (crashkernel=512M) 可选 — 想要完整内存转储时再上。
