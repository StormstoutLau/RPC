## 0. 结论

**这不是"版本不一致"，而是这条轴从建立起就没有治理面**：

- **结构性根因**：该轴**逐站本地构建**，**无**「单点构建 → tar 分发 → MD5 校验」。对比另两条轴：
  `/opt/llama.cpp-*`（B 单点 → tar → 分发 → `md5sum -c`）· studio（官方预编译 bundle）。
- **产物实测**：`llama-server` 三站**逐字节相同**；但 **`libggml-base`（B 异于 A/C）** 与 **`libggml-vulkan`（C 异于 A/B）** 逐字节不同。
- **且这轴不可复现**：源码同（HEAD `0d18aaa`、worktree 干净 ×3）、工具链同（GCC 13.3.0 ×3）、CMake 开关同，
  仍产生不同字节 ⇒ **"同源重建"也给不出一致产物**（`GGML_NATIVE:BOOL=ON` 即 `-march=native`，是显式非确定性开关）。
- ⇒ **统一的正解 = 让这条轴消失（方案①）**，而不是去"修"它。
  ★★ **2026-10-12 已执行完毕**（等价性冒烟双 PASS → conf 归位 `/opt` → tar 备份 → 三站删轴 → 代码最小维护 → 门禁 PASS）—— 全过程与证据见 **§5**。

## 1. 调研：六层成因（逐条有据）

| 层 | 成因 | 证据（E1，2026-10-12） |
|---|---|---|
| **① 结构性（根因）** | **逐站本地构建，无单点构建 + 分发 + 校验** | 三站各自 `~/llama.cpp/build`；`~/build/llama-*` **仅 B 有**（A/C 该目录为空） |
| **② 构建目标不同** | C 只编 `llama-server`+`rpc-server`（**27 文件**）；A/B 为全量（**122 文件**，含 `llama-cli`/`llama-bench`/`llama-quantize` 及各自 `-impl.so`） | **C 是 B 的严格子集**（`comm -13` 空）；缺失清单 = 全部工具二进制 |
| **③ 三次独立构建** | A `2026-05-27` · B `2026-09-06` · C `2026-09-07/08` | `build/bin` mtime 范围 |
| **④ ★ 同源同工具链仍不可复现** | 同 HEAD / 同 GCC / 同 CMake ⇒ 仍有 2 个库不同 | 全库 md5 矩阵（下表） |
| **⑤ 版本串不自洽** | git HEAD 为 **5 月** commit，二进制却具备 **8 月才合入**的 `--spec-type draft-mtp` | `--version`=`1 (0d18aaa)`；`--help` 命中 `draft-mtp` |
| **⑥ 无治理覆盖** | 无 MANIFEST · **无门禁判据** · 无回滚点 ⇒ 漂移长期不可见 | `cluster.py versions` 只"直读 commit"，不做 `md5sum -c`；门禁 `backend` 只守 `/opt` 9859 + studio 引擎同版 |

### 1.2 关键辨析（避免误判）

- **`/opt` 三站逐字节同版，不是因为它可复现，而是因为它走 tar 分发**（同一份字节复制三遍）⇒

- **`llama-server` 一致 ⇒ 功能入口未分叉**；差异只在两个底层库（**是否造成行为差异未验证**，见 §7）。

## 3. ★★ 关键前提：这两个 pin **有功能理由**，不是随意写的

两个 conf 的注释（E1 逐字）：

- `davidau-q38-27b-q4k`：
  > `# 引擎必须用 master(0d18aaa) 构建: /opt 不含 qwen35`
  > `# 加载: infer-load davidau-q38-27b-q4k --backend llama-single   (默认 unsloth/b10715 无法加载 qwen35)`
- `qwen3.8-27b-mtp`：注释讲的是**思考模板**（froggeric / reasoning_format），未提 arch；但同样依赖
  `--spec-type draft-mtp` + `--mmproj`。

⇒ **pin 的理由 = arch 支持（`qwen35`）+ MTP**。**因此方案① 绝不能直接改 conf** ——
必须先证明 **新的 `/opt/llama.cpp`（`23b0202a`）能加载这两个模型**（等价性冒烟），否则会**改坏两个可用别名**。
（注：/opt 已在 2026-10-12 从 `91f6a6cf` 升到 `23b0202a`，**"不含 qwen35"这条结论可能已随升级失效** —— 但**必须实测，不许推断**。）

## 4. 统一方案（3 选 1）

| 方案 | 做法 | 代价 | 收益 |
|---|---|---|---|
| **① 退役（采用）** | 先把 2 个别名的 conf 指回 `/opt/llama.cpp`（**前提 = §3 等价性冒烟双过**），随后删除三站 `~/llama.cpp` 轴 | 等价性冒烟（每别名一次加载）+ 一次 conf 编辑 | **轴消失 ⇒ A/B/C 永不再漂**；继承 MANIFEST / 门禁 / 回滚；符合"加法→减法" |
| **② 纳管（备选）** | 照 `/opt` 同款治理：**B 单点构建 → tar → 分发 A/C → MANIFEST + `md5sum -c`**，并**写死构建目标**（全量 or 最小集） | 需定构建口径；**长期仍维护第二条引擎轴**；且**仍不可复现**（§1 ④）⇒ 只能靠 tar 铺平 | 保留独立单站轴 |
| **③ 最小动作（不单独用）** | 仅把 B/A 的 122 文件 tar 分发补到 C | 低 | 消掉文件数/md5 漂移，**根因（本地构建）不变，下次重建即复现** |

**判据（统一后）**：`~/llama.cpp/build/bin` 三站 `md5sum -c` 全 OK（需先有 MANIFEST）**或该路径不存在**。

> ⚠ **方案① 附录（删除的耦合）**：`cluster.py` 的版本矩阵 `_VER_SCAN` 会探 `~/llama.cpp/build/bin/llama-server --version` 与
> `git -C ~/llama.cpp rev-parse`（[cluster.py](../ops/cluster.py) L1209-1210）⇒ **删轴后该探针会退化**，
> 需同步做一处最小维护（否则 `cluster.py versions` 报空）。**该编辑属代码改动，执行前单独确认。**
