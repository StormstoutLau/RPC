## 1. 目标与非目标

### 1.1 目标

1. **判定根唯一**：备路的 accept / accept-golden / `.run-marker` / state-pull 全部以**同一个 `$judgeRoot`** 为根；`$judgeRoot` = agent 的执行点。
2. **golden 可判**：golden 注入到 `$judgeRoot/.golden`（本地 copy / 站上 scp），判据 cwd = `$judgeRoot`；站上变体真正把 golden 送上站。
3. **可观测**：判据输出件里能直接看到 `PWD`（站上）/ `JUDGE_ROOT`（本地）/ `ACCEPT_MODE` / `GOLDEN_RC` / `ACCEPT_GOLDEN_OK`，不需要靠日志猜。
4. **失败闭合**：站上脚本/scp 失败 ⇒ `accept=0` / `golden=0`，整任务 failed；不静默回退到主控。

### 1.2 非目标（明确不做）

- 不改主路 `$body` 的 accept/golden（L3146 / L3440）—— 它已自洽。**例外（O-167，§11）**：O-167 只在主路 body 的 accept 段加“产物新鲜度”前置判据，不改 golden/agent。
- 不做"站上解释器预检"（`.venv` 缺失等）——见 §6 边界；只如实记录 rc。
- 不做"未声明产物的自动拉回"——属 `O-29`/collect 面，不在本项。
- 不合并 `O-42`（权限）与 `O-29`（state/glob）——已闭环，仅复用其 `$evmRoot` 形状。
- 不改卡面契约（不需要 89 张卡改声明）。

## 2. 设计决策（D1–D10）

| # | 决策 | 理由 / 约束 |
|---|---|---|
| **D1** | 在 `Invoke-Task-Claude` 内**只算一次** `$judgeRoot = if ($useStation) { $stWorkDir } else { $projRoot }` | 与已落地的 `Invoke-EvmStatePull` 调用点同形（[L5061](file:///d:/RPC/ops/station-bin/agent-cli.ps1#L5061-L5063)）⇒ **同一事实一个实现点**；后续所有判据从它派生 |
| **D2** | **本地 accept**：`Invoke-LocalBashCmd -cwd $judgeRoot`（行为不变，仍是 Git Bash） | 本地支原本就是对的（O-15/AUDIT）；只把硬编码 `$projRoot` 换成派生值 |
| **D3** | **站上 accept**：生成**站上 bash 脚本**（R14：script-on-disk）→ `Invoke-RemoteScript` 执行 → `scp` 回输出件 | 复用主路 `ACCEPT_B64` + `while read` 语义；`Invoke-RemoteScript` 只回 rc（[L450-454](file:///d:/RPC/ops/station-bin/agent-cli.ps1#L450-L454)）⇒ 输出必须落站上文件再拉回 |
| **D4** | **golden 注入**：本地 `$judgeRoot/.golden`；站上 `scp` 到 `$stWorkDir/.golden`（先清空） | 与主路 `$W/.golden`（[L3253-3255](file:///d:/RPC/ops/station-bin/agent-cli.ps1#L3252-L3255)）同址语义 |
| **D5** | **golden 时机**：agent **结束后**再落 `.golden`，判完即清（本地）；站上保留（工作区可弃）。具体：`$goldenSha`/`$goldenBase` 仍在原处算（只读源），**删掉 L4826-4828 的 scratch copy**，改在 golden gate 前落盘 | 备路原来 golden 在 scratch，agent 看不见；挪进 `$projRoot` 后若在 spawn 前落盘，agent 可读 golden ⇒ **判据可被 gaming**。主路先落是历史形状，本项**不跟随**，并如实登记为差异 |
| **D6** | **站上 golden**：脚本内先 `sha256sum -c` 再 `( cd $judgeRoot && eval "$cmd" )`，输出写 `out/.accept-golden-output.<run>.txt`，rc≠0 ⇒ 退出非零 | 复用主路防篡改语义（[L3138-3148](file:///d:/RPC/ops/station-bin/agent-cli.ps1#L3138-L3148)）；命令走 base64 避免引号/`$` 注入 |
| **D7** | **输出捕获**：站上脚本把输出写到 `$judgeRoot/out/.accept-output.<run>.txt` / `.accept-golden-output.<run>.txt`；执行后 `scp` 到本地 `$accTxt` / `$accGoldTxt` | `out/` 是框架保留区（不同步回主控）⇒ 不污染工作区；per-run 后缀防并发撞名 |
| **D8** | **失败语义**：站上脚本 rc≠0 / scp 失败 / `sha256sum` 不过 ⇒ 对应 `acceptOk=0` / `acceptGoldenOk=0`；日志分别打 `ACCEPT_OUTPUT_PULL_FAIL` / `GOLDEN_TAMPERED` / `GOLDEN_FAIL rc=` | 与主路 `.meta` 的 `ACCEPT_OK`/`ACCEPT_GOLDEN_OK` 语义对齐；**禁止**把 stdout 混进 `Invoke-RemoteScript` 返回值（归零纪律） |
| **D9** | **可观测**：站上输出件在 `cd` **之后**写 `PWD=$(pwd)`；本地输出件写 `JUDGE_ROOT=$judgeRoot`（本地 cwd 由 `Invoke-LocalBashCmd` 的 `Push-Location` 保证）；两路都写 `ACCEPT_MODE=…` / `GOLDEN_RC` / `ACCEPT_GOLDEN_OK` | 直接满足"看件不看日志"；站上 `PWD` 是**件内自证**，本地 `JUDGE_ROOT` 是**声明值**（不冒充 shell 证据） |
| **D10** | **主路**：O-165/166 **零改动**；O-167 只在 body 的 accept 段加产物新鲜度前置判据（§11），不改 golden/agent | 缩小回归面；主路已有真跑基线 |

### 2.1 关键取舍（为什么不是乙/丙/丁）

- **乙（先拉回再判）**：未声明产物拉不回 ⇒ 判不到；且把判据耦合到 collect。**不采纳**。
- **丙（站上 claude 拒绝文件型 accept）**：零假绿但能力损失；可作为**回退开关**（若站上 bash 迁移出现不可解问题），不是主方案。
- **丁（站上工作区镜像回主控）**：制造两个真值、覆盖主控树。**不采纳**。

### 2.2 与主路的**刻意差异**（必须留档）

| 点 | 主路 | 备路（本设计） | 原因 |
|---|---|---|---|
| golden 落盘时机 | agent **前**（`$W/.golden`） | agent **后**（`$judgeRoot/.golden`） | 防 agent 读 golden；备路原本就不暴露 |
| golden 清场 | 留在站上工作区 | 本地判完 `finally` 删除；站上保留 | 本地 `$projRoot` 是真实仓库，不能留脏 |
| accept shell | 站上 Linux bash | 本地 Git Bash / 站上 Linux bash | 既有语义（O-15/AUDIT 已定案：**只差机器与 cwd，不差 shell**） |

### 3.3 站上 accept 脚本（模板）

```bash
set -u
mkdir -p "<judgeRoot>/out"
OUT="<judgeRoot>/out/.accept-output.<run>.txt"
: > "$OUT"
cd "<judgeRoot>" || { echo "JUDGE_ROOT_MISS" >> "$OUT"; echo "ACCEPT_OK=0" >> "$OUT"; exit 90; }
echo "PWD=$(pwd)" >> "$OUT"
echo "=== ACCEPT_BEGIN ===" >> "$OUT"
echo "<acceptB64>" | base64 -d > "out/.accept-cmds.<run>.txt"
ACCEPT_OK=1
i=0
while IFS= read -r c || [ -n "$c" ]; do
  [ -z "$c" ] && continue
  i=$((i+1))
  echo "=== ACCEPT_CMD[$i] >>> $c" >> "$OUT"
  ( eval "$c" ) >> "$OUT" 2>&1
  arc=$?
  echo "--- ACCEPT_RC[$i]=$arc" >> "$OUT"
  [ "$arc" -ne 0 ] && ACCEPT_OK=0
done < "out/.accept-cmds.<run>.txt"
echo "ACCEPT_OK=$ACCEPT_OK" >> "$OUT"
[ "$ACCEPT_OK" -eq 1 ]
```

### 3.4 站上 golden 脚本（模板）

```bash
set -u
mkdir -p "<judgeRoot>/out"
OUT="<judgeRoot>/out/.accept-golden-output.<run>.txt"
: > "$OUT"
cd "<judgeRoot>" || { echo "JUDGE_ROOT_MISS" >> "$OUT"; echo "ACCEPT_GOLDEN_OK=0" >> "$OUT"; exit 90; }
echo "PWD=$(pwd)" >> "$OUT"
[ -f ".golden/<goldenBase>" ] || { echo "GOLDEN_MISS" >> "$OUT"; echo "ACCEPT_GOLDEN_OK=0" >> "$OUT"; exit 93; }
echo "<goldenSha>  .golden/<goldenBase>" | sha256sum -c >/dev/null 2>&1
if [ $? -ne 0 ]; then
  echo "GOLDEN_TAMPERED" >> "$OUT"
  echo "ACCEPT_GOLDEN_OK=0" >> "$OUT"
  exit 91
fi
echo "<goldenCmdB64>" | base64 -d > "out/.golden-cmd.<run>.txt"
echo "=== GOLDEN_CMD >>> $(cat out/.golden-cmd.<run>.txt)" >> "$OUT"
( eval "$(cat out/.golden-cmd.<run>.txt)" ) >> "$OUT" 2>&1
GOLDEN_RC=$?
echo "--- GOLDEN_RC=$GOLDEN_RC" >> "$OUT"
if [ "$GOLDEN_RC" -ne 0 ]; then
  echo "GOLDEN_FAIL rc=$GOLDEN_RC" >> "$OUT"
  echo "ACCEPT_GOLDEN_OK=0" >> "$OUT"
  exit 92
fi
echo "ACCEPT_GOLDEN_OK=1" >> "$OUT"
```

### 3.5 本地分支

- accept：`Invoke-LocalBashCmd -cmd $c -cwd $judgeRoot -logFile $accTxt`（命令数循环保持现状）。
- golden：清空/创建 `$judgeRoot/.golden` → `Copy-Item $gSrc` → `Test-Path`（缺 ⇒ `GOLDEN_MISS`）→ `Get-FileHash` 比对 `$goldenSha`（不过 ⇒ `GOLDEN_TAMPERED`）→ `Invoke-LocalBashCmd -cmd $g.cmd -cwd $judgeRoot -logFile $accGoldTxt` → 失败补 `GOLDEN_FAIL rc=` → `finally` 删除 `$judgeRoot/.golden`。
- 输出件首行补 `ACCEPT_MODE=bash-local (cwd=$judgeRoot)` / `ACCEPT_GOLDEN_MODE=…`；本地写 `JUDGE_ROOT=…`（声明值，不冒充 `pwd`）。

### 3.6 站上分支的传输

- **准备**（golden）：先跑一个 prepare 脚本 `rm -rf "$judgeRoot/.golden"; mkdir -p "$judgeRoot/.golden" "$judgeRoot/out"`（`Invoke-RemoteScript`，R14）。
- **注入**（golden）：`scp -q -o BatchMode=yes -o ConnectTimeout=10 $gSrc.Path "${rt}:$judgeRoot/.golden/$goldenBase"`；失败 ⇒ `GOLDEN_PUSH_FAIL`、判 0。
- **执行**：`Invoke-RemoteScript -HostName $stHost -LocalName agent-cli-claude-accept-<run>.sh -ScriptBody <template>`（内部 scp→ssh，R14）。
- **回传**：`scp -q -o BatchMode=yes -o ConnectTimeout=10 "${rt}:$judgeRoot/out/<file>" "<local>"`；`$rt` 按 `Invoke-EvmStatePull` 的规则构造（`$stUser` 非空 ⇒ `user@host`，见 [L2095-2098](file:///d:/RPC/ops/station-bin/agent-cli.ps1#L2095-L2098)）。
- **失败**：scp/ssh 失败 ⇒ 本地写 `ACCEPT_OUTPUT_PULL_FAIL: <file>` 到对应输出件，判 0。

### 3.7 文件/字段（不变）

- runDir：`accept-output.txt` / `accept-golden-output.txt`（名字不变）。
- `run.json`：`accept_ok` / `accept_golden.ok`（不变）。
- 站上临时件：`out/.accept-output.<run>.txt`、`out/.accept-golden-output.<run>.txt`、`out/.accept-cmds.<run>.txt`、`out/.golden-cmd.<run>.txt`（`out/` 框架保留，不同步）。

## 6. 边界、风险、回滚

1. **站上解释器**：`.venv/` 在 `.agentsync` 排除项；A 站 `paper` 有、`dogfood` 无（E1）。依赖 `./.venv/bin/python` 的**示例/夹具**命令可能不可用 ⇒ 输出件会如实显示 `GOLDEN_FAIL rc=127`；不静默换解释器。
2. **shell 语义**：本地 Git Bash → 站上 Linux bash；现役卡命令为 POSIX（`test`/`grep`/`find`），可迁移。含 Windows 路径/PS 语法的卡**不支持站上 claude**（须显式拒绝或登记）。
3. **并发**：有附件或 golden ⇒ `$leaseX` 排他（[L4685](file:///d:/RPC/ops/station-bin/agent-cli.ps1#L4685)）⇒ 本地/站上 `.golden` 无跨 run 竞争。
4. **`readonly` + golden**：`.golden` 由**框架**写入（非 agent）⇒ 不受 `--permission-mode` 影响；但**未真跑**，列入验收。
5. **回滚**：改动限定在 `Invoke-Task-Claude` + 新 helper；回退一个 commit 即恢复。站上临时件在 `out/`，不影响主控。
6. **安全**：不扩大攻击面 —— 主路本来就在站上工作区执行 accept/golden；本项只是让备路同址。
7. **未核**：站上 B/C 站解释器面未普查；站上 golden 真跑列为可选（甲-2 真跑②）。
