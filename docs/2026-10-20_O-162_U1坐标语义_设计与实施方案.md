## 2. 取证：把「撞身份」这件事算清楚（★ 修正台账的定性）

**撞身份的定义**：两个**不同的件**得到**同一个** `u1:` 身份。
身份只吃 `(ns, id, ver)`，而 `ns` / `ver` 在当前口径里都是**常量** ⇒ **唯一变量是 `id` = `agent-out/<run>/<file>`**。

**逐层收敛**：

1. **同一项目根 + 同一相对路径 ⇒ 同一个文件** ⇒ 同身份是**设计意图**（U-1 = 坐标寻址：同一个产物就该有同一个身份），
   **不是撞车**。⇒ 撞车必须**换项目根**。
2. **换项目根 ⇒ 两条 `run` 名必须逐字相同**。而 `run` 名 = `Get-UniqueRunStamp` 的产物，其抢占物是**全局的**
   （F10：`%TEMP%\agent-cli-claims`，**不按项目根分**）⇒ 同机**不可能**出现两条相同的 `run` 名。
3. ⇒ **结论：本机不可达**。唯一剩余通道 = **跨机**把同一项目根的 `agent-out` 合到一起 —— 而 `agent-out` 是框架保留目录、
   已被排除（F11）⇒ 正常路径不产生。

★★ **所以 ① 的真实风险不是"会撞"，而是"撞不撞取决于别处的一条实现性质"**：当前身份的正确性**依赖**
`Get-UniqueRunStamp` 的全局抢占这一**隐藏前提**（在另一个文件里、与 U-1 无任何咬合）。
⇒ 这正是本仓反复要消灭的东西（**"纪律不能代替判据"** / **"同一事实两处表达"** 的近亲）：
**U-1 spec 与台账都没写这件事**，下一个读者只会照抄"撞身份可能"，继续纠结。

⇒ 故 §3 的 A 组不是"修不修一个会撞的身份"，而是**二选一**：
**(甲) 把这条前提写明并登记**（A1）· **(乙) 让身份不再依赖它**（A2 / A3）。

## 3. 裁定点（**未裁前不实施**）

### A｜① 口径残余：动不动已裁口径？　⇒ ★ **裁 = Ａ1（维持口径 + 写明前提）**

| 选项 | 做法 | 代价 / 收益 |
|---|---|---|
| **A1 维持口径** | 一行码不改；在 §1.3 + 台账里**写明**"身份唯一性依赖 `Get-UniqueRunStamp` 的全局抢占（F10）"+ 立**再触发条件**（跨机合并 `agent-out` / 改用非 run 名的路径形态） | 零改动 · 零迁移；但**前提仍在别处**，属"书面纪律" |
| **A2 id 前缀加受理目录名** | `id = "<受理目录名>/agent-out/<run>/<file>"`（ns / ver 不变） | ★ **消除前提依赖**（身份自足）；代价 = **id 与数据行路径分家** ⇒ `parse_u1_track` 必须**读头部**拿受理目录名，F3 的"路径只写一处"前提须重述 |
| **A3 ns 取来源项目** | `ns = namespace_for_project(proj)`（F12 复用），id 仍 = 数据行路径 | ★ 消除前提依赖、**且不动 F3 的"路径只写一处"**；代价 = **动 ns 轴**（`rpc_inbox` 在 U-2 方言里是**交付分级**轴 L150，语义会分叉），且消费侧须由 header 反推 proj |

★ **窗口期（A2/A3 的共同理由）**：**当前真实身份 = 0 个**（F5）⇒ 改口径**迁移代价为零**；
对照 `U1#8`（截断 `16→32`）的教训 —— 一旦外发过，改坐标就必须**另立映射路径**。
⇒ 若你倾向动，**现在是唯一零成本窗口**。

★★ **裁 = Ａ1 的理由（实施后补记）**：奏效的证据是 §2 的**收敛链**（撞车需要"两个不同项目根 + `run` 名逐字相同"，
而后者被 `Get-UniqueRunStamp` 的**全局**抢占挡掉）⇒ 台账原文的"会撞"**不成立**；真实风险只是**隐藏前提**，而
**写明前提**正是对付"依赖别处实现"的正当手段。★ 两条改法各有**新代价**（A2 会把**一个产物碎成 N 个身份** —— 同一文件被两个
受理目录收录 = 两个 identity，撞 U-1「一个产物一个身份」；A3 **动 ns 轴** + 未登记项目 fail-closed（`dogfood` 未登记））
⇒ 均为**净负**。★ 且本项 **P3 · 零消费者** ⇒ 结构性改动与收益不成比例。

### B｜② 坐标语义：进注册表？　⇒ ★ **裁 = Ｂ1（注册表加字段）**

| 选项 | 做法 | 代价 / 收益 |
|---|---|---|
| **B1 注册表加字段** | `namespaces.yaml` 每条加 `identifier_rule` / `version_rule`（**闭集枚举** + `note`）；门禁判「`status: active` 的每条**必须**声明」 | 与 `U1#5` 同范式（**取值域已在注册表**，语义跟着走 ⇒ 一格补齐）；⚠ 判的是**登记完整性**，**不是**语义正确性（要如实标注，防"假绿灯"） |
| **B2 单立 `identity-coords.yaml`** | 新文件按 ns 映射语义 | 避免动注册表；⚠ 造出**第二份** namespace 轴（两份真值）⇒ 与"不造第二份真值"冲突 |
| **B3 不做** | prose 表（§1.3）继续当唯一真值 | 零改动；"每处各自拼三元组"照旧（新 namespace 不会被轨道逼着定语义） |

⚠ **不论 A 选哪条**，B1 都要顺带**把 §1.3 的 prose 表改成指针**（否则同一个语义两处表达 = 本仓头号形态）。
⚠ **B1 的字段取值不得新铸**：七个出处（Open_Data 源+维度+日期 / Macro_Data `full_url` / factor_pipeline `id` /
Auto_Prover `normalized` / Fin_Agent `text` / Textbook code+statement+… / inbox 相对路径）**已在 §1.3 表里**，
只是**转写成结构**，不是发明。

  ⚠ 首稿写的"改成指针"**被执行成"指针 + 溯源并存"**：那张表是"为何 JSON 数组坐标对所有出处都无损"的**论据**，
