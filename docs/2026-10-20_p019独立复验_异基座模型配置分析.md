## 2. 为什么**本地模型**不可用（两条**互相独立**的理由，任一条即足以否决）

**(理由一) 卡的硬令：只能在主控跑。**
卡 §头部 note 与 §0.1 逐字「执行面：Windows 10 主控机，仓库 `F:\Full_Weather`；**不要**在 A/B/C Linux 站执行」，
理由也给了：**Dynare / Octave 与 `F:` 盘仅主控可用**。⇒ 任务本体**必须**落在主控。

**(理由二) RPC 的"本地档"站位**全在站上** —— 结构如此，不是配置问题。**
**E1**（`ops/station-bin/agent-cli.ps1` 的 `$Script:ROUTE_TABLE`）：

| 别名 | `id` | `station` |
|---|---|---|
| `gpt-oss-c` | `local/gpt-oss` | **C** |
| `nemotron-c` | `local/nemotron` | **C** |
| `m27-q4ks` / `-a` / `-b` | `local/m27-q4ks` | **C / A / B** |
| `flash-next` / `-a` / `-b` | `local/qwen3.8-flash-next` | **C / A / B** |

⇒ ★ **没有任何一条 `local/*` 路的 `station` 是空的** ⇒ D6 派发**必然** ssh 到站上跑 ⇒ **撞卡的硬令**。
★ 另有一条**独立**的否决：claude 通道 + `local/*` id 会被**显式拒**（`REJECT claude-station-egress-local-id`

> **结论**：本任务的**模型选择自由度**只有一维 —— **"主控本地能到达的模型"**。而主控本地能到达的，只有下面 §3 那一路。

### (B) ⚠「`cli: opencode` 在主控不可满足」（**E2 实测**）

- 卡 front-matter 逐字 `cli: opencode`；而卡 §0.1 又要求"**不要**在 A/B/C 站执行"。
- **实测**：主控 `Get-Command opencode` = **无**；`%USERPROFILE%\.config\opencode\opencode.jsonc` = **schema-only(50 B)**。
  ⇒ ★ **"主控 + opencode"这一组合在本机不存在** ⇒ 卡的该字段**自相矛盾**（要么改 `cli: claude`，要么承认走手工且需自备 opencode）。
- **另一条**（口径面）：即便不改卡，RPC 也会**按 `route.cli` 覆盖**成 `claude`（L2484）⇒ ★ **"卡说 opencode、实跑 claude"** = 口径不一致
  ⇒ 建议**显式 `--cli claude`** + **就地更正卡片**（改的是 `F:\Full_Weather` 的卡，**不动 RPC**）。

### (C) ★★「`readonly: true` ⟂ 必须写 `out/`」（**E1**）

- 卡 front-matter 写 `readonly: true`；卡 §0.1 同时**允许**"在 `out/` 下创建证据与报告"；卡 §4 **强制**产出
  `out/verdict.json` + `out/independent-verification.md` + `out/evidence/` **24 个文件**。
- RPC 侧实现逐字（`agent-cli.ps1` **L4807**）：
  `$pmArg = if ($readonly) { '' } else { ' --permission-mode acceptEdits' }`
  （同处 4804 注释：「产物型任务(readonly=$false)需要写 ⇒ `--permission-mode acceptEdits`」）
  ⇒ ★ **`readonly: true` ⇒ 不授权写** ⇒ **产不出卡自己要求的产物**。
- ★★ **注意**：RPC 的 `readonly` **不是**"不许改 tracked 文件"的含义 —— 它在 RPC 里的语义是
  「**站上 flock 取共享锁（`-s`）+ 不授权编辑**」（L3035-3039 / L4804-4807）。⇒ **两个同名但不同域的语义**，
  正是本仓 `ADR-0006 D4`「判据的射程与口径必须一致」点名要防的形态。
- **两条出路（供 `F:\Full_Weather` 那边裁）**：
  - **(甲) 卡改 `readonly: false`** —— 由卡的**人为约束**（§0.1「不得修改 tracked 文件」+ §5.4 结束时的
    `git status --porcelain` **终检**）+ 审计员自己的纪律兜住"只读写 out/"；代价 = **闸从结构面降级到纪律面**。
  - **(乙) 走 §5 路② 手工执行**（权限自管）⇒ **不动卡**、不撞 `$pmArg`。★ 若卡**必须**保持 `readonly: true`，这是唯一自洽解。

### (D) ⚠「别用默认出网档」（**E1**，与 §3 同一件事，但值得单列 —— 它是**最容易踩**的那一脚）
