## 2. 为什么**本地模型**不可用（两条**互相独立**的理由，任一条即足以否决）

**(理由一) 卡的硬令：只能在主控跑。**

理由也给了：**Dynare / Octave 与 `F:` 盘仅主控可用**。⇒ 任务本体**必须**落在主控。

**(理由二) RPC 的"本地档"站位**全在站上** —— 结构如此，不是配置问题。**
**E1**（`ops/station-bin/agent-cli.ps1` 的 `$Script:ROUTE_TABLE`）：

| 别名 | `id` | `station` |
|---|---|---|
| `gpt-oss-c` | `local/gpt-oss` | **C** |
| `nemotron-c` | `local/nemotron` | **C** |
| `m27-q4ks` / `-a` / `-b` | `local/m27-q4ks` | **C / A / B** |
| `flash-next` / `-a` / `-b` | `local/qwen3.8-flash-next` | **C / A / B** |

⇒ ★ **没有任何一条 `local/*` 路的 `station` 是空的** ⇒ D6 派发**必然** ssh 到站上跑 ⇒ **撞卡的硬令**。

## 10. (C) 的调研与解决方案：**RPC 的 `readonly` 与「审计 / 复验类任务」之间的语义缺口**

### 10.1 机制（**逐字，E1**）

`ops/station-bin/agent-cli.ps1` **L4803-4807**（claude 通道 `-p` 的权限开关）：

```
# O-42 (2026-09-24): claude 通道 `-p` 的权限开关。`settings.json` 的 `defaultMode` 在 `-p` 下**不生效**,
#   须 CLI 显式传。产物型任务(readonly=$false)需要写 ⇒ `--permission-mode acceptEdits`;
#   `readonly: true` 的卡**不加**(保持只读 —— 破卡面契约 = D-06/D-07 同级安全面)。
#   空串时 argStr 不变(向后兼容)。正反注入见 _fm_golden_test.ps1 的 O-42 段。
$pmArg = if ($readonly) { '' } else { ' --permission-mode acceptEdits' }
```

两处 argv 拼装都带它：**站上** `Invoke-ClaudeFly-Station … (-p "" --model "<alias>" + $pmArg)`（L4813）·
**主控本地** `Invoke-ClaudeFly … (-p "" --model "<id>" + $pmArg)`（L4815）⇒ ★ **两条路同一条规则**。

### 10.2 为什么这不是"忘了一个开关"—— **它是刻意的安全面**

L4805 后半句逐字：**「`readonly: true` 的卡**不加**(保持只读 —— **破卡面契约 = D-06/D-07 同级安全面**)」**
⇒ ★ **"`readonly` 卡不许写"是被当成与 D-06/D-07 同级的安全不变量立起来的** ⇒ 因此本仓纪律下
**不许"顺手放开"** ⇒ 要动它**必须**：**先验红 + 夹具 + 独立裁定**（同 `O-143` 两步走；也正是 `O-147` ④ / `R7` 那一类的处理方式）。

### 10.3 ★ 加重的一条（**本轮新读出**）：受影响的不只是"写 `out/`"，而是**"能不能跑起来"**

L4803 前半句逐字：**「`settings.json` 的 `defaultMode` 在 `-p` 下**不生效**，须 CLI 显式传」**
⇒ 不传 `--permission-mode` ⇒ 走 claude 的默认模式 ⇒ 在 `-p`（**非交互**）下，**需批准的动作会被拒**（无人可批准）。
★ 而本卡 §3 的执行协议**全是 bash**（`$PY - <<'PY'` · `"$OCT" --eval …` · `… | tee out/evidence/x.txt`）⇒
★★ **`readonly: true` 下，连 Bash 都可能跑不了** ⇒ **不只是"写不进 `out/`"，而是"卡跑不起来"**
⇒ 性质从"**P1 口径冲突**"升格为 **"结构性不可行"**。
⚠ **诚实边界**：这一句是**读码 + `-p` 的已知行为**推出的（E1），**未做一次专门的 readonly 卡实测**
⇒ 若要钉死，需一次小代价实测（**造一张 `readonly: true` 的探针卡，看 Bash 是否被拒**）。

### 10.4 三条方案 + 一个被否项

| **(甲)** | **卡侧** `readonly: false`（并把"**不得改 tracked 文件**"作为**卡内人为约束**保留） | **零**（RPC 一行不改） | 立刻可跑；RPC 侧自然传 `acceptEdits` | ★ **结构闸降级为纪律面**（本仓最不喜欢的形态）；兜底只剩：卡 §0.1 硬边界 + **§5.4 结束时 `git status --porcelain` 只显示 `out/` 下未跟踪文件**（★ 这条**本身可机检**，是本方案唯一的硬残留）+ §6 禁项 |

### 12.0 为什么方案Ⅲ "最简单但浪费"—— ★ 它错过的不是算力，是**独立性的可机判面**

方案Ⅲ 把审计变成一个**孤立的**手工会话：**零 RPC 留痕、零证据链、零跨族判据、零多站**。
本卡最贵的那一条约束（§0.2 异基座 / §0.5 不采信产出方）**只在文字里**，靠审计员**自我声明**。
⇒ ★★ 而 RPC 的真实价值恰恰是：**把"独立"从【声明】变成【可机判的留痕与判据】**。

### 12.1 ★★ 一条**结构性事实**（它决定了分工怎么切）

⇒ ★★ **分工必须按"谁能在哪台机器做哪些事"切**（而不是按任务大小切）：

### 13.7 坑（逐条，都是本仓踩过或读码可判的）

1. **模型名必须用【未识别名】**（`qwen3.8-flash-next`）—— 用 `claude-*` 会触发 Anthropic thinking 格式（站上用 `model="gpt-oss-120b"` 正是为绕开它）。
2. **`CLAUDE_CODE_MAX_CONTEXT_TOKENS` 必须按真实 `n_ctx − 4096`**（L5470-5474 的自对齐），否则 auto-compact 阈值失真。
3. **隧道端口别用 8080**；`ssh -fN` 后台，用完 `kill`（`Get-Process ssh` 或记 PID）。
4. **引擎是共享资源**（`O-18` 跨站各 1）：审计期间别让别的派发抢同一站；**不要并发 load**。
5. ★ **`cluster.py load` 没有 `--help`**（本轮实测：`load --help` 把 `--help` 当别名 ⇒ 路由到 B 站并发起加载，rc=1「无匹配 '--help'」；**未改变任何状态**）。格式 = `load <alias前缀> [--backend unsloth|llama-rpc|llama-single|vllm|ds4] [--engine <变体>]`。
6. **88G 权重加载 60–90s**（`O-136`）；期间 `status` 显示 `STOPPED` 是正常的（还没起来）。

> ★ **一句话**：**这套形态是"主控当审计员、站上当大脑"** —— 执行面留在唯一具备
> Octave / Dynare / pandas / `F:` 盘的主控；**推理面**换成站上异基座引擎（qwen），
> 并把 `/props` 的权重身份写进证据 ⇒ **异基座从"声明"变成"可复核"**。
