## 2. DwarfStar (ds4) 部署方案（版本控制 + 管理）

### 2.1 定位（归因修正后）

llama.cpp RPC 层分布（Vulkan）为**当前首选**（今日已三站跑通 V4-Flash 7.9 t/s）。DwarfStar 是 **GLM-5.3-Flash 的唯一可行路线**（llama.cpp 不支持 glm5next；vLLM sm_121 有输出 bug）+ V4-Flash ROCm 性能增强选项（社区 19-32 t/s）。

**主用路线**：GLM-5.3-Flash 三站 PP 层切片（官方向导 + kyuz0 toolbox coordinator+workers）。
**增强路线**：V4-Flash 走 ds4 ROCm（若需超越 llama.cpp Vulkan 7.9 t/s）。

### 2.2 版本控制目标（解决当前"散置无清单"问题）

| 原则 | 具体 |
|---|---|
| **单一受管路径** | 全部 ds4 构建归位 `/data/llm/ds4/`（而非散置 ~/）；`/opt/ds4` 软链指向现役版本（复用 /opt 管理范式） |
| **构建目录即版本目录** | `/data/llm/ds4/ds4-<commit7>`（如 `ds4-glm53f-xxxxxxx`），构建完成即锁定目录名 |
| **MANIFEST 强制** | 每版本目录内置 `MANIFEST`（md5 ./build 二进制 + lib），复制 `/opt` 校验范式；升级前重建清单 |
| **软链切换** | `/opt/ds4 -> /data/llm/ds4/ds4-<act>`；切换 = 改软链（回滚秒级） |
| **上游锁定** | 记录 fork URL + commit hash + 依赖（ROCm 版本）。DwarfStar 官方 + wkljohn TP fork 分开管理 |
| **C 站约束** | C 站保持 `~/.unsloth/llama.cpp` 不动（unsloth 受管）；ds4 新构建不触碰该路径 |

### 2.3 环境前提检查（对齐 survey §3）

- [ ] 内核参数：`amdgpu.gttsize=126976` + `amd_iommu=off`（A/B/C 三站 GRUB；C 站 ROCm 7.2.1 用户态已备）

### 4.7 GLM-5.3-Flash 双机 PP 速度评估（2026-09-09 补）⚡

> 用户询问"ds4 双机 PP 跑 GLM-5.3-Flash 速度怎么样"，以下为综合官方基准 + 社区 survey 的速度结论。**注意：均为推算值，集群 ROCm 实测尚未做过。**

#### 4.7.1 关键前提：PP 不加速 decode

官方 PERFORMANCE.md 原话：**PP 为容量 + 长 prefill 设计，单条生成流无法叠加加速**（"A single generation stream cannot use that overlap"）。→ 双机 PP 的 decode 速度 ≈ 单站速度，只解决"178G 放不进 128G"的**容量问题**。

#### 4.7.2 速度数据（多口径）

| 口径 | prefill | generation | 备注 |
|---|---|---|---|
| 官方 SSD 实测（M5 Max 128G）GLM-5.3-Flash Q4_K 177.77G | 121→104 t/s | **11.9 / 14.9 t/s** | SSD streaming，非双机 PP |
| 社区 Strix Halo ROCm 单站 ds4 | — | **6.7-32 t/s**（survey 区间） | 同构硬件参考 |
| 集群对照：llama.cpp 双机 RPC V4-Flash | — | 9.1-9.2 t/s（2026-09-09 实测） | 同硬件参照系 |

#### 4.7.3 双机 PP 预期

- **decode**：~**10-20 t/s** 区间（社区 Strix Halo 上沿），**不会因 PP 翻倍**
- **prefill**：PP 对长 prefill 有真实收益（流水线重叠），官方 Q4 档 121/104 t/s 为参考上界
- **档位**：`glm53-q2`（90G）单 128G 机即够、**无需双机**；`glm53-q4`（178G）才需双机 PP
- **MTP 加成**：官方 11.9-14.9 t/s 为**未开 MTP 裸速**，ds4 内置 MTP 投机解码（`--mtp`）还有提升空间

#### 4.7.4 路线对比（decode）

| 方案 | decode 预期 |
|---|---|
| llama.cpp RPC（等 #28047 修复后） | 6-9 t/s（继承 V4-Flash HC 慢路径） |
| **ds4 双机 PP** | **10-20 t/s** + MTP 投机 → 约快 2 倍 |

**结论**：ds4 双机 PP 跑 GLM-5.3-Flash decode 预期 **10-20 t/s**，主要收益是容量（178G 双机可跑）而非 decode 加速；社区 Strix Halo 上沿 32 t/s 为理想情形。落地仍需先构建 ds4（工具链前提 §4.2）+ 单站验证。
