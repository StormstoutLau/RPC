### 批次 A — STATE 结构化 + LOG（①①）

| 项 | 内容 |

| 改动 | `40_state/STATE` 单行文本 → **`STATE.json`**（`{"state":"…","updated_at":"…","by":"admin"}`）+ **`40_state/LOG.md`**（追加式变更记录：时间/新状态/理由/by） |

### 批次 B — 状态机扩展：waiting + 协商回环 + 验收签收（①② + ②#1/#2）

| 项 | 内容 |
|---|---|
| 新状态机 | `open → triage ⇄ waiting → accepted → plan-review ⇄ plan-revise → running → release → done → accepted-by-requester / rejected-by-requester`；`rejected` 可从 triage/accepted/plan-review/plan-revise 任一进入；需求方验收不通过 → 回 `plan-revise`（修订重跑）或 `rejected-by-requester`（终止，后续新需求开新 open） |
| 状态语义 | `waiting`（等需求方补充/外部条件，区别于 triage 主动处理）；`plan-review`（方案已交需求方复核，等回复）；`plan-revise`（收到意见，管理员修订 `20_plan` + 更新 `10_admin/`）；`release`（执行完毕，交付证据束，等需求方验收）；`accepted-by-requester`/`rejected-by-requester`（验收签收终态） |
| 复核产物 | `10_admin/复核意见-N.md`（N=轮次）；`20_plan` 修订留版本（文件名带 `vN` 或 LOG 记录） |
| 落点 | `inbox/README.md` §2/§3；`inbox/_template/10_admin/`（复核意见-N.md 模板）；`inbox/_template/40_state/`（合法取值表更新）；`inbox/paper-2026-08-23/40_state/STATE.json`（现状 open → waiting：卡等 CR-1/CR-5 裁定，LOG 记理由） |
| 验收判据 | README 状态机图含全部新状态 + 回环路径；模板含复核意见-N.md；paper 状态迁移为 waiting 且 LOG 有理由 |

### 批次 D — 交付证据束（①⑥ + ②#3-7）

| 项 | 内容 |
|---|---|
| 30_evidence 链死 | 结案时把 `agent-out/<ts>/` 的 `run.json`（含 `evidence_manifest`）+ 单 run 证据束哈希，以 **`30_evidence/MANIFEST.sha256`** 钉死（同 00_handoff 方案 B 格式）；**未附证据束不 `done`** |
