## 3. 载体三选项（`subject` 声明放哪）

### 选项①（**建议**）：声明在**分片卡** —— 主卡 `decompose:` 条目携带 `subject=<X>`

```yaml
# 主卡（既有语法，附加式）
decompose:
  - subject=路由层 | 分析 router 层的数据流并给结论
  - subject=缓存层 | 分析 cache 层的数据流并给结论
  - 分析日志格式（← 无 subject ⇒ 该片计「未声明」）
```

- split 生成分片卡时：解析前缀 ⇒ ① 在**分片卡 front-matter** 写 `d7-subject: <X>`（机器读点）；② 在【分片约束】段**追加一句**要求产物含 `SUBJECT: <X>` 行（**进提示词、不进 accept** —— 不赌 LLM 输出格式）。
- join 的输入 = split **自己生成的**分片卡（100% 可控）。
- **优点**：零 LLM 依赖 · **零解析器改动**（前缀解析在 split 侧新纯函数里）· 存量卡零影响（无前缀 ⇒ `undeclared`）· 单一定义点。
- **缺点**：声明者是**卡作者**而非"片自己" ⇒ 与 §6.2-3 字面有差异（§3.4 reconcile）。

### 选项②：片**产物自述**（`SUBJECT: <X>` 行落在 `out/*` 或 agent-output），master 从各片 runDir 读

- **优点**：严格贴合 §6.2-3 字面（"片在交付产物里声明"）。
- **缺点**：① **依赖 LLM 输出合规** ⇒ 不填 = 静默回到 #6 原病（本仓最防形态）；② split 现**只取子进程日志**、未记录各片 runDir ⇒ 要新拉一条链路（面更大）；③ 若再靠 accept 强制 ⇒ 改验收面（份额外治理）。
- **判定**：**不作首发**；列为**条件触发**（若日后要求"片自述"，在其上追加即可 —— 与选项①不互斥）。

### 选项③：主卡新开平行列表 `decompose-subjects:`

- **优点**：解析简单。
- **缺点**：**两个平行列表 = drift 风险**（本仓头号形态"同一事实两处表达"）+ 校验复杂度（长度对齐 / 顺序对齐）—— 净负分。
- **判定**：**否**。

### 3.4 reconcile（**必读，防"默默改射程"**）

§6.2-3 逐字「每片须在**交付产物里**显式声明 `subject`」 = **原文理想形态**；选项① 的映射 = **分片卡携带声明**。
同形先例 = `O-145`（"本仓映射到既有载体"须**明写**；当时由**用户裁**）。
⇒ 本方案**提请确认**：按选项① 落（**并写进契约 §6 作"本仓映射"段**，`O-145` 同款），还是要求选项②（片产物自述）。
