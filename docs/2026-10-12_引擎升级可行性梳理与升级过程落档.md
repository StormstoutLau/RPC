## 2. 两个工作负载的升级可行性

### 2.1 DS-V4-Flash-0731（分布式）

- **现役**：`91f6a6cf` + `-sm layer` + `RPC_TARGET=10.10.10.1:50052`（**head=B 本地 Vulkan0 + 1 个 RPC worker，N=2**）。
- **实测基线（E1，2026-10-11）**：`-sm layer` decode **13.89 t/s**（13.81/13.89/13.89），对照 E2（9/10）**14.02** 属噪声内；固定 prompt ×5 输出逐次互异、无重复乱码。
- **升级收益面（候选 commit 含，现役不含）**：
  - **#26610** = `async graph_compute` + `COMM_ALLREDUCE` + **LRU graph cache** + **2D 传输** ⇒ ★ **`-sm layer` 同样受益**（A2 实测 layer 档每 token **38.7 命令 / 903 KB**，正是该 PR 的靶子，见 [metrics-log 附加试验 A2](../spec/rpc-optimization/metrics-log.md)）；
  - Vulkan/MoE 面：#29998（`mul_mat_id` prepass）、#29887 / #30112（MoE experts host-RAM 缓存 / 多 GPU）、#30049（AMD iGPU checkpoint 读取慢）、#29988 / #30145（Vulkan 长 ctx 稳定性）、#30003 / #29934 → **模型是大 MoE + Vulkan + 长 ctx，条目命中率高**；
  - #29749（direct-io 免第二份全尺寸张量拷贝）→ 与 **UMA 预算**直接相关。
- **阻断项（已判）**：**`-sm tensor` = No-Go**（见 §3 时间线）⇒ 升级时**必须显式维持 `-sm layer`**（现役 conf 本就在 layer 档，无需改）。
- ★ **唯一缺口**：**"新引擎 + `-sm layer`"从未验证**。本轮 S4 只验了 tensor 形态；S1 基线跑的是**旧**引擎。⇒ **这是决定 DS-V4 分布式能否升级的最后一个未知数**。

### 2.2 GLM-5.3-Flash（分布式）—— ⛔ 换档门未过

- **现役**：变体引擎 `glm5next-20260928`（conf **钉死** `LLAMA_SERVER_BIN` + `LLAMA_RPC_SERVER_BIN`），`RPC_TARGET=auto`，`EXTRA_FLAGS="-fa on "`。
- **为什么不能简单升**：**"升级主线" ≠ 换 flag，而是"换引擎 + 换一份 GGUF"**（E1/E2）：
  1. 我们的档 arch 串 = **`glm5next`**；主线注册 = **`glm5-next`（带连字符）** ⇒ **主线拒载**（实测报 `unknown model architecture: 'glm5next'`；[cluster_const.py](../ops/cluster_const.py) 同证）；
  2. 官方 Q2 档 arch 虽对，但**张量是 ds4 命名（`kda_*`）** ⇒ 过 arch 门、**过不了张量门** ⇒ **无现成免费档**，须自转或重下（受 **>50GB 下载闸**，走 `lm-download@` 分段）；
  3. 新档须实测**张量绑定**（#27773 引入 `llama-memory-hybrid-idx` / `llama-kv-cells.h`，与 unsloth 实现**非同一份代码** ⇒ 改 arch 串 patch **不可靠**）。
- **升级收益面**：主线含 **#29928（GLM5Next MTP，10-07 合并）** + **#29745（indexer scatter data race 修）** —— 后者是**稳定性**收益（我们的稀疏 indexer 是活跃路径，ctx>2051 即启用，我们跑 32K）。
- **升级风险面（上游仍 open）**：**#30093**（`glm5-next` + `--spec-type draft-dflash` **首个请求即 abort**，`GGML_ASSERT(t_layer_…`）· **#28360**（GLM-5.3 的 **RPC issue**，报告者第二台机器 = **gfx1151 同架构**）· #30268（open，input layer embeddings）。
- **另有一条架构级结论（E3，§1.7③）**：GLM 的混合架构（KDA 线性注意力 + NoPE MLA + 池化 indexer + ×4 mHC）**天然不适合张量切分** ⇒ **GLM 只能走 `-sm layer`**，`-sm tensor` 对其无意义。
- ⇒ **判定：暂不启动**。前置 = ① 上游 #30093/#28360 收敛；② 拿到 arch=`glm5-next` 且张量非 ds4 命名的档；③ 一次升级窗口。

### 2.3 单站引擎 —— ★ 分 A / B 两轴，结论不同（2026-10-12 判定）

#### A. studio bundled `~/.unsloth/llama.cpp`（HIP/ROCm）—— ⛔ **不必要升级**

- **现役（E1，`cluster.py studio status`）**：`0.3.0-dev (b10715, 92cedc867)` · 设备 **`ROCm0`** · Clang 23.0.0 · md5 `31d8787b…` · **三站逐字节同版**；
  marker `backend: rocm` / asset `…linux-x64-rocm-gfx1151.tar.gz`；pin `UNSLOTH_LLAMA_CPP_BACKEND=rocm` 三站生效；studio `2026.9.7` + `X-Unsloth-Events` 修复在位。
- **不升级的四条理由（均有据）**：
  1. **无收益机制（已被本仓实测否掉）**：2026-09-22 那轮升级的净收益 = **控制帧移除 + 压缩路径恢复**，**不在引擎**；
     且 [决策简报 §8.4](2026-09-22_决策简报_unsloth-studio升级方案.md) **明确实测「升级不含吞吐提升」**（引擎同二进制同参数，无机制）。
  2. **硬阻断**：引擎升级需拉 **337.4 MiB `rocm-gfx1151` bundle**；**C 站无可行通路**（`github.com` 直连不通，借 B 的 SOCKS 实测 107 KB/s ⇒ 约 55 min）。
  3. **`studio update` 无跳过引擎的开关**，且**强制重做硬件探测**（A 站曾因此从 `ROCm0` 被换成 Vulkan-only，报 `invalid device: ROCm0`）—— pin 只保后端、**不保版本**。
  4. **会破坏被门禁守护的形态**：三站引擎**逐字节同版 + 可站间 tar 复原**（`backend` 判据 (h)）；升级须三站同步推 `b11030` 并另立回滚点。
- **现役需求已被覆盖**：单站线模型（gpt-oss-20b / m27 等）在 `b10715` + `ROCm0` 上端到端冒烟通过（[简报 §7.7/§8.6](2026-09-22_决策简报_unsloth-studio升级方案.md) 实测 `READY ✓ :8080`）。
- ★ **触发条件（何时才"有必要"）**：① 出现**具体痛点**（某单站别名在 `b10715` 上崩溃/精度异常且有对应上游修复）；或 ② **先做 `b10715 vs b11030` 同机 A/B** 且收益显著。前置：修 GitHub 通路 · **三站先各自备份引擎目录**（⚠ 现状**仅 A 有** `llama.cpp.vulkan-b11030-20260922`，**B/C 无备份**）· 保持 pin · 三站一次同步 + 门禁。

#### B. `~/llama.cpp/build/bin`（Vulkan，`llama-single`）—— ★ **不建议"升级"，建议"收敛/退役"**

- **现役**：`0d18aaa`（2026-05-26），Vulkan（**无 hip**），仅 **2 个** `llama-single` 别名使用（qwen3.8-27b-mtp · davidau-q38-27b-q4k）。
- **它的问题不是"旧"，是"无治理 + 不一致"**：① **三站不一致**（C 站 bin 27 文件 vs B/A 122；构建时间 5/27·9/06·9/08）② **无 MANIFEST / 无版本化 / 无门禁覆盖** ③ 出处存疑（git HEAD 2026-05-26，但二进制具备 8 月才合入的 `--spec-type draft-mtp` ⇒ 版本串与产物不自洽）。
- **正解 = 收敛而非升级**：`/opt/llama.cpp`（**已升 `23b0202a`**）是它的**功能超集**（同 cmake 开关；`--help` 覆盖 `spec-type / draft-mtp / mmproj` 全部），且有 MANIFEST + 门禁 + 回滚。
  ⇒ 建议把那 2 个别名的 `BACKEND`/`LLAMA_SERVER_BIN` 改指 `/opt/llama.cpp`，**让这条轴消失**（符合"加法→减法"）；实施前须做一次等价性冒烟（mmproj + `--device Vulkan0`）。
  ★★ **2026-10-12 已执行完毕（方案①）**：conf 归位 `/opt` · 三站目录已删 · 等价性冒烟 + 删轴后复验 **PASS** ⇒ 见 [单站引擎轴不一致调研与统一方案](2026-10-12_单站引擎轴不一致调研与统一方案.md) §5。
