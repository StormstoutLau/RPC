## 3. ★★ 更直接的证据：**我们的错误史正好落在它的"形态学三类"里**

`ASSERTION_EVIDENCE_FRAMEWORK.md` §2.1 归纳了三类错误形态（E1）。**用本会话的四个真实实例去对**：

| 它的形态 | 定义 | 本会话的实例（E1） |
|---|---|---|
| **I 无据断言** | 全部可核查来源**零命中**仍写出 | "Open_Data / Auto_Prover 的**存储不在本机**（扫描均为空）" ⇒ 我**没搜到**就断言**不存在** |

★★ **这张表比任何类比都硬**：它说明**我们不是"可能会犯这些错"，而是"已经犯了，且分布一致"**。
⇒ 它的拦截手段（生成期证据强制 / 机械枚举 / 机械反证探针）**对我们适用**，不需要先证明。

**形态 III 无法被"要求给链接"拦住**（两处引用都真实且正确，错在综合跳步）——

⇒ 拦截它**不能**靠"每句话都带证据"，**必须靠机械反证或异构第二视角**（§3.3 / §3.6）。

## 4. 可吸收的（按优先级）

### 4.1 【P0】`gate` + `--require-gate`：把"流程"从纪律变成**前置条件**

**我们现状（E1，`ops/station-bin/agent-cli.ps1`）** —— 派发路径 `Invoke-Task`(:1634) / `Invoke-SplitTask`(:2940) /
`Invoke-Task-Claude`(:3132) / `Invoke-ClaudeFly`(:3728) / `Invoke-BatchTask`(:4417) 的前置**全是资源层**：

| 已有前置 | 性质 |
|---|---|
| `Invoke-StationReady` · `Invoke-SlotGate` · `Assert-AgentOutWritable` · `Enter-WorkspaceLease` · `Test-CardSafetyDeclared` | **资源 / 安全**前置 |

⇒ ★ **缺口精确地说**：**有"资源前置"，没有"流程前置"** ——
没有任何机制表达"**这道门禁没过，就不要启动这次派发**"。
这正是 Scott 那句话要的东西：**"每个 agent cli 都遵守特定流程"**。

**可借形态**：`rpc_check` 已经是"**命令 + exit code**"形状 ⇒ 天然可当被调门禁；
`.agent-run.json` + 证据链**已经存在** ⇒ 天然可承载"这道门禁在**这个内容**上过了"的记录。
⇒ 增量 = 一个**前置断言** + 一个**绑定**。

⚠⚠ **但必须改写后借（今天刚学到的）**：`Spec_Runner` 的 verdict = **exit code 机械映射**，
而 **O-89 证明 exit code 单独不够**（`test_rpc_check_u1.py` exit 0、**零断言执行**、门禁报 PASS）。
⇒ 我们版 `--require-gate` 必须叠加**我们自己**的判据：**门禁必须有汇总行 / 报数**，
否则 `--require-gate` 会把**假绿**从"一次失误"升级成"**流程的一部分**"（这比不借更糟）。

⚠ 第二个必须叠的：门禁结论要**绑内容**（commit / 卡片指纹），否则"上次过了"会被当成"现在过了"
（同族：O-81 的真值源 / mirror 的计数对账）。

### 4.2 【P0】断言分级 A/B/C + "假设区禁止进正文"

**我们现状**：`spec/` 与 `docs/` 的调研文档**没有**断言分级；**已有**的近似物 = "未实测登记"节（≈假设区）
+ "证据等级 E1-E5"（在 Ds 分析里）+ "置信度"。
⇒ ★ 缺的那一半是：**"无证据的断言不得出现在正文结论里"** ——
我们现在**允许**无证据断言进正文（"未实测登记"只是列出来，**不禁止**上面已经断言）。

**可借的三条最小规则**（不做全量分级）：
1. **阻断性断言（会传导进 spec/实现的）必须 ≥2 独立来源**，否则标 `[单源-待二核]`；
2. **A 类（版本号 / 计数 / 路径存在性）必须带"可 grep 的取证形式"**（不是 URL，而是**命令 + 输出**）；
3. **假设与正文严格分离**：无证据断言**只能**进"未实测/假设"节，**不得**出现在结论句中。

★ 理由（不是抄它的口味）：本会话**三条错**全部是 2 的违反（计数/存在性凭印象），
而 1 与 3 是**成本最低**的两条（不需要新工具，只需要写的时候多一句）。

### 4.3 【P1】B 类机械反证探针（**探针优先于 LLM**）

它的对照表（E1，§4.2）按 **op 类型**给探针：`equivalence`（调用/赋值 grep）·
**`existence`（否定搜索：列候选 → 全量 grep → 零命中才维持）** · **`counting`（枚举再数，非记忆）** ·
`transitivity`（import/调用链追踪）· `cross_library`（同输入数值 diff）· `causal`（反事实对照，**无机械探针**）。

★ **对我们最划算的两类**：`existence` 与 `counting` —— 因为**我们各已经有一次真实事故**（§2 的 A 与 B）。
而且这两类**探针就是脚本**（零 LLM、零幻觉），与 `id_site_census.py` / `id_storage_census.py` **同构**。
⇒ 落点 = 把这两类做成**可调用的探针**（而不是新写一份方法论）。

### 4.4 【P1】E1-E5 证据分级 + **"E5 禁入结论"**

我们**已有** E1-E5 的定义；缺的是那条**禁令**：**推测级证据（E5）禁止出现在结论中，只能进"未覆盖项"**。
⇒ 这是一句话的规则，但能拦住一整类"看起来有依据"的句子。
⚠ 我们已有同族判据（`evidence` 门禁的 A1/A2/A3 + 可重放缺口），**可复用其分档**，不新增第二套分级。

### 4.5 【P1】`Spec_Runner` 的两处工程形态（**机制**，不是规则）

1. **append-only 事件流 + `state = 事件流的派生视图`** —— 与我们**证据链**同构（246 条 / `cluster.py agent`）；
   ★ 可借的是它那句明写：**"重放校验 = seq 单调 + 每行可解析"**（把"流没坏"变成可判）。
2. **两端单点把守**："schema 违规 / seq 非递增在**写入器**抛错拒绝落盘" ——
   ⇒ 借法：**在写入侧拒绝坏数据**，而不是事后 lint（我们已有部分：`.agent-run.json` 的回退要显式标 `src=log`，O-81）。

### 4.6 【P2】双盲重推导 + `STEP_GAP` 两态

**形态 III 的唯一有效拦截**（§3 的盲区）：剥离原推理、只给源与命题，让**未见原报告**的 agent 重推，
再比"**结论**"与"**步数差**"（差额步 = 跳步藏身处；两态 `CLOSED`/`OPEN`，禁止悬空）。
⚠ 成本最高（一次重推 + 一次仲裁），且需要**异构基座**（我们已有跨家族引擎 + judge 校准可复用）。
⇒ 列 P2：**先在有"阻断性 B 类断言"的场景用**，不要全量。

⇒ **结论 1**：**不是"能不能引入"，而是"已经引入了大部分，只剩几块没补"**。
把它说成"引入 spec workflow"会**低估现状**，也会**重复已做过的事**（本仓头号形态）。

### 8.2 这条路**唯一的硬约束**是 shell 窗口 + 采集面

- 站上 agent 由 `timeout … opencode run -m "$id" < .prompt.txt > .agent-output.txt` 起（`agent-cli.ps1:2288`），
  prompt = 卡正文（:2218）；ACCEPT 在站上按 `.accept-cmds.txt` 逐条跑并置 `ACCEPT_OK`（:2341-2354），
  失败即 `FINAL_RC=9`（:2372）。
- ⇒ **硬**边界只有两个：**① ACCEPT 的 exit code ② 回收面**（`.meta` / `.prompt.txt` / `.accept-*` …）。
  卡面里的**一切纪律**（不许探索 / 不许补写 / 不许引入用户名）都是**软的**。
- ★★ **而且我们有实测反例**（不是推测）：U3 spec 的"未实测登记"第 8 条 ——
  模型**读到并把** `dogfood-cards/README.md` 里的用户名抄进了产物，**尽管卡面明写"不要探索目录"**。
  ⇒ 报账时必须写成：**写进卡面能"减少"幻觉，但拦不住**。（"减少"与"拦住"是两件事。）

### 8.3 缺口清单（按性价比排序）

#### ① 【P0 · 成本低】R7 落到"**内容里声明的计数**"

ACCEPT 现在只查"**有 ≥5 条**"，**不查正文自己声明的数**。
本会话已因此吃两次亏（`factor_pipeline` 18→16→21；`Auto_Prover` 114→8）。
⇒ 候选：卡面加一条规矩 —— **"正文凡写计数，必须附可 grep 的枚举命令"**；ACCEPT 加一条判据检该命令**存在于文中**。
⚠ 如实说清射程：它只能判"**有命令**"，**判不了"命令真能数出那个数"** —— 但比现在强（把**可复核性**变成必要条件）。

#### ② 【P0】流程前置（**O-90**，与 §4.1 同一件事）

派发前只有**资源前置**（`Invoke-StationReady` :354 / `Invoke-SlotGate` :398 / `Assert-AgentOutWritable` :832 /
`Enter-WorkspaceLease` :958 / `Test-CardSafetyDeclared` :1148），**没有"这道门禁没过就不要启动"**。

#### ③ 【P0 · 成本高，但**唯一能拦"形态 III"**】双盲重推导

★★ **实读到的结构事实**（E1）：judge 的提示词是

```powershell
$prompt = Build-JudgePrompt -fm $fm -product $productText -runId $runName -cardPath $card   # agent-cli.ps1:4295
```

⇒ **我们的 judge 是"带原产物 + 原卡"的评审，不是双盲**。
而 SPEC §4.3 明写：双盲是**硬条件** —— "auditor **不得接触原推理文本**，否则**锚定效应会把跳步复制一遍**"。
⇒ 这正是 §3 里**形态 III 拦不住的结构原因**：judge 看得到产物的推理，于是**同一个跳步会被它再走一遍**
（本仓头号形态"把两件事说成一件"就藏在这一格里）。
⇒ 候选：卡面**要求产物附"断言登记块"**（机读：结论 / op / 依赖源 / 推理链）+
judge 侧加 **`--blind` 模式**：**只给"卡里的输入摘要 + 该条断言"**，让它**独立重推**，
再比对 **① 结论是否一致 ② 步数差**（`STEP_GAP_CLOSED` / `_OPEN` 两态，禁止悬空）。
⚠ 成本 = 每次判 **×2 次调用** + 一个结构化产物格式；⚠ 且它**只对 B 类（推断类）断言有意义**。

#### ④ 【P1 · 软】把断言分级写进卡面 + 一条**可机判的形态**

产物每条断言带 `[A]` / `[B#ID]` / `[C]` 标注；ACCEPT 检**标注存在**且与附录 B 的 ID **对得上**（这是能 grep 的）。
⚠ 只能判**形态**，判不了"那条断言**真的是** A 类"。

### 8.4 诚实边界（必须与上面的建议同时说）

1. **卡面纪律是软的** —— 能减少、不能拦；有实测反例（§8.2）。
2. **ACCEPT 判不了内容对错** —— 它全是**形态 / 存在性**判据（`grep -q` + 计数下限）
   ⇒ 一份**形式合规但内容错**的产物**可以整份通过**。这正是形态 III 的入口。
3. **judge 非双盲**（§8.3 ③）⇒ 形态 III **结构性**拦不住，不是"还没配好"。
4. **双盲很贵**（×2 调用 + 结构化格式）⇒ 建议**只对有阻断性 B 类断言的卡**开。

### 8.5 一个顺带发现：**卡片内联的取值会随标准漂移而变旧**

实读那张卡的第 124 行仍写着 U-1 截断 **`[:16]`** —— 而它在**今天**已被裁成 **`[:32]`**（O-84）。
⚠ 卡片作为**历史输入**（记录当时被派发了什么）**不该改**；
但**它的"内联摘要"是一份标准的副本** ⇒ 标准一变，副本即旧，且**没有任何判据会报**。
★ 这与 §8.1 的结论是同一枚硬币：**把标准内联进卡面**换来了"输入自包含"（防探索），
代价是**制造了一个会静默变旧的副本**。
⇒ 候选（**未实现**，待裁）：卡面内联**必须注明取自哪个标准的哪个版本**，并**只允许引用不变量、不允许内联取值**
（取值改为"见标准 §X"）；或加一条判据扫卡片里是否出现**已废弃的取值**。
