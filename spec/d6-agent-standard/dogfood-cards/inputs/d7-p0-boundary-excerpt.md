## 一、一句话判据（D6 vs D7）

| | D6 | D7 |
|---|---|---|
| **一句话** | **单次派发的闭环** | **跨主体的复核闭环** |
| 链路 | 需求 → 受理 → **一次执行** → 证据回收 → 抽检 | **审 → 改 → 再审**（多轮）→ 结论收束 → 留痕 |
| 主体数 | **1 个执行主体**（可跨站选站，但仍是"派一次"） | **≥2 个主体**（产出方 + 复核方） |
| 终止判据 | 证据入链 + 门禁绿 | **复核方签收**（≠ 产出方自认完成） |

## 二、三条可机械判定的分界判据（建议写入 ADR）

| # | 判据 | 归 |
|---|---|---|
| **B-1** | **是否需要一个"非产出方"的主体来给结论？** | 是 ⇒ **D7** |
| **B-2** | **是否在同一产物上需要多轮往返（改完再审）？** | 是 ⇒ **D7** |
| **B-3** | **是否只是"这一次派发内部"的质量门（判官抽检、accept 判据）？** | 是 ⇒ **D6** |

> 用 B-1/B-2/B-3 复核此前"归给 D7"的 14 项，**结论全部一致**（无一项应退回 D6）：
> 它们要么需要第二个主体（权限/结论/裁决），要么需要多轮（续聊/编排），要么是跨站形态（架构/自环盲区）。

## 三、边界上的灰色地带（必须显式裁定，否则会被两边都漏掉）

| 灰色项 | 现状归属 | 建议 |
|---|---|---|
| **判官抽检（证据链断言 + judge 校准）** | D6 | **留 D6** —— 它是"单次派发内的质量门"，判官是**同侧**的（B-3）。**不得**因它"像评审"就并进 D7 |
| **受理阶段的协商回环（评审 ⇄ 修订）** | D6（已实现） | **留 D6** —— 协商发生在**管理员 ↔ 需求方**之间，是**受理阶段**的事，与"产出复核"不同层 |
| **需求方验收签收** | D6（已实现） | **留 D6，但它是 D7 的接入点**：D7 的"复核方签收"应复用同一状态语义，**不新造** |
| **跨站派发** | D6 | **留 D6** —— 跨站只是"派到哪个站"，主体仍只有 1 个 |
| **站间互审（`--peer`）** | **D7** | 确认 D7（B-1 + B-2 同时命中） |
| **异构复审编排** | **D7** | 确认 D7（缺的正是"编排层"） |
| **多轮续聊（审→改→再审）** | **D7** | 确认 D7（B-2） |
| **agent 派生边表 / 多 agent 树** | **D7** | 确认 D7 —— **但九项目实测中无一提出此需求**（无真实诉求支撑） |

**⇒ 关键裁定**：**D7 ≠ "把 D6 没做完的补完"**。D6 的剩余项全部是**事件驱动**（等限额 / 等升级窗口 / 等试点），
**没有一个因为"做不动"而被推给 D7**。**D7 是新能力，不是 D6 的尾巴。**
