## 任务描述

**背景（抽象）**：有一个研究方法仓库，它的核心教训是 —— **"判据通过了，是因为它什么都没判"**：
一条检查显示"成功"，既可能因为它真做了，也可能因为它**恒为真 / 范围为空 / 只覆盖了一部分却报整体成功**。
仓库正在为若干"能力缺口"写**设计底稿**（执行形态 + 三态处置 + 假绿清单 + 缺料）。

**你的任务 = 对下面两份设计底稿做**独立缺陷复核**（**不采信底稿的自述**）。要找的是：

1. **内部矛盾** —— 底稿里两处说法互相冲突。
2. **机械缺陷 / 可漏报点** —— 设计里某步**报"成功"但其实没做**，或**报"一致"但比对面漏了对象**。
3. **假绿清单不实 / 不全** —— 清单里某条**与设计矛盾**（其实已被拦住），或**漏掉了**最明显的一类。
4. **未加论证的断言** —— 声称"必然 / 一定 / 严格 / 零遗漏"，却没有支撑。

### 唯一产物：`out/xrev3.md`

格式固定：

- 先写一行 `## 底稿一`，再逐条写缺陷，**每条一行、以 `- ` 开头**：
  `- [等级: 高/中/低] <缺陷一句话> ｜ 依据: <引底稿原文片段，≤30 字> ｜ 修法: <一句话>`
- 再写一行 `## 底稿二`，同样逐条。
- **每一份至少 4 条**。
- 拿不准的写等级 `低`，修法处写 `不确定：<缺什么>`。
- 末尾加一节 `## 无法判断项`：你没有足够信息判定的部分，逐条说明缺什么。

## 执行形态

| 步骤 | 输入 | 输出 | 失败时怎么办 |
|------|------|------|--------------|
| 1. 校验决策完整性 | 决策对象(action/class/reason + affected) | 合法性布尔 | 拒绝执行，记录拒绝原因 |
| 2. 冻结输入快照 | changed 集合 | 只读快照引用 | 中止，回滚到步骤 0 |
| 3. 解析 affected 语义 | affected 列表 + 决策类 | {空列表/不可判定/正常列表} | 按不可判定处理 → 全量降级 |
| 4. 逐条派发重算任务 | 解析后的 affected 项 | 任务队列 | 单项失败标记，继续派发 |
| 5. 执行重算并收集结果 | 任务队列 | {成功/失败/不适用} 映射表 | 记录失败详情，不中断其余 |
| 6. 汇总与状态持久化 | 映射表 | 执行报告 + 更新后的派生状态 | 仅持久化成功项，失败保留旧态 |

## 前置校验

- **决策同源性**：决策中的 changed 必须与当前快照一致；不一致 ⇒ 拒绝，防止基于过期决策执行
- **输入冻结**：changed 集合在执行期间不可变；未冻结 ⇒ 拒绝，防止竞态导致不一致
- **affected 存在性**：决策必须包含 affected 字段（即便是空列表）；缺字段 ⇒ 拒绝，区分"空"与"无"
- **action 可执行性**：action 必须在已知执行器注册表中；未知 ⇒ 拒绝，避免静默无操作

## 失败与降级

| 结果类别 | 定义 | 必须显式区分的理由 |
|----------|------|-------------------|
| 跳过（合法） | affected 为空列表 ⇒ 无需重算 | 静默当作成功会掩盖"本应重算但未重算"的缺陷 |
| 失败（算失败） | 重算抛出异常/超时/校验不通过 | 静默吞掉会让下游读到脏数据却以为是新数据 |
| 不适用（有理由） | 依赖缺失/版本不匹配/策略显式禁用 | 混入失败会触发不必要的告警与全量降级 |

## 假绿

1. **部分覆盖当整体**：affected 10 项，9 项成功 1 项失败 → 汇总报"成功"
2. **幂等假象**：重算写入同一版本号 → 版本未变 → 误判为"已是最新"
3. **旁路缓存命中**：读到旧缓存却未校验有效性 → 返回旧值却报"重算完成"

**防假绿硬约束**：汇总仅在 **所有 affected 项均返回"成功"且版本号严格单调递增** 时才标记整体成功；否则整体标记为"部分失败"并拒绝提交新版本。

## 缺料与歧义

- 重算原子性：不确定——缺"单项重算是否支持回滚"与"多项重算是否需事务边界"
- 并发执行：不确定——缺"是否允许同一派生产物并发重算"与"冲突检测粒度"
- 幂等键设计：不确定——缺"重算请求去重键的来源与作用域"
- 资源配额：不确定——缺"单次执行的 CPU/内存/磁盘上限与超时策略"
- 观测埋点：不确定——缺"执行耗时/重试次数/降级触发的标准指标名"

## 判据定义

**(a) 确定性**：同一输入、同一环境、同一版本代码连续执行两次，所有生成物逐字节一致（SHA-256 相等）。
**(b) 幂等性**：在确定性成立前提下，第二次运行不产生任何文件系统副作用（mtime、inode、目录项均不变），或仅产生与首次运行逐字节一致的覆盖写入。

## 双跑与比较

- **快照对象**：流水线声明的所有产出路径（文件/目录树），排除临时目录。
- **第二次运行**：在**相同工作目录、相同环境变量、固定随机种子**（若代码依赖 RNG）下直接再跑一次；不要求干净环境，但需保证首次运行不留下影响二次运行的状态（如锁文件、增量缓存）。
- **比较方式**：逐文件 SHA-256；目录递归比对文件集合与每文件哈希。**不排序、不归一化换行符**——若需归一化，应在生产端固化，而非比对端妥协。

## 必须排除的噪声

| 噪声类别 | 理由 |
|---|---|
| 当前时间戳（ISO / epoch / 格式化） | 每次运行必变，与输入无关 |
| 运行 ID / UUID / ULID / 增量序号 | 进程级唯一，非输入确定 |
| 绝对路径（`/home/...`、`C:\...`、`/tmp/xyz123`） | 机器/用户/容器相关 |
| 临时目录名（`mktemp`、`tempfile.mkdtemp`） | 内核分配不可控 |
| 并发调度顺序导致的键序 / 日志行序 | 线程/进程调度非确定 |
| 环境变量 `HOSTNAME`、`USER`、`PWD`、`PATH` 顺序 | 运行上下文差异 |
| 文件系统 mtime/atime/ctime / inode | 元数据随写入时间漂移 |

## 假绿

1. **首次运行即失败/异常退出**，第二次未执行或执行路径不同 → 逐字节一致（均为空/均无产物），实则未验证正常路径。
2. **生成物被显式排除**（如 `.gitignore`、清单未列入） → 未参与比对，实则未检查。
3. **天然不可双跑的生成物**：一次性外部副作用（推送远端、发邮件、写数据库、申请证书、硬件烧录）。**必须在清单中显式标记 `determinism: n/a` 并给出理由**，禁止静默跳过。
