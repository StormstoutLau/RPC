## 任务描述

**背景（抽象）**：一个研究仓库对"**记忆面**"（长期记忆 / 笔记 / 上下文沉淀的读写通道）设了**四道门**：
写入门 / 取回门 / 晋升门 / 复用门，另加一条**授权边界**（把"私有 → 共享"那一跳挡住）。四道门各有载体，
**门是否齐全**已由一条检查项断言（报"四门齐 4/4"）。

**现在的问题**：检查项同时报出 —— 「**无门通道：本仓可控 0 条 / 引擎侧 1 条（点名：某条平铺笔记通道）**」。
即：那条通道的**闸门不在本仓库手里**（它在**引擎侧**：由外部工具直接读写，本仓库既改不了它的实现，
也无法在它上面插一个判据）⇒ 现处置 = **点名 + WARN**（**不静默**，但**也不阻断**）。

⚠ 该检查项的原始口径明确写了两条**纪律**（供你推理）：
1. 「**`gate: none` 且本仓可控 ⇒ 红**」（**私有 → 共享那一跳敞着**是最要紧的一类）；
   **引擎侧**关不掉的无门通道**只点名 + WARN**（**绝不静默**）。
2. 「⚠ **它不判什么**：不判记忆**内容**，也**验不了门的效力**」——
   别把这条检查项读成"记忆已安全"。

★ 同一检查项还有一条已登记的**结构性约束纪律**：「**隔离靠文本前缀 ⇒ 红**」（即"靠命名约定当判据"是病，
**要靠结构 contain**）。这条纪律对本题很关键：**如果我们的候选动作本质上只是给那条通道改名/加前缀，
那它就不是防护，只是把 WARN 换了个说法。**

### 你的任务：产出**执行方案**，写入 `out/hang2.md`

**格式（小节名照抄、顺序照抄）**：

1. `## 现状口径` —— 用**你自己的话**把现状与边界写清（每条一行 `- `）：
   ① 这条通道**是什么**（在不了解具体工具的前提下，给出"它可能是什么"的**最小假设集**，并标注哪几条未核）；
   ② **闸门为什么在本仓之外**（"引擎侧"意味着：谁改、改哪里、改动了算不算本仓的账）；
   ③ **现在的处置是什么**，它**保证**了什么（只说它真保证的：**不静默**），**没保证**什么。
   ⚠ 明确写清："点名 + WARN" **不等于**"已防护"。
2. `## 可做与不可做分界` —— 两栏式，每条一行 `- `：
   `事项 | 本仓可控?（可控 / 不可控 / 可观察但不可改） | 依据`。**≥6 条**。
   目的：把"我们**能**做什么"与"我们**只能**记录什么"**钉死**，防止把不可控项写成动作项。
3. `## 候选动作清单` —— **≥5 条**，每条一行：
   `动作 | 成本（低/中/高） | 收益（它让哪一类事从"不知道"变成"知道"） | 副作用 / 代价 | 它是否只是把 WARN 搬家（是/否 + 一句）`。
   必须含**至少一条"什么都不做，但把理由写下来"**的候选（该仓库的纪律："**不做也是一种结论，必须写下来**"）。
4. `## 推荐方案与理由` —— 从上面的候选里推荐**一个**（或一个组合），并给出：
   ① 为什么选它（**不要**只说"成本低"）；② 它在**哪一天会失效**（触发重审的条件）；
   ③ **反面**：如实写出"不推荐的那个候选其实也说得通"的理由（≥2 条）。
5. `## 验收判据` —— 可机判形态 ≥4 条（每条一行 `- `）：`看到 X ⇒ 判 Y`。
   至少含一条**反向**判据（"若出现 Z ⇒ **必须判不通过**"，应专门守住上面那条"靠文本前缀"的纪律）。
   另含一条**防假绿**判据（"若该判据在**对象为空**时判通过 ⇒ 不通过"）。
6. `## 不确定项` —— 你无法从上述口径判定的，逐条说明缺什么（**不许猜**）。
