## 任务描述

**背景（抽象）**：有一个**长期维护的研究方法仓库**，它的核心教训是 —— **"判据通过了，可能是因为它什么都没判"**，
以及 **"同一事实两处表达 ⇒ 迟早有一处过期"**。仓库里有一批**台账与真值表**（台账登记未决问题；
真值表登记"某类事实的单一真值"）。它们此前被查出过一类反复发作的病：**格首/段头/射程声明停在旧结论上，
而同一格的末尾已经写明新结论** ⇒ 读者按旧的那半边行动。

本批做的是**回写**（把这类滞后与读数漂移就地修正）。**你的任务 = 对下面四段回写做独立缺陷复核**
（**不采信回写的自述**，也不采信它引用的读数）。

要找的是：

1. **与所引证据相反** —— 回写声称"原文与实现相反"，但它引用的读数/规则**支持不了**这个判断。
2. **数字与被引读数不符** —— 改写后的数字**推不出**来（含"分母/分子"口径错位、把"跳过项"算进分母）。
3. **未加论证的断言** —— 声称"一致 / 等价 / 不构成第二定义点 / 已闭环"，却没有给出支撑。
4. **新引入的第二定义点** —— 改一处却让同一事实在**两处**各写一份（尤其"只加指针"这句自己有没有重复那个数）。
5. **把缺口写没了** —— 用"已裁不做 / 已登记"掩盖"**从未被测**"。

### 唯一产物：`out/xrev4.md`

格式固定：

- 依次写四行小节标题：`## 回写一` / `## 回写二` / `## 回写三` / `## 回写四`。
- 每个小节下逐条写缺陷，**每条一行、以 `- ` 开头**：
  `- [等级: 高/中/低] <缺陷一句话> ｜ 依据: <引材料原文片段，≤30 字> ｜ 修法: <一句话>`
- **每一段至少 3 条**（四段合计 ≥ 12 条）。
- 拿不准的写等级 `低`，修法处写 `不确定：<缺什么>`。
- 末尾加一节 `## 无法判断项`：你没有足够信息判定的部分，逐条说明缺什么。

### 硬性要求

1. **只读复核**：**不要修改**内嵌材料的任何内容；**不要**把材料大段抄进产物。
2. **不许编造**：材料里读不出来的 ⇒ 标 `不确定`，**不要猜**。
3. **不要引用、不要推测**任何具体项目 / 组织 / 主机 / 路径 / 人名。
4. `out/xrev4.md` 里 `^- ` 的行数 **≥ 12**。
5. **stdout 只输出一行**：`DOGFOOD_XREV4_OK`
6. 除 `out/xrev4.md` 外**不产生任何文件**。
   ⚠ 建议**先写一个只含四个小节标题的空骨架**再逐条填 —— 中途出错也留得下产物。

`partial` **必须**写 `gap`（否则是托词）。另有一栏 `evidence` 是**自由文本的实测读数**。
**门禁只核结构 / 载体是否存在 / 取值在封闭集内 —— 不核 `evidence` 里的数字**。

**本次改了 5 处 `evidence`（改写前 → 改写后）**：

   → 「2026-09-29 实测：`--quick` **40 项**（全量 **48**）—— 与手册里的断言计数行 `# 48 项断言 (quick 40 + 全量 8)` 一致」

5. **一条 `partial` 的 `gap` 整段重写**：

     ② **零实例**（仓内无一份文档真的标了某作废标记）⇒ **有词无牙**」
   - 改写为：「★ 本项 gap 重写（原文与实现相反）—— 原文写「① 零判据 …」：其中 **① 已不成立**

### 回写二：两处"段头 / 射程声明"与正文相反

- **二-甲**：一张真值表的**段落标题**写「**待接入**（如实登记"尚未接上"，不假装已接）」，
  而**同一段的正文**写「★ 落地进度：①②③+⑤ **已由门禁断言覆盖**、④ 已由另一条断言覆盖（均进快速集）
  ⇒ 本表从"有真值但无人读"变成**有消费者**」。
  **改法**：段头改为「**接入沿革**」并加一句结论（已接入、有消费者）；下方沿革原文**保留**。
- **二-乙**：一份"优先级与修复计划"文档的**射程声明**写「其后新增的条目（**O-62 … O-76**）**未**并入本文」；
  实为 `O-62` **及以后全部**、**截至 `O-116`**。
  **改法**：把枚举写成开区间并标明改动日期（原写"O-62 … O-76"是**枚举冻结**，会让读者以为 O-77 及以后已并入）；
  并加一句"直接读判据读数（仍开着 N + 清单）"作为入口。

### 回写三：台账里两条"否决"的理由分层与反向链接

- **三-甲**：某部署路线的否决，原状态格只写「该框架当前**已闲置** ⇒ 本部署路线不再推进」。
  **复核结论（本次改写）**：**主因写反了** —— 主因应是「该路线在本机群的具体后端上**未实现**」
  （依据 = 另一份"上游跟踪"文档里的**只读核验**）；"闲置"只是辅因，且**表述不准**：
  另一份 ADR 明确该引擎「**保留、不删**」（处置已降为"观察保留 / 不投入"，并写明复活条件仍有效，
  被清退的只是它的专属量化档）。
  **改法**：主因 / 辅因**分层写**，并补一句「**本条只否掉该路线的一条腿** —— 另两条路径未被本条否决」。
- **三-乙**：另一条的否决原写「**承三-甲一并否**」。但两条**对象不同**（三-甲讲新模型部署；
  三-乙讲"下载一个低量化档做同题准确率对照"）。
  **改法**：写明三-乙**自己的理由**（裁定不做该对照 ⇒ 不下载），并如实登记后果：
  「该路线的**准确率-代价一问从未被测**（另一条只证了'容量装得下'）⇒ 由'待裁'转为'已裁不做'，
  **不等于'已被回答'**」；并注明**与三-甲 / 那份 ADR 无关**。
- 两条的「**关联**」栏都补了指向那份 ADR 的**反向链接**（此前**只有单向引用**：ADR → 台账）。

### 回写四：一张"多轮闭环真值表"的上限由"未定"改为一个数

**表的结构**：登记仓库里**真实存在的重复执行闭环**；每条必须写清：轮次怎么数 · 上限是多少（或为什么没有）·
正向终止条件 · 超限怎么办 · 有没有 Delta。
**上限三态必须显式其一**：`capped`（给了数）/ `unbounded-by-design`（无上限但**必须给理由**）/
`undecided`（**未定也要写清等谁裁**）。**门禁规则**：若声明 `capped`，则"超限时发生什么"必须是
**可枚举动作**（`escalate` / `terminate` / `fail-record`）—— **不得**留 `undecided`，
否则判「上限只说了一半」。

**本次改动**：某条闭环（受理侧的**协商回环**：交需求方复核 → 收意见 → 修订 → 再复核）原为 `undecided`
（缺口径：源文档只写"循环至定稿"，而"定稿"是人的判断）。现改为：

- `cap_state: capped` · `max_rounds: 3`；
- 理由：与另两条闭环的循环上限**同值**（它们的循环上界都是 3）⇒ 协商回环不设得比"重试"更宽松；
- `on_exceed_kind: escalate` · 超限描述 = "第 3 轮复核后仍未定稿 ⇒ **停止回环**，管理员把未消化的分歧点
  逐条记录并据此定稿，**不再等下一轮意见**（升级到显式裁决，而非继续空转）"；
- 表头的**读数日期**由前一版改为当日；
- 「未实测登记」里原"上限**未定**"一条改写为「上限**已裁为 3，但无执行机制**」——
  如实说明：该闭环是**人的**流程，轮次靠"意见文件数"**可数**，但**没有任何代码在 N=3 时拒绝第 4 轮**，
  ⇒ 与"正向终止条件是人工判"同一性质：**写下来的是约定，不是牙**。
- 另在受理区流程说明的第 5 步**只加指针**（写「轮次上限与超限处置**不在本行**，真值 = 那张真值表的对应条目」），
  **不重复那个数**。
