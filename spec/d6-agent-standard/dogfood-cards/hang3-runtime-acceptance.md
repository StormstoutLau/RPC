## 任务描述

**背景（抽象）**：一个研究仓库有一个"**派发**"机制：把一张**任务卡**发给三台工作站中的一台，
由站上的外部执行体做完、把**产物**收回主控。仓库对"派发"新加了两项**机制**，
两项都**已落地**（有代码、有离线夹具、有先验红自证），但**两项都从未真跑过一次派发** ⇒
它们的**运行时验收**至今是空的。本卡要的就是**把这两项的运行验收拆成可执行方案**。

⚠ 仓库的一条硬纪律，本题必须遵守：**"没验到" ≠ "验出问题"** ——
**没有对象时只能报数（不入分母），不许算通过，也不许算失败**。

---

### 项一：**过程留痕**（一次派发留下"做过什么"的最小充分集）

**口径**：一次派发要留下 **5 维**过程痕迹，缺任一维都算**看着有留痕、实际缺维度**：

1. **命令** —— 外壳层面的执行记录（含退出码）；
2. **环境** —— 启动器在 fork 子进程**之前**采的环境快照（**不读** `/proc/*`，用等价的可执行命令）；
3. **文件系统写入** —— 用"比某时间戳更新的文件"这类**派生**手段得出，不额外记录；
4. **工具调用链** —— ⚠ **关键**：这条链由**执行体内部**产生 ⇒ **可篡改 / 可漏报 / 可伪造**
   ⇒ **只能如实标"不可核"**（`uncore`）。**若出现"已核 / 已验证"之类的标记 ⇒ 判不通过**
   （门禁有**负向自证**守这条）；
5. **产物** —— 由**主控侧**在回收时算哈希（不由执行体自报）。

**门禁判两段**：① **机制**（上面 5 个采集点逐个在位 + 负向自证）—— 已 PASS；
② **覆盖**（回收回来的那件留痕**若存在**则必须**段落齐全**；**存在 0 件 ⇒ 只报数、不入分母**）——
**本段至今是空的**（因为一次真派发都没跑过）。
**另有一条已知射程**：留痕件**只进主路**，本地备路（另一个 CLI 通道）**不产**该件。

### 项二：**层级归属**（该次派发落在哪一层，由三条判据机械求值）

**口径**：一张卡在**派发前**声明三个布尔字段（真值源 = 该仓库的一份 ADR 的求值规则节）：

- `B-1` = 是否需要"**非产出方**"的主体来给结论？
- `B-2` = 是否在**同一产物**上需要**多轮往返**？
- `B-3` = 是否只是"**这一次派发内部**"的质量门？

**求值规则 = 三分支，互斥且穷尽**（8 种取值组合全部命中且**仅命中一条**）：

- `B-1 ∨ B-2` ⇒ 归 **D7**；
- `B-3 ∧ ¬B-1 ∧ ¬B-2` ⇒ 归 **D6**；
- `¬B-3 ∧ ¬B-1 ∧ ¬B-2` ⇒ 归 **D6**（★ 这一支是**"约定"而非推导** —— 因为当前这三类场景都由 D6 承载）。

**求值点 = 派发前**（与"流程前置门"同处），结果写进该次运行的**记录文件**里（一个可选键）。
**诚实性要求**：三个字段**任一未声明**（空串 / 非 `true|false`）⇒ 必须落 **`resolved=false`、归属留空**
—— **"没判" ≠ "判了且归 D6"**。存量卡不带这三键 ⇒ **归属不变**，只多一条"未求值"留痕。
**另有一条已知射程**：本地备路（`claude` 通道）**早返回** ⇒ 其运行记录**不带**该键。

### 你的任务：产出**执行方案**，写入 `out/hang3.md`

**格式（小节名照抄、顺序照抄）**：

1. `## 前置条件清单` —— 逐条（每条一行 `- `）：`条件 | 为什么必须满足 | 怎么核（可执行命令的形态） | 核不过怎么办`。
   至少覆盖：**目标站要能跑本地引擎**（已知：引擎可能处于**停止**态；而"**出网档**"不需要本地引擎）、
   卡必须可写（要产物）、卡的超时设置、以及"**回收件**落在哪、怎么取回"。**≥5 条**。
2. `## 最小执行步骤` —— **有序**清单（每条一行 `- `），每步写：动作 / 期望输出 / 判据 / 不过怎么办。
   要求：**两项分开走**（不要一次派发同时验两项 —— 失败时无法归因）⇒ 明确写出**两次派发**的差别
   （第二次的卡要**额外声明哪三个字段、都取什么值**）。**≥8 步**。
3. `## 交叉锚定方案` —— 项一的留痕件怎么与**产物哈希**互相锚定（谁先算、谁记谁、比什么）。
   至少回答：① 哈希由**哪一端**算（为什么不能由执行体自报）；② 留痕件里**哪一行**承载这个哈希；
   ③ **哈希不一致**时算不算失败、算的话判什么。
4. `## 验收判据` —— 可机判形态 ≥5 条（每条一行 `- `）：`看到 X ⇒ 判 Y`。必须含：
   ① 一条**负向**（"若出现'工具调用链已核'类标记 ⇒ **必须判不通过**"）；
   ② 一条**空对象**（"若**没有任何**回收件 ⇒ **只报数、不入分母**，**既不算通过也不算失败**"）；
   ③ 一条**未求值**（"若三个字段缺任一 ⇒ 记录里必须是 `resolved=false` 且归属为空 ⇒ 判**通过**"，
   因为**诚实报"没判"才是对的**）；④ 一条项二的**穷尽性**（"8 种取值组合逐组合验，**每种恰命中一条**"）。
5. `## 失败形态` —— ≥4 条（每条一行 `- `）：`失败形态 | 它说明什么（是机制没落 / 是环境未就绪 / 还是真缺陷）|
   下一步`。必须含：① 站上引擎**未加载**导致派发失败（应与"机制坏"**区分开**）；
   ② 留痕件**段落不全**；③ 记录里**根本找不到那个键**（要区分"本地备路"与"主路没写"两种成因）；
   ④ **回收件 0 个**（应判"未验"，**不许**升级成"验出问题"）。
6. `## 不确定项` —— 你无法从上述口径判定的，逐条说明缺什么（**不许猜**）。
