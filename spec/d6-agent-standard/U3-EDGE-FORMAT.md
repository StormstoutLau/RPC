## 1. 字段集

| 字段 | 取值 | 格式 | 为什么是它 | 否掉了什么 |
|---|---|---|---|---|
| **`src`** | **U-1 产物身份** | `u1:sha256:16:<hex16>`（见 §5） | 边指向"谁"必须有唯一答案；U-1 已定案为身份标准 | 任意字符串 · 路径 · UUID · 未截断哈希 |
| **`dst`** | **U-1 产物身份** | 同 `src` | 同上 | 同上 |
| **`kind`** | **封闭枚举**（见 §2） | 小写蛇形 | 只收录有摘要依据的种类；凭常识补的**不进枚举** | `depends_on` / `imports` / `references` 等通用词 |
| **`provenance`** | **机器可解析串**（见 §3） | `<前缀>:<载荷>`；前缀 ∈ 封闭集 | RFC-0002：「无 provenance 的边**无效**」；必须可追溯"谁、依据什么" | 自由文本 · JSON 对象 · 无结构串 |

## 3. `provenance` 的取值形态

**格式**：`<前缀>:<载荷>`。**切分规则**：只按**第一个** `:` 切分 ⇒ **载荷允许含 `:`**
（⚠ 这是对产物初稿的更正：初稿既给"载荷禁含未转义 `:`"，又给了四条含 `:` 的示例，自相矛盾）。

| 前缀 | 含义 | 载荷示例 | 完整示例 |
|---|---|---|---|
| `hash` | 内容哈希自动发现 | `sha256:<64hex>` | `hash:sha256:ab…（64 位）` |
| `filetrack` | 文件读写追踪自动发现 | `v1.2.3:in=…,out=…` | `filetrack:v1.2.3:in=<相对路径>,out=<相对路径>` |
| `manual` | 人工录入（记录"人工同步"这一**事实**） | `<作者标识>:<日期>:reason=<理由>` | `manual:<作者标识>:2026-09-26:reason=initial_sync` |
| `tool` | 确定性工具生成 | `<工具名>:<版本>[:配置摘要]` | `tool:dep-scanner:v0.1.0:config=prod` |

★ **`<作者标识>` 不得是用户名 / 主机名 / IP / 盘符路径**（与 [sensitivity.yaml](../../inventory/sensitivity.yaml)
表头的出站口径裁定一致：**用户名属需脱密项**）⇒ 用角色标识或哈希短串，例如 `operator-a` / `human-3f2c`。

★ **`manual` 只记录"人工同步这一事实"，不表示"模型判断出此依赖"** ——
见 §6 的生成纪律。

## 4. `provenance` 缺 ⇒ 边无效（**可机判形式**）

### 4.1 判定表达式

```
invalid(e) ⇔
      e.provenance 字段不存在
   ∨  e.provenance == ""
   ∨  trim(e.provenance) == ""
   ∨  e.provenance == null
   ∨  lower(e.provenance) ∈ {"unknown", "none", "n/a", "null"}
   ∨  分隔后前缀 ∉ PROVENANCE_PREFIXES
   ∨  载荷为空（首个 ":" 之后 trim 为空）
```

### 4.2 视为"缺"的值（逐种列出）

1. 字段**完全不存在**
2. 空串 `""`
3. 仅含空白（`" "` / `"\t\n"` …）
4. `null` / `None` / `nil`
5. 不分大小写等于 `"unknown"` / `"none"` / `"n/a"` / `"null"`
6. **形式对但前缀不在封闭集**（如 `guessed:…`）
7. **形式对但载荷为空**（如 `"manual:"`）

### 4.3 无效边的处置（**产出方 fail-closed · 消费方显式降级**）

★ 这一节按**角色**分开写（是对产物初稿"丢弃该条边、继续"的更正）：

- **产出方（本仓写边的这一侧）**：**禁止写出无效边** ⇒ 一旦出现 `invalid(e)`，
  就是 **FAIL**（不是"丢掉那条边继续"）。理由：静默丢弃 = **静默 skip**，
  而 **D-26 已明裁**「H-3 的降级必须**有机判呈现位**，**禁止静默 skip**」——
  丢掉一条边等于把一次"判不了"悄悄变成"没有这条边"。
- **消费方（读边去决定重算什么的那一侧）**：命中无效边 ⇒ 按 **H-3** 处理：
  **无法安全判定影响面 ⇒ 强制降级为全量重算**（不是"跳过这条边"）。

⇒ 两句话合起来：**无效边不许产生；万一被读到，就降级，不许绕。**

### 4.4 反向自查（"看起来有、其实无效"）

```
{ src: "u1:sha256:16:…", dst: "u1:sha256:16:…", kind: "document_level", provenance: "manual: " }
```

它**带** `manual:` 前缀，看着像有来源，但**载荷为空** ⇒ 命中 §4.1 最后一条 ⇒ **invalid**。
⇒ 这条用例的作用是证明判据**不是只看"有没有那个前缀"**。

## 5. `src` / `dst`：直接采用 U-1 产物身份

```
u1:sha256:16:<hex16>
```

其中 `hex16 = sha256(RFC 8785 规范化 JSON(["<namespace>", "<identifier>", "<version>"]))[:16]`；
`namespace` 取值域 = [inventory/dialect.yaml](../../inventory/dialect.yaml) 的 `namespaces[].id`（单一真值，不另列）。
★ 算法标识前缀 `# u1:sha256:16` **只进文件头部注释**、**不出现在边字段值里**
（那条约束是给清单文件用的；见 [U1-ARTIFACT-IDENTITY.md](U1-ARTIFACT-IDENTITY.md) §1.4）。

## 6. 生成纪律（结构性事实**不得**由模型产生）

**原文 invariant**：

> "Edges SHOULD contain provenance. Edges without provenance are invalid."
> "No AI in graph construction. Compiler graph facts MUST NOT depend on probabilistic model output."

⇒ 落到本仓：

- **依赖边由确定性机制产生**（内容哈希 / 文件读写追踪 / 人工录入）——
  **不得**由模型（含本仓的吃狗粮 agent）"判断出"某条依赖后写进去。
- ⇒ 因此**吃狗粮卡不得产出"边实例"**；它只能产出**形状**（本文件就是形状）。
  ★ 本文件正是这条纪律的实例：它的产物是 schema，**不是边**。
- 一个尚存的灰区（登记在末节）：`manual` 前缀合法的前提是"人**记录**了一个已发生的同步"，
  而不是"人**猜**了一条依赖"—— 二者在字段层面**无法区分**。

## 7. 与既有现状的关系

摘要给出的九条"人肉边"**全部可表达**（逐条映射见本文件 §2 的枚举依据）；
且在 §2 的粒度下它们其实展开为 **13 个 kind**。**表达不了**的两类：

- **双向关系**：现状把它当"一条关系"，本 schema 强制拆两条 ⇒ 迁移时需人工确认两方向是否对称。
- **"人肉同步"这个元信息**（改一处靠人记得改另一处）**无字段承载** ⇒ 暂不建模。

**迁移策略 = 增量**：新增 / 修改边时按本 schema 写；**存量边不做一次性全量迁移**。

### 7.1 ★ 当前**边界实例数 = 0**，且原因是前置缺失

`src`/`dst` 要求 **U-1 产物身份**，而 **U-1 是"设计定案、实现未落地"**
⇒ 到目前为止**没有任何产物登记过 `namespace` / `identifier` / `version`**
⇒ **造不出合规的边**。

⇒ 因此本仓的边清单（[inventory/edges.yaml](../../inventory/edges.yaml)）**刻意为空**，
并带一个 `empty_reason` 字段说明原因 —— **空 ≠ 没事**，而是**判据的"前置缺失"**，必须在报告里显式出现。
