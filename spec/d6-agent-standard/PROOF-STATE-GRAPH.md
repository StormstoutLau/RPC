## 3. AND-OR 超图 领域语义

### 3.1 节点（goal）

- **节点身份 = 规范化后的 goal**。规范化函数 `norm(·)` 把 Lean 目标串归一（去无关空白 / 归一绑定名），
  取 `norm(goal)` 或其哈希作为**节点 id**；同一 `norm` 结果 ⇒ **同一节点**（可去重、可复用）。
- **根节点** = 待证定理的初始 goal。
- ⚠ 规范化**必须确定**：`norm` 不同 ⇒ 同一目标被当作两节点（图膨胀）；`norm` 过粗 ⇒ 不同目标被合并（**假证**）。
  ⇒ `norm` 的实现属**它侧**（`F:\Auto_Prover`），本文档只要求「确定 + 可复算」并**禁止**用 LLM 做规范化。

### 3.2 超边（tactic）

- **一条超边 = 一条 tactic 作用于某 goal**，产出 **k ≥ 0 个子目标**：
  - `k = 0` ⇒ **闭叶**：该 tactic 直接把该 goal 证成（如 `rfl` / `by decide` / 精确引理闭合）。
  - `k ≥ 1` ⇒ 该 tactic 把该 goal **归约**为 k 个待证子目标。
- 一条超边携带：`tactic 文本` + `产出子目标列表（有序）` + `verifier 判决（见 §5）`。

### 3.3 AND 与 OR（本件的**核心**，必须分清）

- **AND = 同一条超边产出的 k 个子目标之间**：**全部**子目标被证 ⇒ **该超边证成其父 goal**。
- **OR = 同一 goal 上的多条超边之间**：**任一**超边证成 ⇒ **该 goal 被证**（多条超边互为**替代路径**）。

### 3.4 唯一判据（写死，可机判）

```
proved(g)  ⟺  ∃ e ∈ out(g) :  ∀ c ∈ sub(e) : proved(c)
```

其中 `out(g)` = 以 g 为父的超边集合，`sub(e)` = 超边 e 产出的子目标集合。
**「被证」只有这一个定义**；任何"看起来像证完了"的启发式（近闭叶、模型自报、部分子目标已证）**一律不得**替代它。

### 3.5 一个最小例子（形态示意，非实现）

```
root: ⊢ a + b = b + a                      (goal: G0)
  OR  e1: rw [Nat.add_comm]                  → k=0  ⇒ 闭叶 ⇒ proved(G0)
  OR  e2: induction a with
          | zero  => ⊢ 0 + b = b + 0          (AND: sub1 of e2 = G1)
          | succ a ih => ⊢ succ a + b = b + succ a   (AND: sub2 of e2 = G2)
                                              ⇒ proved(G0) 仅当 proved(G1) ∧ proved(G2)
```

⇒ `e1` 与 `e2` 是 **OR**（任一即成）；`e2` 的两个子目标是 **AND**（缺一不可）。
★ **把 e2 的两个子目标误当成 OR = 允许「只证一半就宣称证明」** —— 这是本件最要防的**语义级**错误（§8②）。

## 4. 依赖聚合与传播

### 4.1 节点状态（**封闭集**）

| 状态 | 含义 |
|---|---|
| `open` | 尚无已判决的超边，或尚有子目标未判决 |
| `proved` | 按 §3.4 判据**已证**（存在一条超边，其全部子目标 `proved`） |
| `failed` | **所有**超边都被 verifier 判为失败（该 goal 在此搜索空间内证不出来） |
| `blocked` | 被**预算 / 超时 / 不可判**挡住（`unknown` 侧，见 §5） |

★ **封闭集**：不得出现「部分证成」「大概证了」等**第五态**；`partial` 一律映射为 `open`（或 `blocked`），
因为它是**过程量**、不是结局。

### 4.2 传播规则（**纯函数 `图 → 状态`**）

- **自底向上**：子目标状态先动，父状态由 §3.4 重算。
- **单调**：状态只允许 `open → {proved, failed, blocked}`，**不得回退**（除非图被显式重建，见 §8④）。
- **确定 + 可复算**：**同一张图重放 ⇒ 同一组状态**（无时间/随机/执行器内部状态依赖）。
- **与搜索分离**：聚合**不**决定"下一个展开谁"（那是 §6）；搜索**不**改聚合规则。

### 4.3 `sorry` 与部分证明（**红线**）

- 任何子目标以 `sorry`（或等价占位）闭合 ⇒ **该子目标不得为 `proved`**（顶多 `blocked`）。
- ⇒ 由 §3.4，**父不得为 `proved`**。★ **「`sorry` 当已证」是本件最要防的失效形态之一**（§8⑤）——它会让整张图「全绿」而其实没证成。

## 5. verifier 闭环

### 5.1 oracle = Lean（唯一）

- **唯一 oracle = Lean**：`compile_check`（`lake build` 级）与 **REPL 逐步执行**（`F:\Auto_Prover\proof_pipeline` 既有 `LeanSimRuntime` / `Lean4ReplRuntime`）。
- **状态迁移只在 oracle 判决之后发生**：一次超边展开，先由 oracle 给出「该 tactic 在此 goal 上成功 / 失败 / 不可判」，
  **再**据此更新节点状态。**不得**先改状态再补验证。

### 5.2 no-silent-success（**写死**）

- 超时 / 异常 / 空输出 / **响应不可解析** ⇒ 判 **`unknown`**（**判不了 ≠ 通过**）。
- `unknown` 在聚合层映射为 **`blocked`**（§4.1），**不得**映射为 `proved`。
- ★ **执行器（LLM/agent）自报一律不可信**：任何"我证明了"的自述**不**构成 `proved` 的理由；
  `proved` 的**唯一**来源是 oracle 判决。这是本仓头号失效形态（「同一事实两处表达 / 自报代替实测」）在证明域的对应物。

### 5.3 判决的记录

- 每条超边的判决须**留档**（tactic + 子目标 + oracle 原始输出 + 类别），以便：
  (a) 图可复算；(b) 失败可归因（对齐既有 `ErrorClassifier` 的 5 类）。

## 6. 最简搜索策略（**best-first**）

### 6.1 选型

- **选 best-first（优先队列）**。理由：**没有学习价值函数**（HTPS 的贡献是「搜索算法 **+ 学到的 value function**」，
  我们没有后者）⇒ 只能用**非学习型启发式**；而**纯贪心**在 AND-OR + 部分证明场景下**易烧穿死分支**（一条注定失败的路径会吃光预算）。
- **回退**：首条端到端跑通可先用**贪心**（最简单、可解释）；一旦出现"死分支吃预算"即切 best-first。二者共用同一聚合层（§4）。

### 6.2 启发式（**必须非学习型**，且**不得**用 LLM 打分）

组合以下可复算项（权重是**待校准参数**，非本件裁定值）：

- **深度惩罚**：越深的节点越贵。
- **子目标数惩戒**：一条超边一次性产出过多子目标 ⇒ 降权（AND 面变宽，风险大）。
- 复用既有 **`ErrorClassifier`** 的**错误类别**权重（如 `missing_lemma` 比 `timeout` 更值得重试）。
- **是否近闭叶**（有 `k=0` 候选边 ⇒ 优先）。

### 6.3 预算（**显式上界**，红线）

- 沿用它侧既有上界：**beam 宽 = 4 · 深度 = 10**，外加**最大扩展次数**上限。
- ★ **预算必须显式**（不得"跑到不行为止"）：长搜索 + 崩溃重放 = **重算 LLM 调用**，是真代价（§8④）；
  预算耗尽 ⇒ 相关节点置 `blocked`，**不静默**。

## 7. 与 `ProofNode` / `ProofTree` 的接缝契约（**只许附加式**）

### 7.1 现状（它侧，读码事实）

- `F:\Auto_Prover\proof_pipeline\datatypes.py` L590-655 已有 `NodeStatus / ProofNode / ProofTree / BeamCandidate / BeamSearchState`；
  **节点只有 `children: list`** ⇒ **无显式 AND/OR 超边**。
- `F:\Auto_Prover\proof_pipeline\stages\stage3_proving.py` 的 `AgenticProver.prove()`（L664-694）只建**一个根 `ProofNode` + 一棵 `ProofTree`**，
  `_beam_search_prove()`（L696-751）从**线性 `goal_queue`** 里弹出目标、把子目标**追加进 `children`**（⇒ 现状 = **树**，不是超图）。

### 7.2 契约（**附加式**，不得改既有字段语义）

1. **增设显式超边结构**：一条 edge 携带 `tactic` + 其（有序）子节点引用 + 判决；`children: list` **保留不动**（向后兼容）。
2. **增设 OR 组**：同一 goal 上的多条 edge 显式成组（现状靠"隐式多次展开"，会**丢掉 OR 结构**）。
3. **既有字段零语义变更**：`NodeStatus` 需**恰好对齐** §4.1 的封闭集（若现名不同，**映射**而非改名 —— 改名等于第二定义点）。
4. ★ **本仓内核不解析拓扑**（`ADR-0013` 护栏①）：本仓**只**在#卡（TaskContract）里**附加式**带上必要的**指针/摘要**，**不**复刻拓扑。
5. **判据归属**：★ **证明图语义的判据属于 `F:\Auto_Prover` 的 `tests/`**，**不**属于本仓门禁
   （本仓将来最多有一条**接缝**判据，见 §8 末尾）。

## 8. 漂移陷阱与「不做什么」

逐条点名（前六条是**语义/工程**陷阱，第七条是**治理**陷阱）：

1. **第二真值源** —— 拓扑在本文档写一份、在 `F:\Auto_Prover` 代码里再写一份 ⇒ 分叉（本仓头号失效形态）。
   ⇒ 本文档**只定义语义**，**不复刻**拓扑；两侧一致靠**接缝契约**（§7）而非"各写一遍"。
2. **AND/OR 混淆** —— 把「同 goal 多条 tactic」误当 AND（或反之：把一条 edge 的多个子目标误当 OR）。
   ⇒ **允许「只证一半就宣称证明」**（§3.5）⇒ 必须由 §3.4 的唯一判据机械判定。
3. **verifier 信任执行器自报** —— 拿 LLM 的"已证明"当 `proved` 依据（§5.2 红线）。
4. **搜索预算无界** —— 长搜索 + 崩溃重放（`SIGKILL` 重跑已记录工作，独立实测 **at-least-once**）⇒ **重算 LLM 调用**（§6.3）。
   ⇒ 预算显式 + 重放**不得**重写已判决的 edge 判决（否则 `digest 不符`，本仓已有实测先例 `O-140`）。
5. **`sorry` 当已证** —— §4.3 红线。
6. **对空气设计外壳** —— 真实输入 **0 条**（§2.1）⇒ 本文档刻意**只定义领域语义**、**不**设计执行外壳（外壳是 P4，且"越晚绑越好"）。
7. **治理陷阱** —— 本文档若被读成「本仓内核判据」即**违反 `ADR-0013` 护栏①**（内核不解析拓扑）。
