# D7 结论契约（Conclusion Contract）—— 受限判定 + 结构化意见 + 综合分类

> **批次**：`D7-P2-2`（路线总表 §4.3）· **依据**：合并稿 **M-6** + [Council Mode](https://arxiv.org/html/2604.02923v2)（§362/§406/§543）
> **状态**：**设计定案 · 校验器已落地 · 生产消费者 = `Invoke-Review`（单判官路径）**
> **与 `D7-P2-1` 的关系**：本契约与 `review.json` 的 **`l1` 段**（机械面裁决）**同处一份产物**
> —— 读的人应当能一眼区分"**机械面已通过**"与"**语义面这么认为**"两件事（那是本仓头号形态的正面用法）。

## 1. 为什么需要它（一句话）

站在 `D7-P2-1` 之后，L2 的产物里已经有了 **`l1` 段（机械事实）**；但 **L2 自己的意见仍是自由文本**
（现契约 = `{score, pass, evidence[{anchor,hit,reasoning}], flags_hit, conclusion}`，见 `review/judge-prompt.tmpl`）。
⇒ 后果有三：
1. **不可数**（"几条意见 · 各自多重"数不出来）；
2. **不可定位**（没有 `path:line_range` ⇒ 意见落不到行）；
3. ★ **不可区分"共识"与"孤例"** —— Council Mode 的实测收益（幻觉率相对降 35.9%）恰恰来自
   **综合阶段显式分类 consensus / disagreement / unique**，而**不是**多数投票出一个结论。

## 2. 契约形状（机器可读）

```json
{
  "verdict": "accept | revise | reject | uncertain",
  "findings": [
    {
      "id": "F1",
      "statement": "一句话（可被逐条核验）",
      "hit": true,
      "priority": 3,
      "confidence": 0.8,
      "path": "ops/rpc_check.py",
      "line_range": "L120-L134",
      "note": "可选：证据链/推理"
    }
  ],
  "score": "优秀|良好|合格|不合格",
  "pass": true,
  "conclusion": "一段结论"
}
```

**逐字段的硬约束（校验器判的就是这些）**

| 字段 | 约束 | 为什么 |
|---|---|---|
| `verdict` | **封闭枚举** `accept`/`revise`/`reject`/`uncertain` 四选一 | "受限判定"：**不许自定义词** ⇒ 可数、可对账 |
| `priority` | **整数**（≥0；越大越优先） | 浮点 priority 会让"排序"变成"看起来有区别" |
| `confidence` | **浮点**，`0.0 ≤ c ≤ 1.0` | 概率语义；**越界 = 无效**（不许用 1.5 或 `"high"`） |
| **`hit`** | **布尔**（true = 该锚点**达标**） | 沿用既有 rubric 的 `evidence[].hit` 语义（**不新造**）。★ **有它才使 `disagreement` 可判**（同一锚点、两个判官结论相反） |
| `path` | 必填，非空 | 意见必须**落到一个具体文件** |
| `line_range` | 必填，形如 `L<起>-L<止>`（单行 `L<n>` 允许；`L<起>-` 允许） | **落不到行的意见不可核验** |
| `agreement` | ★★ **单个判官【不得】输出此字段** | 它是**综合阶段算出来的**；判官自报 = **自证**（本仓禁止）。校验器见到 ⇒ **拒** |

★ **`agreement` 的值域**（**只由综合器产出**）：`consensus` · `disagreement` · `unique`。

## 3. 综合（N 个判官 ⇒ 三分类）的判定规则

以 **`path` + `line_range`**（**归一化后**，**不含 `statement`**）把各判官的意见对齐成"锚点"：

★ **为什么锚点里不含措辞**：不同判官对同一件事的**表述必然不同** ⇒ 若把 `statement` 并入键，
"共识"会**几乎永不出现**（分类随即退化成噪声）。**位置是客观的，措辞不是** ⇒ 用位置对齐。

| 分类 | 判定 |
|---|---|
| **consensus** | 该锚点被 **≥2 个判官**提到，且**所有 `hit` 一致** |
| **disagreement** | 该锚点被 **≥2 个判官**提到，且 **`hit` 不一致**（同一位置有人判达标、有人判未达标） |
| **unique** | 该锚点**只被 1 个判官**提到 |

⚠⚠ **两条硬纪律**（否则分类会变成假信号）：
1. **单判官 ⇒ 只可能是 `unique`**，且**必须同时报 `judges=1`** —— 不许把"只有一个判官"渲染成"多家共识"。
2. **空集不产共识**：`findings` 为空时 **`consensus` 必须为空**（`0/0` 读成"没问题"是本仓已登记过的假绿形态）。
   ⇒ 综合器**必须**把输入规模（判官数 / 意见数）**显式报出来**，与分类同时呈现。

## 4. 校验器（落地物）

| 实现 | 位置 | 性质 |
|---|---|---|
| `Test-FindingShape` | `ops/station-bin/agent-cli.ps1` | **纯函数**：单条 finding 的字段/类型/越界校验 ⇒ `(ok, reasons)` |
| `Test-ConclusionContract` | 同上 | **纯函数**：整体（`verdict` 枚举 + 每条 findings + `agreement` 不得自报） |
| `Merge-JudgeFindings` | 同上 | **纯函数**：N 判官 ⇒ 三分类 + **显式报 `judges`/`opinions` 规模** |

**正反用例**：`ops/station-bin/_fm_golden_test.ps1`（`cc-*` 组，含**恒真检测**：每条判据都必须有能把它打红的反例）。

## 5. 与其它批次的边界（明确不做）

- **多判官编排**（谁审谁 · 跨族 · 信息独立）⇒ **`D7-P3-2` 编排层**。本批的 `Merge-JudgeFindings` **只在离线用例上被喂 N>1**；
  **站上路径当前只跑 1 个判官** ⇒ `review.json.findings` 的分类**必然是 `unique`** 且带 `judges: 1`（**如实**，不假装做过 Council）。
- **权限隔离**（"只标记永不改写"的物理约束）⇒ **`D7-P3-1`**。本批只保证"意见**带位置**、结构**可校验**"。
- **判据自身的有效性**（覆盖率 / 恒真检测的**系统性**做法）⇒ **`D7-P2-3`**；本批只做到"**每条新判据都配了反例**"。
