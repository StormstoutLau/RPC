## 1. 四条规则（原文 → 可机判形式）

| # | 规则（**原文照录**） | 可机判形式（本仓落体） | 需要的输入 |
|---|---|---|---|
| **H-1** | "Incremental builds MUST be clean-build equivalent."（另有 invariant："A successful incremental build MUST be semantically equivalent to a successful clean build."） | **`incremental_equivalent is not True` ⇒ 不得走增量**（⚠ **"未证"≠"等价"** ⇒ fail-closed，付全量代价） | `incremental_equivalent`（`True` / `False` / `None`=未证） |
| **H-2** | "Dependency invalidation MUST be conservative." | **影响面只许扩大**：结果集**未传递闭包化** ⇒ 取全量（宁可多算） | `affected`（结果集）+ `affected_is_closure` |
| **H-3** | ★ "If affected regions cannot be determined safely, the compiler MUST broaden invalidation or fall back to a clean build." | **`affected is None`（无法安全判定）⇒ 强制 `full_rebuild`**，且**必须可见**（见 §2） | `affected is None` |
| **H-4** | "A failed build MUST NOT partially overwrite the last valid canonical graph artifact." | **`build_failed` ⇒ 不落盘**（保留上一份有效产物），且**算失败** | `build_failed` |

**同源 invariant（同样适用，已在别处落地）**：`"Edges SHOULD contain provenance. Edges without provenance are invalid."`
⇒ 已落进 [U3-EDGE-FORMAT.md](U3-EDGE-FORMAT.md) 与门禁 `edges`（本文件不重复定义）。

## 2. ★ H-3 的"降级"落进「非执行三分」（**D-26 那句"必须有呈现位"的落地**）

「非执行三分」的**唯一落点** = `run_checks()`：

| 分 | 含义（原文） | 后果 |
|---|---|---|
| `MODE_SKIP` | 调用方**不给**它（未选中） | **不进 results ⇒ 不计失败** |
| `SKIP_FAILED` | `needs` 里有 FAIL/SKIP_FAILED | **算失败** |
| `WARN` | **环境降级** | **不进 FAIL 集，但必须可见** |

**本批的映射（每一支都写在 `decide_invalidation()` 里）**：

| 情形 | `action` | 三分 | 为什么是这一分 |
|---|---|---|---|
| 变更集**为空** | `none` | **`MODE_SKIP`** | 这是**唯一**允许落到 MODE_SKIP 的情形 —— 它是"**真的没事**"，不是"判不了" |
| **影响面无法安全判定**（H-3） | `full_rebuild` | **`WARN`** | 能力降级：保守全量，**可见但不阻断**（降级本身是**安全**方向 ⇒ 不该拦提交） |
| **增量等价性未证**（H-1） | `full_rebuild` | **`WARN`** | 同上（付代价换正确性） |
| **影响面未闭包化**（H-2） | `full_rebuild` | **`WARN`** | 同上 |
| **重算失败**（H-4） | `none` | **`SKIP_FAILED`** | 失败必须**算失败**；且不得部分覆盖 ⇒ **不落盘** |
| 四条全过 | `incremental` | `None` | 正常路径，**不属于**"非执行"三分 |

### 2.1 硬不变量（**禁止静默 skip**）

> ★★ **任何"判不了"的情形，都不得落到 `MODE_SKIP`。**

理由（原文 D-26）：`MODE_SKIP` 的后果是"**不进 results ⇒ 不计失败**"——
把"判不了"映射到它，等于**把一次判不了悄悄变成"没事"**（本仓头号形态）。
⇒ 用例 `u4⑦` 专门钉这一条：**遍历全部"判不了"输入，断言 class ≠ `MODE_SKIP`**。

★ 这条不变量的形态与门禁 `edges` 的"**空清单必须给 `empty_reason`**"同源：
**两者都在防"没有结果被读成一切正常"**。

## 3. 三条已裁约束（必须遵守）

1. **D-26**：四条**全采**（照 RFC-0002 MUST 语义）；H-3 的"降级"必须有**机判呈现位**（见 §2）；
   **只适用派生产物** —— 上游变更集指**派生产物**，不是任意文件。
2. **D-27**：**结构性事实不得由 LLM 产生** —— 模型可**提议**、不得**成为**事实；
   须经确定性机制**独立复算**才准入，**复算不过 ⇒ 不入图**。**判据 = 可复算**。
   ⇒ 对本批的直接含义：**影响面（`affected`）不得由模型判断产生**，只能来自内容哈希 / IO 追踪 / 显式声明。
3. **D-51**：**受理目录不纳入失效传播**（"新需求开新 `open`、不重写旧目录"策略与传播语义冲突已裁）
   ⇒ `changed_ids` **不得**包含受理目录下的产物。

## 4. 首靶与前置

**首靶**（已裁）：`Macro_Data` 的 **`revision_propagation` 占位** —— 原文实测它**就是一个返回 `skipped` 的 P0 占位**，
且该项目的"失效传播"维度实测为 **0/9 里的一员**。

**前置（→ 解锁才能真跑）**：

  而 U-1 当前是"设计定案·实现未落地"（与本仓 `edges.yaml` 为空**同一个前置缺失**）。
- **U-3（边格式）必须先落地**：没有机读的边图，"影响面"无从计算（九项目"机读阶段依赖"实测 **0/9**）。

⇒ 三条（U-1 / U-3 / U-4）是**同一根链**：**身份 → 边 → 失效**。

## 第一个真实用例：**U-1 切换对存量产物的影响面**（2026-09-26）

> **来源**：`docs/2026-09-23_D7调研_立项·机制·统一基座.md` 的第 9 条待评估项 ——
> 原文把它标为"**未评估**…… 这正是 **U-4 的第一个真实用例**"。本节把它评了。
> ⚠ 本节数字都**标依据**；grep 命中的是**代理指标**，**不等于**"产物 ID 产出点数"。

### 1. 变更是什么（变更集）

把各项目的产物 ID 从**旧形态**迁到 U-1（`sha256` + `["ns","id","ver"]` 的 JCS 字节 + `[:16]` + 前缀）。
按 D-23「**不追溯重算历史**」，只对**生效后新产生**的产物生效 ⇒ 变更集 = 各项目的 **ID 产出点**。

| 项目 | ID 站点（py/ps1 命中 `hexdigest()[]` / `md5(` / `sha256(`） | 判读 |
|---|---|---|
| **Open_Data** | 34 | ✅ **真受影响** —— 实测 5 处 `sha256("<ns>\|<d1>\|<d2>")[:32]`（blackmarble / portwatch / eia / gfw / opensky）**确认是产物 ID** |
| **Auto_Prover** | 114 | ◐ **未分类** —— 命中数远超"产物 ID"的合理量 ⇒ 疑含大量 Lean / 构建无关用法 ⇒ **需逐点核** |
| **Textbook** | 10 | ✅ 确有哈希用法（但 KG **不是**其一，见 §2） |
| **Fin_Agent** | 3 | ◐ 未核 |
| **Cpp_Hub / Spec_Workflow / Full_Weather** | **0** | 本项目**不产哈希形态 ID** |
| **Macro_Data** | — | ❓ **目录未定位**（`F:\` 下只有 `Macro_Sandbox`；**未证实两者同一** ⇒ 不当成它） |
| **本仓 RPC** | 2 个 `u1:` 声明 | ✅ **已迁**；`inbox/MANIFEST.sha256` 按本规范 §2 **不动**（保 `sha256sum -c`） |

### 2. ★★ 实测**推翻清单里的一条**：Textbook 的 20,236 条 KG 边**不在影响面里**

调研清单把"Textbook 20,236 条 KG 边"列为 U-1 切换的影响面。**一手实测**：

- `D:\Textbook\kg_dashboard\{dist,public}\knowledge-graph.json` ⇒ **nodes 1,823 · edges 20,236**（数字**对**）
- **但那份 KG 的 ID 是语义主键**：节点 `def_1.1` / `thm_2.2`、边 `edge_00000`
  （边形状 = `{id, source, target, type, relation}`）—— **不是哈希**
  ⇒ **U-1 切换不会动它**（除非 Textbook 另行决定用 U-1 表示节点身份 —— 那是**另一件事**，不在本变更集里）

⇒ ★ 这正是"未评估"该被评估的理由：照抄清单会**高估**影响面。而高估的代价不是学术性的 ——
**它会让迁移看起来大到没人敢动**。（⚠ 与本仓 O-82 的"射程说明"是**同一件事的两个方向**：那边防把局部读成全仓，这边防把清单读成事实。）

### 3. ⚠ 顺带实测出一处**清单漏掉**的影响面

同一份 KG 在 `kg_dashboard` 下**有 3 个文件是同一份内容**（`dist/knowledge-graph.json` ·
`dist/knowledge_graph.json` · `public/knowledge_graph.json`；三者 **size 均 6,159,011 B**、结构相同）
⇒ **将来真要改它，三处必须一起改**（"影响面反查"能救的正是这一类）。本次**不改**，仅登记。

### 4. 判据给出的处置（**真跑**，输出逐字）

变更集 = Open_Data 五处产物 ID；`affected=None`（**理由见 §5 —— 是如实，不是省略**）：

| 场景 | 输入 | 输出 `(action, class, reason)` |
|---|---|---|
| **★ A 本次真相** | `affected=None` | `('full_rebuild', 'WARN', 'H-3 影响面无法安全判定 ⇒ 强制全量降级（可见，禁止静默 skip）')` |
| B 影响面已知但未闭包化 | `affected=['t1','t2'], closure=False, inc_eq=True` | `('full_rebuild', 'WARN', 'H-2 影响面未闭包化 ⇒ 保守起见取全量（宁可多算）')` |
| C 增量等价性未证 | `affected=['t1'], closure=True, inc_eq=None` | `('full_rebuild', 'WARN', 'H-1 增量等价性未证 ⇒ 不得用增量（付全量代价）')` |
| D 重算失败 | 上者 + `build_failed=True` | `('none', 'SKIP_FAILED', 'H-4 重算失败 ⇒ 不得部分覆盖，保留上一份有效产物（算失败）')` |
| E 无变更 | `changed_ids=[]` | `('none', 'MODE_SKIP', '变更集为空：确实无需动作（不是「判不了」）')` |
| F 四条全过 | 全绿 | `('incremental', None, '四条规则全过：可安全增量')` |

⇒ **处置 = 全量重算 + WARN**，且**禁止静默跳过**（六种里**唯一**允许 `MODE_SKIP` 的只有 E）。
复现：`py -c "import sys;sys.path.insert(0,'ops');import rpc_check as R;print(R.decide_invalidation(changed_ids=['open_data:blackmarble', …], affected=None))"`

### 5. 为什么这次**只能**判"判不了"（而不是偷懒写 `None`）

`affected` 的**产出机制本就不存在**（本文件未实测第 2 条），而这次连**人肉**都判不了：
① Auto_Prover 的 114 个命中**未分类** ⇒ 不知几个是产物 ID；② **Macro_Data 目录未定位**；
③ Open_Data / Auto_Prover 的**存储不在本机**（`*.duckdb` / `*.db` / verdict 扫描均为空）⇒ 下游表无从枚举。
⇒ `affected=None` 是**如实**。而它**恰好**触发了 H-3 想防的那一幕：**判不了 ⇒ 全量 + 可见**（而不是"悄悄按增量跑"）。

### 6. 结论

1. **影响面比清单小**：至少一条（Textbook KG）是**误列**，另有两个项目根本不产哈希 ID。
2. **但"能不能安全判"仍是否**：三项未核 ⇒ 处置 = **全量 + WARN**（保守且可见）。
3. ⇒ 下一步**不该**是"开始迁移"，而是**把 `affected` 变得可产出**：
   逐点分类 Auto_Prover 的 114 个命中 · 定位 `Macro_Data` · 让两处存储可达（或在站上跑）。
   ★ 这三件**每件都能独立做**；做完 `affected` 就从 `None` 变成**已知集合** ⇒ **那时才谈增量**。

5. **与「非执行三分」的映射未在真实调度器上跑过**：`WARN` / `SKIP_FAILED` 的**呈现**已由

   ⚠ **2026-09-26 收紧这一条**：判据**本身**已有一次**真实调用**（上一节 §4 的六种场景，输入 = U-1 迁移的真实变更集）

6. **H-1 的"等价"如何证明，未定**：`incremental_equivalent` 的**证明程序**不存在 ⇒

7. **首靶未触碰**：`Macro_Data` 的 `revision_propagation` **本轮未读、未改**（原文的"已读真源码"是**前序轮次**的实测）

8. **`affected` 的可产出性在**本仓之外**（2026-09-26 增，来自上一个用例）**：那次 `affected` 只能给 `None`，
   三条理由**都是取证缺口、不是设计选择** —— Auto_Prover 的 114 个 ID 命中**未分类** ·
   `Macro_Data` **目录未定位** · Open_Data / Auto_Prover 的**存储不在本机**。
   ⇒ 补齐这三项之前，**任何**真实变更都只能落到 H-3（全量 + WARN）—— 保守是对的，但**它同时意味着增量这条路没被走过**。
