## When to Run

- 需要生成研究创意或提出新方法
- 基线复现完成后，需要确定研究方向
- 用户要求头脑风暴或探索新思路
- 现有方案遇到瓶颈，需要寻找替代思路

## Instructions

### 1. 收集输入信息

从 memory 和 artifact 中检索已有研究成果：

- 读取 `literature_review_*`：了解领域现状和研究空白
- 读取 `paper_list_*`：获取已有方法的技术细节
- 读取 `baseline_result` 类型的 artifact：了解基线性能和局限性
- 读取上一阶段的 `decision_record`：了解基线选择理由

### 2. 生成研究创意

基于收集的信息，按以下维度系统生成创意：

**维度 A：填补研究空白**
- 针对文献综述中识别的研究空白
- 提出直接解决空白的方法

**维度 B：改进已有方法**
- 分析基线方法的局限性
- 提出针对性的改进策略

**维度 C：跨领域迁移**
- 识别其他领域的成功方法
- 设计迁移到当前领域的方案

**维度 D：组合创新**
- 组合多个已有方法的优势
- 设计新的组合架构或流程

对每个创意，按以下模板记录：

```markdown
## 创意：<创意标题>

### 核心思路
<1-2段描述核心想法>

### 技术方案
<具体的技术实现路径>

### 预期优势
- 优势1: <描述>
- 优势2: <描述>

### 潜在风险
- 风险1: <描述>
- 风险2: <描述>

### 可行性评估
- 计算资源需求: 低/中/高
- 数据可获得性: 是/否/需准备
- 实现复杂度: 低/中/高
- 预计实验周期: <天数>

### 新颖性评估
- 与最相关工作的区别: <描述>
- 潜在贡献程度: 增量/中等/突破
```

### 3. 评估和排序创意

对所有生成的创意进行评估：

**评估标准：**
| 标准 | 权重 | 说明 |
|------|------|------|
| 新颖性 | 30% | 与已有工作的差异化程度 |
| 可行性 | 30% | 在当前资源下实现的可能性 |
| 影响力 | 20% | 对领域的潜在贡献 |
| 可验证性 | 20% | 能否通过实验清晰验证 |

**排序规则：**
1. 按加权得分从高到低排序
2. 标注推荐等级：强烈推荐 / 推荐 / 备选
3. 对强烈推荐的创意，补充更详细的技术方案

### 4. 提交创意记录

使用 artifact_record 提交每个创意：

```
artifact_record(
  artifact_type="research_idea",
  title="<创意标题>",
  content="<完整创意描述，包含上述模板所有字段>",
  tags=["idea", "<方法类别>", "<技术关键词>"]
)
```

提交创意评估汇总：

```
artifact_record(
  artifact_type="idea_evaluation",
  title="研究创意评估汇总",
  content="""
# 研究创意评估汇总

## 创意列表
| 排名 | 创意 | 新颖性 | 可行性 | 影响力 | 可验证性 | 总分 | 推荐等级 |
|------|------|--------|--------|--------|---------|------|---------|
| 1 | <创意1> | <s> | <s> | <s> | <s> | <s> | 强烈推荐 |
| 2 | <创意2> | <s> | <s> | <s> | <s> | <s> | 推荐 |

## 推荐方案
<详细描述推荐的首选方案及其理由>
""",
  tags=["idea_evaluation", "summary"]
)
```

### 5. 记录创意决策

```
decision_record(
  stage="idea",
  decision="<选择了哪个创意作为主方案，哪些作为备选>",
  rationale="<选择理由：评分、风险评估、资源匹配>",
  outcome="<生成X个创意，推荐Y个>",
  next_action="experiment"
)
```

### 输出格式要求

- 每个创意独立记录为 artifact
- 评估汇总使用 Markdown 表格
- 评分使用 1-5 分制
- 推荐方案必须包含具体可执行的技术路径
- 风险评估必须诚实，不可回避潜在问题
